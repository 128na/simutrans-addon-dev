# AMI の道路の作り

道路（生活道路・一般道路・幹線道路・高速道路）と、その壁・高架・橋脚・橋・トンネル・分岐の絵・ex 画像の作り。全体の案内は [AMI の README](../../README.md)。文中の `ingame/…`・`blender/…`・`docs/…` などのパスは `addons/ami/` から数える。

## 道路の作り（通常の版、#21）

3 種とも blender-poc の高速道路（`../blender-poc/blender/render.py` の `ROAD_PROFILES["expressway"]`）と同じ作りで、`tools/blender/sheetlib` の `road_sheet` で描く（設定は `blender/render.py` の `ROAD_SETTINGS`）。種類ごとに変えたのは中央線・路面の色・アイコンだけ。

| 種類 | 中央線 | 路面の色 | アイコン |
|---|---|---|---|
| 生活道路 | なし | blender-poc の街路の灰色（`road_parts` の `STREET_ASPHALT`）を 2.4 倍明るくした灰色 | 道路の背景・40 |
| 一般道路 | 白の実線 | 同上 | 道路の背景・120 |
| 幹線道路（#257） | 白の破線（直線 4・斜め 3。線とすき間は同じ長さ） | 街路と高速道路の 2 色の幾何平均（`render.py` の `TRUNK_ASPHALT`）を 2.0 倍明るくした色（街路 2.4・高速道路 1.6 の間） | 道路の背景・240 |
| 高速道路 | 白の広い破線（直線 2・斜め 1。線 8m・すき間 12m の割合 0.4） | blender-poc の高速道路の暗く青みのある色（`EXPWY_ASPHALT`）を 1.6 倍明るくした色 | 高速道路の背景・360 |

- 白線: 路側の白線は 3 種とも実線。T字は枝の側の路側線を点線（分岐の口）にし、十字と 1 タイルだけの道は東西の中央線と東西の点線（blender-poc の高速道路と同じ）。行き止まりは直線と同じ絵
- 幹線道路の作り（#257。2026-11-24。4 車線の利用を想定し、4 車線は way を増やさず道路を 2 本並べる今の作りのまま）: 高速道路（`ami_road_expressway`）を元に、同じ断面（片側 1 車線・タイル全面が路面・歩道なし）・同じ一式（通常・基盤 4 版・高架 4 版・橋・トンネル・線路との踏切 4 個）で、カーブも高速道路と同じ斜めの直線（`switch_diag`）、T字の枝も同じ。違いは中央線（白の破線。`sheetlib` の `center="dash"` で、直線 4・斜め 3。線とすき間は同じ長さで、タイルの辺がすき間の中ほどに来る。ユーザーの判断 2026-11-24: 幹線道路は車線変更できる破線で、高速道路より間隔を狭く。高速道路は `center="dash_wide"` で広げた）と路面の色（街路と高速道路の間）だけで、一般道路（実線）・高速道路と見分ける。壁（`ami_wall_road_*`）・分離帯・橋脚・歩道は共通のままで、幹線道路専用の物は作らない（物を分ける理由が無い）。最高速度 240 km/h は確定（2026-11-24、ユーザーの判断。一般道路 120 と高速道路 360 の間。費用・維持費・登場年も今の値で確定）。範囲外: 路面表示（`ami_mark_*`）を重ねること、水路の踏切の幹線道路の版（`CANAL_ROADS` に入れていない）、Y 字・三方分岐（#210）
- 中央線の破線（幹線道路。#257 の前は高速道路もこの割り方）: タイルの中の長さを、直線は 4 本、斜めは 3 本に割り、タイルの辺がいつもすき間の中ほどに来るように置く（`road_parts` の `CENTER_DASHES`・`sheetlib` の `tile_dashes`）。直線（長さ 10）と斜め（10/√2）のどちらも割り切れるので、直線と斜め・坂と平地の継ぎ目で間隔がそろう。前の点線の作り（経路の始点から周期 1.6）は 10 を割り切れず、斜めは経路をタイルの外まで延ばすので、継ぎ目で間隔が崩れる。線の幅は実線の中央線と同じ（約 1px）。画面で横向きの斜めは、実線と同じく半画素ずらす
- 高速道路の広い破線（#257。2026-11-24、ユーザーの判断「幹線道路が今の高速道路程度にして高速を広げる」）: タイルの中の本数を直線 2・斜め 1、線の割合を 0.4 にした（`road_parts` の `CENTER_DASHES_WIDE`・`CENTER_DASH_FRAC_WIDE`、中央線の種類 `dash_wide`）。ユーザーの参考図は一般道が線 5m・すき間 5m（周期 10m）、高速道路が線 8m・すき間 12m（周期 20m）で、周期が 2 倍・線の割合が 0.4。本数は 2 倍に細かくできないので、幹線道路を今までの高速道路の割り方（周期 2.5）とし、高速道路は周期を 2 倍の 5 にした。斜めは周期をそろえにくく（タイルの中の長さ 7.07 を整数に割る）、1 本にした（周期 7.07）。分岐・合流の路面表示の破線（`marking.py` の `MARKING_EXPWY_DASHES`・`MARKING_EXPWY_DASH_FRAC`）も同じ割り方にして、下の高速道路の破線とそろえた。手本の測定（2026-11-24。直線のタイル 1 枚の中心線の白の画素の連なりを数えた。`../refs/iss/release/pak128/way/road/*.png` の列 2・行 0 のセル、`../refs/pak128/infrastructure/roads/*.png` の `Image[NS][0]` のセル）:

  | 手本 | 中央線 | タイルの中の周期数（直線） | 線:すき間 |
  |---|---|---|---|
  | ISS 高速（`iss_wrg_1200_*`） | 破線 | 2（周期 32px、タイルの長さ 64px） | 16:16px（1:1） |
  | ISS 都市高速（`iss_wrg_0120_*`）・`iss_wrg_0050` | 実線 | - | - |
  | pak128 標準 `Highway_110`・`130`・`200`・`Road_090` | 破線 | 4（周期 16px） | 8:8px（1:1） |
  | pak128 標準 `Road_050` | 実線 | - | - |
  | AMI の高速道路（今まで） | 破線 | 4（斜め 3） | 1:1 |
  | AMI の幹線道路（今） | 破線 | 4（斜め 3） | 1:1 |
  | AMI の高速道路（今） | 広い破線 | 2（斜め 1） | 2:3（0.4） |

  斜めは測っていない（手本の斜めは別のセル）。
- カーブ（#259。#209 の 2 本目。2026-11-24 に速さで描き分けた）: 一般道路は **円弧**（路面軌道と同じ。タイルの角を中心に半径がタイルの半分、2 辺の中点をつなぐ）、
  生活道路は **L 字**（2 辺の中点から中心まで直線で来て、中心で直角に折れる）、高速道路は斜めの絵（dat の `image[sw]` などが `diagonal` と同じセル。幹線道路 #257 も同じ）。
  円弧・L 字は way のシートの行 2 の列 5〜8 に描き、dat の `image[sw]` などがそのセルを指す（`catalog.py` の `ROAD_CURVE_SHAPES`。斜めのセル・近い斜めは道路の全種が持つ）。
  描くのは `sheetlib` の `road_sheet` のプロファイルのキー `curve`（`"arc"`・`"ell"`）で、通常の版だけが持つ（壁・基盤・高架・橋・トンネルは写して `curve=None` に戻す）。
  L 字の角は、`sweep` が角で断面を細めない `MiterPath` の経路で組む（白線・走行跡・路肩の雪の型が角で細らない）。
  橋とトンネルにはカーブのセルが無い（橋は `BRIDGE_CELLS` が直線と坂だけ、トンネルは坑口の 4 向き）ので、この変更の対象外（本体が橋・トンネルの中を曲げない）。
  壁の way-object・基盤・高架の single のカーブも、3 本目の #260 で円弧・L 字にそろえた（下の「道路の壁・高架・橋脚・橋・トンネルの作り」の「カーブの形ごとの壁」）。
  確かめた見本: `ingame/curve_sample.nut`（`sample_parallel.sh` に `NUT=ingame/curve_sample.nut`。1 本の輪・2 本並べた輪・坂の隣・T字の隣。温暖と降雪）、`road_sample.nut` の B・AFC・K、`tram_sample.nut` の LO_B・GE_B（路面軌道を重ねる）、`marking_sample.nut` の X4（路面表示を重ねる）。
  以前（#259 の前）は 3 種をそろえていた。理由は、道路の壁（`ami_wall_road_<版>`、#22）を 3 種で共通の way-object にするため（way-object のカーブの絵は 1 つなので、種類ごとにカーブの形が違うと壁が合わない）。この食い違いは #260 で、カーブの形ごとの壁を足して直した。手本では、iss の道路は速さで分かれる（`../refs/iss/src/way/road/ground.dat` の `iss_wrg_0030`・`0050`・`0120_*` は `image[ne]` が曲線のセル、`iss_wrg_1200_*` は `diagonal` と同じセル）。pak128 標準の `Road_030`（`../refs/pak128/infrastructure/roads/road_030.dat`）も曲線のセル。今の AMI もこれらと同じく、速さでカーブの形を描き分ける。
- 路面の色: 生活道路・一般道路は pak128 標準の道路（灰色）とつなぐことが多いので街路の灰色、高速道路は一般の道路と見分けられるよう暗い青み。走行跡と路肩のまだらの雪は、路面と同じ 2 色から作る（`sheetlib` の `asphalt_skin`。路面だけ替えると、暗い路面に明るい帯が乗る）
- 雪: 車道は除雪されて夏と同じ（路面・白線・走行跡）。路側の白線の外から路肩に雪が積もり、白線の内側をまだらの雪でぼかす（blender-poc の道路と同じ `snow` の部品）
- 精細化（#56。ラウンド 1〜4 で試し、ラウンド 3 を本番に入れた。2026-11-20、ユーザーの決定。ラウンド 4 の明るい路面はリアルだが色があせて見えた）: 設定は `blender/render.py` の「道路一式の質感」で、道路 3 種とその版・道路の壁・道路用の橋脚・歩道にだけ渡す（`sheetlib` の既定は blender-poc・在来線・スラブ軌道と共通なので変えない）。決め方は `docs/records/2026-11-20_ami-road-refine-round1.md`〜`round3.md`、入れ方は `2026-11-20_ami-road-refine-production.md`
  - 路面: 照り返しを切り（生活道路・一般道路。前は空の色の映り込みが明るさの大半で、色とまだらが効かなかった）、2 色を明るくして平均から 1.4 倍離し、色の段を 0.47〜0.53 に狭めて 1 画素の骨材の粒を出す（iss の路面と同じ描き方）。走行跡の寄せ具合は半分（高速道路は 4 分の 1）で、明るい縞でなくかすかな帯にする（`asphalt_skin` の `ramp`・`wear_t`）
  - コンクリート（壁・基盤・高架の躯体・橋脚・坑口の躯体）: 元の色を中心に ±12% のまだら（Scale 25）で、打ち放しの肌を出す。形を作る関数の中で材質を作るので、材質の名前で差し替える（`road_sheet`・`tunnel_sheet`・`pier_sheet` の `mat_skin`）
  - 雪の歩道・縁石と路肩の雪: 地面の雪に合わせ、青みの色（0.88・0.86・0.97）を中心に ±10% のまだらと発光 0.15（`road_sheet` の `snow_skin`、`sidewalk_sheet` の `snow`）。一色の雪では、地面の雪の上に灰色の板が置いてあるように見えた
  - 歩道の敷石: 灰色の敷石と暗い目地（`sidewalk_sheet` の `paving`。Brick テクスチャ、約 6 x 3px）。前は緑がかったまだらで、草地か砂利に見えた
- 汚れ: 走行跡（車輪の通る所が磨かれた明るい帯）と油の帯。交差点は右左折の経路にも付ける（blender-poc と同じ）
- 近い斜め: `diagonal[close1]`・`[close2]` を持つ（斜めの 2 片を中心線で切って 1 枚に描く。blender-poc と同じ）

### 分岐の絵（switch 画像 1・2）

**2026-11-23 に dat へ戻した（[#46](https://github.com/128na/simutrans-addon-dev/issues/46)。OTRP v64 で KUTA 流の道路の決まりが無くなり、十字は標準の十字の絵になった: [teamhimeh/simutrans#816](https://github.com/teamhimeh/simutrans/pull/816)）。v64 でゲーム内の確認を済ませた（左側通行の `flat_512_left_v64.sve`。右側通行は未確認）。** 以下の「外していた間」の説明は、2026-11-20〜23 の経緯。

**（2026-11-20〜23 に外していた間の経緯）道路の dat に分岐の絵を入れていなかった（ユーザーの決定）。** 本体（OTRP）は、道路の「1」を枝の先が分岐の T字に、「2」を十字のタイルにだけ出す（KUTA 版から引き継いだ、多車線の交差点のための使い方）。固定の道具の名前は線路の分岐の意味で付いていて、これと合わない。T字の 1・2 を固定の名前に合わせて描くと、自動の 4×2・6×6 の十字がふさがり、ex 画像を足しても 4×4 しか直らない（[reference](../../../../docs/reference/way-addon.md) の 9.3）。本体の分岐の絵の仕様を整理するまで、道路の way（waytype が `road` のもの全部。通常の版・基盤の版・高架の版）の dat から 1・2 の 10 枚を外す（戻すのは [#46](https://github.com/128na/simutrans-addon-dev/issues/46)）。

- 切り替え: `blender/ami_dat.py` の `ROAD_SWITCH_IMAGES`（既定は真 = 入れる）。偽にすると dat から外す。シートの分岐のセル（下の絵の作り）と、轍・優先道路の十字・停止線の部品、見本の区画 I・P は消さずに残している
- 外していた間に使えなかったもの: 優先道路の十字（`nsew1`・`nsew2`）と、固定した T字の轍。固定の道具で 1・2 を選んでも通常の絵のまま。2 本並べた道路の渡り口（区画 HV・HH）も通常の T字（枝の口の点線）が向かい合う
- 外していた間に見えたもの: 十字はどれも通常の十字（開いた十字）、T字は通常の T字。多車線の交差点（4×2・4×4・6×6）も、4 車線に 2 車線が T字でつながる所も、横切る道路はふさがらない（`docs/road_GE_junction_noswitch.png`・`road_junction_noswitch_all.png`・`road_junction_tee_noswitch.png`・`road_GE_noswitch_ground.png`。2026-11-20、`OTRPv64_3.exe`、`flat_512.sve`）。4×4・6×6 の中ほどの角の丸い四角の枠（下の「十字と T字の絵（通常の絵）」）は残る
- 線路と橋脚の way（`ami_pier_road` は `tram_track`。分岐の絵は T字・十字と同じ柱）の分岐の絵は変えていない

**T字の 1・2 の轍の向きは 2026-11-23 に改めた**（線路と同じ向き: 枝と名前の側の本線の端をつなぐ。2026-11-19 は逆だった。#46、記録 [2026-11-23_ami-road-switch-ruts-direction](../../../../docs/records/2026-11-23_ami-road-switch-ruts-direction.md)）。

分岐の絵を入れていたときの作り（T字の 1・2 の白線と轍、優先道路の十字、開いた十字と角の円弧、停止線）と、ゲームで確かめた結果は記録 [2026-11-20_ami-road-switch-design](../../../../docs/records/2026-11-20_ami-road-switch-design.md) にある。本体の 1・2 の使われ方は [reference](../../../../docs/reference/way-addon.md) の 9.3。戻すときは [#46](https://github.com/128na/simutrans-addon-dev/issues/46) で、本体の分岐の絵の仕様の整理（[128na/simutrans#15](https://github.com/128na/simutrans/issues/15)）に合わせる。

### 十字と T字の絵（通常の絵）

- 通常の十字（`image[nsew]`）は開いた十字: 交差点の中に走行車線を横切る白線を引かない。腕の路側線は角の円弧でつなぎ、中央線は腕の口（円弧の端）まで。3 種とも同じで、1 タイルの道路（`single`）も同じ絵（`docs/road_GE_cross_open_zoom.png`・`road_EX_cross_open_zoom.png`・`road_LO_L_open_zoom.png`）
- 通常の T字: 本線の中央線と、枝の無い側の路側線（実線）を通す。枝の側は、本線の路側線を角の円弧で枝の路側線へつなぎ、枝の口を点線で渡す（`docs/road_GE_tee_arc_zoom.png`）
- 角の円弧: 隣り合う腕の路側線を、角で 4 分の 1 の円弧でつなぐ。半径は `EDGE_CORNER_R` = 0.8（`tools/blender/sheetlib/road_parts.py`）。中心は路側線の交点から角の外へ (0.8, 0.8) で、円弧の中ほどが車道の半幅 3.6 の交点にちょうど来る（それより大きいと路面の角の外へ出る）。枝の口の点線は口の幅（両側の路側線のあいだ、-3.37〜3.37）だけに引き、そこから円弧の端（4.17）までは路面のまま
- 道路を 2 本ずつ並べた交差点（4×4・6×6）では、並べた道路のあいだ（路肩どうし）の角の円弧が交差点の中ほどで閉じ、角の丸い四角の枠が出る（6×6 では 4 つ。`docs/road_GE_junction_noswitch.png`）
- 切り替え: `blender/render.py` から `sheetlib` の `road_sheet` に `open_cross`（開いた十字）・`corner_arcs`（角の円弧）を渡す。分岐の絵の作りの `switch_ruts`・`priority_cross`・`drive_left`（`DRIVE_LEFT`。偽にすると優先道路の十字の停止線が右側通行の位置へ移る）も渡したまま

## 道路の壁・高架・橋脚・橋・トンネルの作り（#22）

道路 3 種に、共有の壁の way-object（`ami_wall_road_<single|back|center|front>`）、地上の基盤の版（`<道路>_base_<版>`。確定。2026-11-19、ユーザーの決定）、高架の 4 版（`<道路>_elev_<版>`）、橋（`<道路>_bridge`）、トンネル（`<道路>_tunnel`）、道路用の橋脚（`ami_pier_road`）を足した。作りは線路の壁・高架・橋（[「壁の敷き方」](rail.md)[「高架と橋脚の作り」](rail.md)[「橋とトンネルの作り」](rail.md)）と同じで、断面と壁の形は blender-poc の高速道路の壁の版（`tools/blender/sheetlib` の `road_sheet` の `walls`）。設定は `blender/render.py` の「道路の壁の way-object・高架の 4 版・橋・トンネル・道路用の橋脚」、値は `blender/ami_dat.py`。

- カーブの形ごとの壁（#260。ユーザーの判断 2026-11-24 「お勧めでOK」）: 一般道路（円弧）・生活道路（L 字）の基盤・高架の `single` と組む壁の way-object を 2 つ足した。`ami_wall_road_single_arc`（一般道路用。円弧）・`ami_wall_road_single_ell`（生活道路用。L 字）。
  直線・T字・十字・坂・端の壁は `ami_wall_road_single` と同じ絵で、カーブのセル（行 2 の列 5〜8）だけが円弧・L 字の経路に沿う（`catalog.py` の `ROAD_WALL_CURVED`、`render.py` のプロファイル `wall_road_single_arc`・`_ell`）。
  幹線道路・高速道路は今までどおり斜めの `ami_wall_road_single`。橋・トンネルは直線と坑口だけでカーブが無いので、どの single の壁でもよい。
  別の案（壁を way の絵に焼き込む）は、橋・トンネルの壁と扱いが食い違い、壁を way-object に分けた方針（ADR 0003）から外れるので採らなかった。

## 道路の ex 画像（#210）

道路 4 種（`ami_road_local`・`_general`・`_trunk`・`_expressway`）の通常・基盤・高架の way（24 個）に、線路と同じ ex 画像（26〜29 番の Y字分岐、31〜34 番の三方分岐。30・35 番は通常の十字）を入れた。壁の way-object・橋・トンネル・橋脚は入れない（壁は通常の T字・十字と同じで、橋・トンネルは分岐の絵を持たない）。本体（v64）が道路でも線路と同じ決めで ex 画像を選ぶことは、reference の 9.4。

- 作り: シートのセル（行 0・1、列 10〜13。雪は行 4・5）を `tools/blender/sheetlib` の `road_sheet` の `ex_switches`（プロファイルに `"ex_switches": True`）で描く。白線と轍だけを替え、経路（路面・壁・基盤）は元の T字・十字のまま。腕の形は `tools/blender/sheetlib/road_ex.py`
  - 一般道路: 腕は 4 分の 1 の円弧。路側線は腕の内側（道の外の縁。根元の路側線へつながる。そのまま引く）と、腕と腕の間の外側の線
  - 腕と腕の間の線は、腕が分かれ切った所（隣の腕の帯の縁）まで引き、隣の線と V 字につなぐ（`road_ex.py` の `GORE_JOIN`。頂点は分かれ切った所で、根元の側へは伸ばさない。2 つ目のユーザーの指摘）。中央線は、根元から各腕へ進む車の通り道を塞がないよう、分かれ切った所からさらに少し離れた所から先だけに引く（`GORE_GAP`。1 つ目のユーザーの指摘で、最初の版の、分岐のタイルの中まで届く実線・点線をやめた）。三方分岐は腕の間の角が 2 つあり、どちらも V 字につなぐ
  - 幹線道路・高速道路: 腕は斜めの直線（路側線・中央線の画素のそろえ方は斜めのセルと同じ）
  - 生活道路: L 字の腕を 2 本重ねると T字・十字の形そのものになるので、白線は T字・十字の白線（口の点線なし）で、轍だけを Y字・三方分岐の向きにした
