# blender-poc

iss（Illustrator で作ったインフラアドオン）の作り方を Blender に置き換えられるかを確かめる検証用アドオンです。配布用ではありません。

- 対象: Simutrans 125.0 以降 / pak128（画像は iss と同じ 256px セルで作り、タイルの外へはみ出せる）
- ライセンス: 未定（検証用）。sis（CC BY-NC-SA）からはカメラの数値だけを参考にし、形状・素材・画像は使っていない

## 中身

| ファイル | 内容 |
|---|---|
| `blender/render.py` | Blender をコマンドで動かし、形状をスクリプトで組み立てて描画し、シート画像を作る |
| `blender/check.py` | 描画位置の検証。タイル菱形の位置と、iss の既存画像との描画範囲を比べる |
| `blender/preview.py` | 確認用の拡大画像 `work/preview.png` を作る |
| `blender/compose.py` | つなぎ目の確認。シートのセルをゲームと同じ位置・順番で並べた画像を作る |
| `blender/ingame_diff.py` | ゲームの画面と、シートのセルを同じ順に貼った予想図を画素単位で比べる |
| `blender/ref_measure.py` | 手本の画像（pak128 のソース・iss の元絵・このアドオンのシート）で、直線・斜めが理想の位置から何 px ずれているかと、直線のレールの行を測る |
| `blender/zoom.py` | 画像の指定した座標の周りを拡大して並べる（ツールが出した候補を目で確かめる） |
| `ingame/sis_check.sh` | SIS・pak128 標準の道路とのつなぎ目を MCP で撮る（`ingame/road_seam.nut` を敷いた後） |
| `ingame/slope_ref.nut` | 手本どうしの継ぎ目: `seam.nut` の坂と同じ並びを x=156 に Rail_100 だけで敷く。こちらの継ぎ目と同じ判定にかけて比べる |
| `ingame/seam_check.sh` | 他のアドオン・pak128 標準とのつなぎ目を撮り、`blender/seam_judge.py` で継ぎ目ごとに合否を出す（`seam.nut`・`road_seam.nut` を敷いた後） |
| `blender/seam_judge.py` | 他のアドオンとの継ぎ目の判定。継ぎ目の草・帯の中心のずれ・模様（レール・白線）のずれを測る |
| `ingame/steep.nut` | 坂の十字の見本: 線路（新・旧）と Rail_100 の急坂（2段の坂）、Rail_100 の1段の坂を y=60 に敷く |
| `ingame/steep_check.sh` | 坂・急坂の十字を撮り、`blender/slope_measure.py` で坂のタイルごとに合否を出す。このアドオンの線路は `ingame_diff.py` の差分も出す（`steep.nut` を敷いた後） |
| `blender/slope_measure.py` | 坂の線路の判定。直線のタイル（平地・坂・急坂）ごとに道床の縁・レールの位置・まくらぎの濃淡を測り、レールが道床の中ほどにあるかを平地と比べる |
| `ingame/capture_check.sh` | 4種類 × 6か所を MCP で撮り、`ingame_diff.py` で比べる（ゲームを MCP ポート付きで起動しておく） |
| `blender/special.py` | 特殊色の検査。シートに特殊色が何 px、どのセルにあるかを数える |
| `blender/special_preview.py` | 特殊色の見え方の再現（昼・会社の色を変えたとき・夜）|
| `src/track.dat` | 線路・新描画位置（レールが低い。今の pak128・iss）。セル配置は iss の線路と同じ |
| `src/track_old.dat` | 線路・旧描画位置（レールが高い。古い pak128・SIS）。形は `track.dat` と同じで、名前は `bpoc_track_old` |
| `src/road.dat` | 道路（歩道付き、50km/h）。幅・白線・縁石の位置は SIS の一般道 `SIS_L_RG1-1_01S` に合わせる。セル配置は線路と同じ |
| `src/expressway.dat` | 高速道路（歩道なし、120km/h）。SIS の高速道路 `SIS_E_RG1-1_01S` に合わせる。カーブは SIS と同じく斜めの絵を使う |
| `src/tollbooth.dat` | 料金所風の建物（駅の付属建物扱い）。屋根がタイルからはみ出す |

## 必要なもの

- Blender 4.5 LTS（`D:\bin\blender\blender.exe` で確認）
- makeobj（PATH 上。60.12 で確認）

## ビルド

アドオンのディレクトリで:

```powershell
D:\bin\blender\blender.exe -b --factory-startup --python blender/render.py
cd src; makeobj pak256 ..\dist\bpoc.pak track.dat track_old.dat road.dat expressway.dat tollbooth.dat; cd ..
```

iss と同じく `pak256` で 256px セルとして切り出す（ゲームは pak128）。

位置の検証:

```powershell
D:\bin\blender\blender.exe -b --factory-startup --python blender/check.py -- ..\..\..\iss\src\way\rail\standard_slab.png
```

## 描画の決まりごと

- カメラ: 正投影、回転 X60° / Z45°（sis と同じ向き）。`ortho_scale = 20√2`、256px でタイル1辺10 → 菱形 128×64px
- 高さ1段 16px = Blender で約 2.041
- Blender の向き: +Y が北（画面右上）、+X が東（画面右下）
- タイル中心をセルの (128,128) に映す → dat オフセット `-64,-32`（線路）
  建物はカメラをずらして (128,192) に映す → `-64,-96`
- 線路はタイルの範囲で切り抜いて（Boolean）、隣のタイルとの継ぎ目をそろえる
- 線路の形はほぼ平ら（道床の厚み 0.12 ≈ 1px、レール上面 0.30 ≈ 2px）で、新・旧の描画位置で共通
- レールの間隔は iss・SIS と同じく画面上 6px（直線）。レール中心の間隔 0.934（1単位 ≈ 6.4px）
- 新描画位置と旧描画位置は、画面上の上下位置だけが違う。カメラを整数 px ずらして描き分ける（`render.py` の `TRACK_PROFILES`）。
  タイル中心を基準にして、新は 3px 下げ（iss に合わせる）、旧は 1px 上げ（SIS に合わせる）。
  iss と SIS のレールの位置を比べると、直線・斜め・坂のどの方位でも、画面上で 4〜4.5px 上下にずれているだけだった
- 斜めのタイルはレール・まくらぎの横幅を 2/√10（≈0.63）倍、道床を 0.8 倍にする。
  3D のまま描くと斜めは横幅が縮まずに映り、直線の約1.6倍太く見えるため（pak128 標準も斜めはレール間隔を細く描く）
- 後処理は iss と同じ: 特殊色にたまたま一致した画素は +1 ずらす。アルファ25未満は `#E7FFFF`、それ以外は不透明にする。
  そのあとで、材質に指定した特殊色を入れる（下の「特殊色」）

### 描画位置の描き分け（2026-11-12）

- 描き分ける前の線路は、レールが SIS より 1px 低く、iss より約 3px 高かった。ほぼ旧描画位置にあった
- 描き分けの後、レールの間隔が基準より約 1.1px 広かった（直線 7.1px と 6.0px）ので、6px に詰めた。
  列ごとにレール2本の位置を比べると、旧と SIS・新と iss の差は直線・坂・斜めのどれも 0.4px 以内
- 描き分けた後、iss と照合（`check.py`）: 直線・端・坂・斜め・分岐は重心のずれ 0.7〜3.5px（端は 8.6〜9.8px）。
  カーブ `curve_sw`/`curve_ne` だけ 12.1px で基準の 12px をわずかに超えた。
  iss のカーブはタイルの外まで描く別の作りで、もともと差が大きいところ（上の「カーブは描き方が違う」）
- ゲーム内のつなぎ目（`ingame/seam.nut`。比べる線路 → 検証用の線路 → 比べる線路 の順に1本につなぐ）:
  - 旧描画位置と SIS（`way.SIS_ShinkansenTrack_Ballast_E01_ds.pak`）: 東西・南北の直線、斜め（SIS のカーブとの境目）、
    坂の下の境目で、2本のレールが段差なくつながった（`docs/seam_old.png`・`docs/seam_old_straight.png`・`docs/seam_old_detail.png`）。
    違いはレールの色合い（SIS は赤茶色）と、SIS が新幹線用でタイル全体が道床なこと
  - 新描画位置と pak128 標準 Rail_100: 目立つ段差は無い。ただし Rail_100 は道床の幅も模様も違い、
    レールも暗くて見分けにくいので、1〜2px の差までは判定できていない（`docs/seam_new.png`・`docs/seam_new_detail.png`）
  - 検証用のカーブが pak128 標準の斜めとつながる所では、カーブの丸みが大きく張り出して見える（`docs/seam_new.png` の中央）

### 道路（2026-11-12）

車道の幅はアドオンによってまちまちなので、SIS の一般道（`Local_Street/1-1lane` の `SIS_L_RG1-1_01S`、歩道付き 50km/h）を基準にした。

- SIS の直線セルの中心の列を測った断面（タイル半幅を 5 とした横位置）: 中央線 0、車道 ±3.2、路側の白線 ±3.3〜3.45、
  縁石 ±3.6〜3.85（奥側は立ち上がりが 2〜3px 見える）、歩道はタイルの端まで。路面は地面と同じ高さ（中央線がタイル中心を通る）
- 作り方: タイル全面の歩道（縁石の色の板 + 石畳の薄い板）から、車道の中心線に沿った型を Boolean で抜く。
  抜いた切り口が縁石の立ち上がりになる。分岐・十字は型を重ねるだけで口が開き、角は扇形に丸める（SIS と同じ）
- 斜め: SIS もタイルの半分の三角形だけを描き（残りは隣のタイル）、横幅を 2/√10 倍に縮めている。
  SIS は車道の半幅が縮めた後で約 2.7 と、白線の外に余白がある。最初はこれに合わせたが、直線とのつなぎ目で縁石が段になり
  白線が切れたので、直線とタイルの辺で同じ点を通る位置（直線の 1/√2）に変えた（下の「直線↔斜めの段と白線の切れ目」）
- SIS とセルごとに並べた比較: `docs/road_cells.png`（上段 SIS、下段 移植版）。斜めの白線と縁石の位置は 1px 以内
- 色は SIS の直線で平均を合わせた（車道 49/45、歩道 89/84。左が移植版）。石畳とアスファルトのまだら模様はノイズで付けた
- ゲーム内のつなぎ目（`ingame/road_seam.nut`。SIS → 検証用 → SIS の順に1本につなぐ）: 東西・南北の直線、斜め、坂、
  SIS の直線から分かれる分岐で、歩道の縁・縁石・白線が段差なくつながった（`docs/road_seam.png`・`docs/road_seam_detail.png`）
- SIS と違うところ: 行き止まりの白線（SIS はコの字に回す。移植版は両脇だけ）、十字の中央の × 印、単独タイルの角の形、
  斜めのタイルの内側の歩道の端に小さな段が出る

### 高速道路（2026-11-12）

SIS の道路8種（一般道 50/70/80km/h、高速 80/100/120/999km/h）の直線を測ると、路側の白線（±22px）と中央線の位置はどれも同じだった。
違うのは白線の外側（歩道＋縁石／灰色の路肩／タイルの端までアスファルト）と線の種類で、高速道路は斜めの白線だけ約 1.08 倍外にある
（移植版は、直線とのつなぎ目で白線が切れないよう、斜めの白線を直線の 1/√2 の位置にした）。
そこで道路と同じ作りに「歩道を作らない」切り替えを足し、`SIS_E_RG1-1_01S`（片側1車線、120km/h）に合わせた。

- タイル全面がアスファルト。色は SIS に合わせて暗く青みがある（平均 18,19,24 と SIS 20,20,27）。照り返しを切らないと空の色が映って明るくなる
- 分岐は枝の側の路側線を点線（約2px の四角）にする。十字と単独のタイルは東西の中央線と両側の点線。行き止まりは直線と同じ絵
- カーブは SIS と同じく、同じ向きの斜めの絵を dat で割り当てる（`image[nw]` = `diagonal[nw]`）
- SIS とセルごとに並べた比較: `docs/expressway_cells.png`（上段 SIS、下段 移植版）
- ゲーム内のつなぎ目（`ingame/road_seam.nut` の y=160〜）: 直線・斜め・坂・分岐で白線が段差なくつながった（`docs/expressway_seam.png`）
- SIS と違うところ: 分岐・十字のタイルの左右の角にある小さな透明の三角、行き止まりの白線の模様（SIS は市松模様）

## つなぎ目のバリ（2026-11-12）

ゲーム内の等倍表示で、斜め同士と坂の周りのタイルの境にバリが出ていた。原因と直し方:

- 斜めの道路の縁石の切り欠き: 車道・縁石を抜く型の経路を、辺の中点から 2.5 しか延ばしていなかった。
  45° の向きでは型の端の角がタイルの内側に入り込み、端の近くで縁石が削り残されていた → `DIAG_EXT = 8.0` に延ばした
- 白線の途切れ・暗い点・明るい点: タイルの境の画素を、それぞれのタイルが「自分の側にある部分だけの色」で描いていた
  （形をタイルの範囲で切り抜き、アルファ25以上を不透明にしていたため）。細い線が境にかかると、片側だけの色が残る
- 坂の付け根の緑の線: 本体（OTRP 版）は坂のタイルの地面を物と一緒に後から描き、奥のタイルの線路の端の画素を上書きする
  （`boden/grund.cc` の `draw_as_obj`）。手前のタイルの絵がその画素を描いていないと地面が見える

2つ目と3つ目は描き方を変えて直した（`render.py` の `render_cell`）:

- 形はタイルより `CLIP_PAD = 0.6` だけ大きく切り抜いて描く。境の画素も、隣とつながった形で画素全体の色になる
- 画素ごとに、どのタイルの絵に残すか（持ち分）を決め、ほかは透明にする。決め方は次の節の「地面の菱形で持ち分を決める」
- 確認用の合成: `blender/compose.py` でシートのセルをゲームと同じ位置・順番に並べる（`docs/compose_*.png`）。
  ゲーム画面にセルを当てはめると、計算どおりの位置で一致した
- ゲーム内（等倍、`gui.set_zoom(3)`）: 斜めの縁石・白線は段差なくつながった（`docs/seam_fix_road.png`）。
  坂の付け根は緑の線が消え、合成との違いは道床の縁の1px が数か所だけ（`docs/seam_fix_slope_diff.png`。左 ゲーム、中 合成、右 違う画素を紫）
- 注意: MCP の `gui.set_zoom(1)` は 1.5 倍で、等倍は `set_zoom(3)`。これまでのつなぎ目の確認画像は 1.5 倍で撮っていた

### 直線とのつなぎ目（2026-11-12 続き）

上の直し方の後、斜めとカーブはきれいになったが、直線とのつなぎ目が目立つようになった:

- カーブ↔直線（道路）の灰色の点線: 経路をタイルの辺から 0.6 しか延ばしておらず、切り抜く幅 `CLIP_PAD` と同じだった。
  車道を抜く型の端が切り抜きの縁と重なり、カーブでは型の端がわずかに斜めなので、縁石が細いくさびの形で残っていた
  → 経路の延長を `PATH_EXT = 1.5` にし、カーブの端は円の接線の向きに延ばす
- 直線↔斜めの段差（線路・高速道路の角）: 全部のタイルを 0.5（約3px）重ねていたので、直線の道床や白線が、
  半分しか描かない斜めのタイルの側へはみ出していた。逆に斜めの車道が、先に描かれた直線の白線の端を覆い、角で白線が切れていた

最初はタイルの種類ごとに重ねる幅を変えて合わせたが、坂の十字や高速道路の輪で、まだ穴や緑の点が残った。

### 地面の菱形で持ち分を決める（2026-11-12 続き）

本体（OTRP 版）は、タイルごとに「地面 → そのタイルの物」を奥から順に描く。
奥のタイルの絵が手前のタイルの地面の菱形に入った画素は、手前の地面で必ず上書きされる。
なので画素の持ち分は、ワールド座標ではなく **画面上の地面の菱形** で決めるのが正しい:

- `render.py` の `_ground_mask` で、セルの中の地面の菱形を計算で塗る（中心 y=`GROUND_CY = 127`、画素の中心が菱形の中なら持ち分）。
  坂は四隅の高さを反映した四角形にする。菱形の中の画素だけ残し、外は透明にする（隣のタイルの持ち分）
- 重ねる幅（以前の `OWN_MARGIN`・`DIAG_WIDE_*`）はやめた。Blender で地面を描いて持ち分にする案は、1px ずれて 1タイル約60px 違った
- 坂の形: 形をタイルの範囲で切ってから高さを足す（`apply_slope`）。タイルの外へ坂を延ばすと、付け根で段差になっていた
- 横向きの斜め（高速道路の中央線）: 中央線が画素の行の境にかかり灰色に見えたので、線を半画素ずらした（`DIAG_CENTER_SHIFT`）
- 斜めの帯の切り口: 下の節のとおり、画面の菱形の半分で切る

確かめ方（ゲームの画面と、シートのセルを同じ順に貼った予想図を画素単位で比べる）:

- `ingame/capture_check.sh`: 線路（新・旧）・道路・高速道路の6か所（行き止まり・輪・分岐・斜め2系統・坂の十字）を
  MCP で等倍に撮り、周りのタイルの一覧（位置・高さ・坂・向き）を書き出し、`blender/ingame_diff.py` で比べる
- `blender/ingame_diff.py`: 違う画素の数と、形の欠け・出っ張りの候補（上下左右の覆われ方が周りと違う画素）を出す
- 結果: 4種類 × 6か所の 24 枚すべてで、ゲームと予想図の違いは 0px。
  ただし 0px は「ゲーム = 予想図」を示すだけで、予想図そのものの段は見つけられない。形の候補のうち左右対になって出た所
  （`expressway_dg2` の (189,416)・(450,416) など）を「角」と判断したが誤りで、次の節の段だった
- 見た目: 坂の十字・道路と高速道路の輪・線路の直線↔斜めとも、等倍で段差・線・点は見えない
  （`docs/seam_fix_loop_road.png`、`docs/seam_fix_loop_expressway.png`、`docs/seam_fix_track_diag.png`、`docs/seam_fix_slope_cross.png`）

## 特殊色（プレーヤーカラー・夜に光る色）

Simutrans の特殊色は 31 色（本体 `descriptor/image.cc` の `rgbtab`）。makeobj は RGB が完全に一致した画素だけを特殊色にする
（`descriptor/writer/image_writer.cc`）。一覧は `render.py` の `SPECIAL`。

### 意図しない特殊色を消す

- 描画結果の画素が偶然特殊色と一致したら、RGB を 1 ずつ上げてずらす（`finalize`。iss の `handleReplaceSpecialColor` と同じ）
- ずらした先がまた特殊色になる色は無い（`blender/special.py` で確認）
- 不具合を1つ直した: 色を `R*65536+G*256+B` の整数にするとき int16 で計算していて桁あふれし、見逃しと誤検出が起きていた。
  int32 に直す前は `road.png` に灰色の特殊色が 14px 残っていた（灰 2 が 10px、灰 3 が 4px。夜も暗くならない灰色として表示される）。直したあとは全シートで 0px
- 確認: `D:\bin\blender\blender.exe -b --factory-startup --python blender/special.py -- src/track.png src/road.png ...`
  （シートごと・特殊色の種類ごと・セルごとの画素数を出す）

### 意図して特殊色を入れる

- 材質に `special="<SPECIAL の名前>"` を付ける（例: `material("band", (0.35, 0.35, 0.35), special="player1")`）
- `render_cell` は特殊色の材質がある場面だけ、もう1枚「マスク」を描く（`work/<名前>_mask.png`）。
  特殊色の材質は種類ごとの番号の赤で発光させ、それ以外の材質は holdout にする。手前の物に隠れた所はマスクに出ない
- `make_sheet` は 1) 偶然の特殊色をずらす 2) マスクで半分以上覆われた画素を特殊色にする、の順に行う。
  縁の半端な画素は普通の色のまま残す（縁が特殊色だと会社の色を変えたときに輪郭がにじむため）
- 光る色（窓・照明・ランプ）は1色なのでそのまま入れる。プレーヤーカラーは 8 段階の明るさがあるので、
  描画結果の明るさがいちばん近い段階を選ぶ。材質を灰色にしておくと、日なたと日陰で段階が分かれる
- 料金所に入れた: 屋根の帯 = プレーヤーカラー1、ブースの窓 = 暗い窓（夜は黄色く光る）、
  安全島の両端の照明灯 = 黄色の光、ブースの上のランプ = 赤と緑の光
- 確認画像: `docs/special_tollbooth.png`（上: シート、下: 特殊色の画素。紫 = プレーヤーカラー、黒 = 光る色）
- 見え方の再現: `docs/special_preview.png`（上から 昼 / 会社の色を赤橙に変えたとき / 夜）。
  本体 `display/simgraph16.cc` の `calc_base_pal_from_night_shift` と同じ式で色を置き換えた（`blender/special_preview.py`）

### 直線↔斜めの段と白線の切れ目（2026-11-12 続き）

ゲーム内で、高速道路の直線と斜め（画面で横向き）のつなぎ目の上の縁に 1〜2px の段が見えた。
測ると、直線の舗装の上端は頂点の行（414 行目）まで来るのに、斜めの上端は 417 行目からだった。原因と直し方:

- 斜めの帯の切り口を内側へ 0.3 寄せていた（`DIAG_CUT_INSET`）。直線の舗装はタイルの頂点の行まであるので、その分が段になった
  → 形は帯より `DIAG_OVERFILL = 0.6` 広く残し、切るのは持ち分マスクの側で、菱形の中心を通る横・縦の線で切る
  （`_ground_mask` の `side`。nw は上、se は下、sw は左、ne は右の半分）。この線は隣の直線・斜めの菱形の頂点を通るので、縁がそろう
- 白線の切れ目（つなぎ目の1px が暗い）と縁石の段: 道路の絵を地面より 1px 下（`set_anchor(128)`。SIS の道路と同じ位置）に描いていた。
  タイルの辺は 2:1 の斜めなので、絵の中で形が曲がる所と持ち分の境が、辺に沿って 2px ずれる。その 2px は直線のタイルが描くが、
  直線の絵は隣が斜めか直線か知らないので、白線をまっすぐ延ばしたまま描いてしまう
  → 最初は道路を地面と同じ位置（127）に描いて直したが、SIS や pak128 標準の道路とつなぐと隙間が出た（次の節）。
  今は絵と持ち分を一緒に 1px 下げている
- 斜めの車道・縁石・白線の位置: 直線とタイルの辺で同じ点を通るよう、経路からの距離を直線の 1/√2 にした（`DIAG_EDGE`。
  以前は SIS に合わせて 車道 2.7、白線 直線の 0.632 倍（高速道路は 0.68 倍）で、辺で 0.1〜0.4 ずれていた）
- 横向きの斜めの路側の白線は、そのままだと画素の行の境にかかって灰色になるので、経路からの距離を「整数 + 0.5」px に丸める
  （約 0.3px 内へ）。縦向きの斜めはそのままで列に収まる。縦横の両方を同時に収める位置は無い

結果（`docs/seam_fix_expressway_diag.png`）: 道路・高速道路の 12 枚で、ゲームと予想図の違いは 0px。対になった形の候補（直線↔斜め・輪の角）は消えた。
残る候補は、坂の十字の歩道の丸い角に囲まれた草の先端（自然な尖り）と、まっすぐな縁の1画素で、見た目には何も無い。

残り: 線路も直線↔斜めのつなぎ目の下の角に、草が1〜2px 尖って入り込む（新・旧とも）。線路の描画位置は pak128 の決まり
（新はレールが 4px 下・旧は地面と同じ）なので道路のように動かせない。斜めの道床の幅を、道路と同じく辺で直線とそろえると直る見込み

### SIS・pak128 標準の道路とのつなぎ目（2026-11-12 続き）

道路を地面と同じ位置に描くと、このアドオンどうしはきれいにつながったが、SIS の高速道路や pak128 標準の道路（Road_050）と

### 他のアドオンとのつなぎ目の自動判定（2026-11-13）

`ingame/seam_check.sh` → `blender/seam_judge.py`。相手のタイルとこのアドオンのタイルが道でつながる辺（継ぎ目）ごとに、両側の道の帯を測って比べる。

- 継ぎ目の草: 継ぎ目の線（±1px）の上で、両側の帯の縁より 2px 内側にある草の画素。草は「緑が赤・青より 12 以上、青より 40 以上大きい」色
  （歩道の緑がかった敷石は、緑が青より 16〜24 大きいだけなので草にしない）
- 中心のずれ: 継ぎ目から 4〜20px（曲がりは 3〜10px）離れた所で、帯を横切る向きに草でない画素が続く範囲の中央値を両側で比べる。
  両側の縁が測れて、幅の差が 3px 以下のときだけ判定する（縁がタイルの角まで届く道、曲がり、幅の違う相手は参考値）
- 模様のずれ: 帯を横切る明るさの断面の相互相関で、いちばん合うずらし量（1px 未満まで）。相関 0.5 未満と曲がりは判定しない
- 曲がりのタイルが斜めの絵かカーブの絵かは、出口の先の隣が階段状に続く曲がりかどうかで決める
- 位置はタイルの並びから計算する。絵で位置を探すと、こちらの絵のずれを位置合わせが吸収してしまう（わざとずらした絵で、2px のずれが位置合わせに吸われた）

結果（全 5 組 × 4 種類、継ぎ目 35 か所）:
- SIS の一般道・SIS の高速道路・Road_050・SIS の新幹線（旧描画位置）とは、全 28 か所が合格。目で見た結果（草の線・段なし）と一致した
- Rail_100（新描画位置）とは、7 か所のうち 5 か所が不合格:
  - こちらが奥・Rail_100 が手前の継ぎ目（直線・坂）に、帯の上側の草の線（15〜28px）。ゲームの画面を拡大しても見える
    （`docs/seam_judge_rail100_ew.png` の右。黄が草と判定した画素）。Rail_100 の道床は奥の辺の近くで上の数行が欠けていて、
    奥のタイルのはみ出しで埋める作りらしい。こちらは持ち分を地面の菱形どおりに切っているので埋まらなかった（下の「Rail_100 が手前の草の線を直す」で直した）
  - Rail_100 の直線とこちらのカーブの内側の角に、草 4px

### 線路を「部品」と「基準面」の組み立てにまとめ直す（2026-11-13）

絵の元は 3D ファイルではなく `blender/render.py` で、毎回形を組み立てて撮る。これまでは道床・まくらぎ・レールを別々の物として作り、
「レールは 4px、道床は 2px、横向きの斜めは半分、坂は割り戻す」を部品ごとに当てていた。
レールと道床の動かし方が食い違うと、急坂でまくらぎが道床に埋もれた（上の節）。同じ種類の失敗を防ぐため、作りをまとめ直した。絵は変えていない。

- **基準面（`Datum(drop, ground)`）**: 部品が乗る面。描画位置のずれ（下げ幅）は、部品ではなく基準面が持つ
  - `bed`: 路盤の面。道床など、地面に置く物
  - `rail`: 走行面。まくらぎ・レールなど、軌道に付く物
- **部品（`Part`）**: 名前・乗る基準面・横幅の倍率の種類・材質・形（経路 → 頂点と面）・まとまり（`group`）。線路は `TRACK_PARTS` の 4 つ
- **組み立て（`assemble`）**: 部品を経路ごとに作り、乗っている基準面の分だけ動かし、坂を当て、タイルの外を切る
- **動かし方（`datum_move`）**: 画面で n px 下げる動かし方はここ 1 か所。坂の割り戻し・横向きの斜めの半分（`div`）もここで決まる
- **描画位置（`TRACK_PROFILES`）**: 新は `bed: Datum(2, 1)`・`rail: Datum(4, 1)`、旧はどちらも 0。`dy`・`ballast_drop`・`ground_shift` は無くなった
- 確かめ: 新・旧のシートを描き直し、前のシートと全画素を比べて、違う画素は 0（`src/*.png` に差分なし）

今後の検証項目の置き場所（まだ作っていない。作るときの目安）:

| 項目 | 置き場所 |
|---|---|
| 車止め | `rail` に乗る部品。形は経路の端に置く（行き止まりのセル `s`・`w`・`n`・`e` だけ）。`group="structure"` |
| 側壁・ガードレール | `bed` に乗る部品。経路から横へ一定の距離で押し出す。高さがあるので持ち分（はみ出し）の決まりを確かめ直す |
| 橋脚・橋・トンネル | `bed` より下の新しい基準面（例: `pier`）。高架は dat の画像の種類も別なので、シートの割り当てから決める |
| 路面の痛み・さび色 | 形ではなく材質。部品の面の上で、経路からの距離（走行位置・レールの脇）で色を変える。`rail` に乗る薄い部品にしてもよい |
| 降雪 | 同じ部品のまとまり違い（`group="snow"`）か、材質の差し替えで、雪用のシートをもう 1 枚描く |
| アイコン | 同じ `assemble` を `clip=False` で使う（今もそうしている）。背景色・文字・配置は種類の表（速度・地上/高架・waytype）から決める |
| カーソル | アイコンと同じ仕組みで、情報を足した別の絵にする（今は `ns` のセルの流用） |

道路（`build_road`）は、車道を歩道から型抜きする作りで、まだこの形にしていない。側壁やウェザリングを道路にも付けるときに合わせる。

### 側壁と橋の試作の直し（2026-11-13 続き）

ゲームで見つかった点を直した。本体のシート（`track.png`・`track_old.png`）には触れていない。

側壁（`bpoc_track_wall`）:
- **手前と奥の分け方**: 直線だけでなく、すべてのセル（坂・急坂・行き止まり・カーブ・横向きの斜め）で、カメラに近い側の壁を手前の絵に分けた
  （`render_layers`。壁の重心が本体の重心よりカメラ側なら手前）。dat は `frontimage`・`frontimageup`・`frontimageup2`・`frontdiagonal` を
  すべての絵に付け、シートの 4 行下の同じ列に置く。画面で縦向きの斜めは壁が左右に並ぶので、どちらも奥の絵
- **縦線**: 直線の壁だけ手前の絵にしていたとき、直線とカーブの境で、手前の絵と奥の絵の描く順が食い違って縦線が出ていた。
  全セルで分けたら、輪（直線↔カーブ）の境の縦線は消えた
- **全パターンの見本**: `ingame/wall.nut` を `all_dirs.nut` と同じ形（行き止まり・直線・カーブ・T字・十字・斜め・坂）にした（x=20〜, y=120〜）。
  撮って拡大して見た結果（`docs/trial_wall_all.png`）:
  - 直線↔カーブ・坂・行き止まり: 縦線なし
  - 分岐・十字の隣: 壁を付けていないタイルとの境で壁が終わり、切り口の暗い面が縦の帯で見える（継ぎ目ではなく壁の端。分岐用の壁は未対応）
  - 縦向きの斜め↔直線: 斜めの壁は道床の幅の倍率（1/√2）で内側に寄るので、直線の壁とつながらない（未対応）

橋（`bpoc_track_bridge`）:
- **東西の橋が架からなかった原因**: 見本（`ingame/bridge.nut`）の坂の向きが逆だった（絵の問題ではない）。直して架かった
- **端の絵の種類**（本体の `descriptor/bridge_desc.cc`）: 坂のタイルから始まる橋は `Start`（平らな橋の絵）、平地から立ち上がる橋は `Ramp`（坂の絵）。
  急坂は `Start2`・`Ramp2`。`Ramp[N]` は「北が高い坂」の絵（本体の `slope_t::north` は南が高い坂で、そのとき `S` の絵が使われる）
- **急坂の端**: `Start2`・`Ramp2` を足した。坂 1 段・2 段のどちらの端からも架けられ、平地からは 2 段の坂で立ち上がる
- **欄干の手前と奥**: 橋も全部の絵で `Front...` に手前の欄干を分けた
- ゲームで確かめた形（`docs/trial_bridge_all.png`）: 坂から始まる橋（東西・南北、1 段・2 段）、平地から立ち上がる橋（東西・南北）
- 残り: カメラ側が高い端の坂（西端・北端）は、坂が画面でつぶれて見えるので、手前の欄干が線路を隠す。絵の位置（オフセット）は今も測っていない。
  車両を走らせた確認はしていない（手前の絵が車両の上に来るかは未確認）
