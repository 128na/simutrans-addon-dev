# blender-poc

iss（Illustrator で作ったインフラアドオン）の作り方を Blender に置き換えられるかを確かめる検証用アドオンです。配布用ではありません。

- 対象: Simutrans 125.0 以降 / pak128（画像は iss と同じ 256px セルで作り、タイルの外へはみ出せる）
- ライセンス: 未定（検証用）。sis（CC BY-NC-SA）からはカメラの数値だけを参考にし、形状・素材・画像は使っていない

## 中身

| ファイル | 内容 |
|---|---|
| `blender/render.py` | Blender をコマンドで動かし、形状をスクリプトで組み立てて描画し、シート画像を作る |
| `blender/check.py` | 描画位置の検証。タイル菱形の位置と、iss の既存画像との描画範囲を比べる |
| `blender/preview.py` | 確認用の拡大画像 `work/preview.png` を作る |
| `blender/compose.py` | つなぎ目の確認。シートのセルをゲームと同じ位置・順番で並べた画像を作る |
| `blender/special.py` | 特殊色の検査。シートに特殊色が何 px、どのセルにあるかを数える |
| `blender/special_preview.py` | 特殊色の見え方の再現（昼・会社の色を変えたとき・夜）|
| `src/track.dat` | 線路・新描画位置（道床が低い。今の pak128・iss）。セル配置は iss の線路と同じ |
| `src/track_old.dat` | 線路・旧描画位置（道床が高い。古い pak128・SIS）。形は `track.dat` と同じで、名前は `bpoc_track_old` |
| `src/road.dat` | 道路（歩道付き、50km/h）。幅・白線・縁石の位置は SIS の一般道 `SIS_L_RG1-1_01S` に合わせる。セル配置は線路と同じ |
| `src/expressway.dat` | 高速道路（歩道なし、120km/h）。SIS の高速道路 `SIS_E_RG1-1_01S` に合わせる。カーブは SIS と同じく斜めの絵を使う |
| `src/tollbooth.dat` | 料金所風の建物（駅の付属建物扱い）。屋根がタイルからはみ出す |

## 必要なもの

- Blender 4.5 LTS（`D:\bin\blender\blender.exe` で確認）
- makeobj（PATH 上。60.12 で確認）

## ビルド

アドオンのディレクトリで:

```powershell
D:\bin\blender\blender.exe -b --factory-startup --python blender/render.py
cd src; makeobj pak256 ..\dist\bpoc.pak track.dat track_old.dat road.dat expressway.dat tollbooth.dat; cd ..
```

iss と同じく `pak256` で 256px セルとして切り出す（ゲームは pak128）。

位置の検証:

```powershell
D:\bin\blender\blender.exe -b --factory-startup --python blender/check.py -- ..\..\..\iss\src\way\rail\standard_slab.png
```

## 描画の決まりごと

- カメラ: 正投影、回転 X60° / Z45°（sis と同じ向き）。`ortho_scale = 20√2`、256px でタイル1辺10 → 菱形 128×64px
- 高さ1段 16px = Blender で約 2.041
- Blender の向き: +Y が北（画面右上）、+X が東（画面右下）
- タイル中心をセルの (128,128) に映す → dat オフセット `-64,-32`（線路）
  建物はカメラをずらして (128,192) に映す → `-64,-96`
- 線路はタイルの範囲で切り抜いて（Boolean）、隣のタイルとの継ぎ目をそろえる
- 線路の形はほぼ平ら（道床の厚み 0.12 ≈ 1px、レール上面 0.30 ≈ 2px）で、新・旧の描画位置で共通
- レールの間隔は iss・SIS と同じく画面上 6px（直線）。レール中心の間隔 0.934（1単位 ≈ 6.4px）
- 新描画位置と旧描画位置は、画面上の上下位置だけが違う。カメラを整数 px ずらして描き分ける（`render.py` の `TRACK_PROFILES`）。
  タイル中心を基準にして、新は 3px 下げ（iss に合わせる）、旧は 1px 上げ（SIS に合わせる）。
  iss と SIS のレールの位置を比べると、直線・斜め・坂のどの方位でも、画面上で 4〜4.5px 上下にずれているだけだった
- 斜めのタイルはレール・まくらぎの横幅を 2/√10（≈0.63）倍、道床を 0.8 倍にする。
  3D のまま描くと斜めは横幅が縮まずに映り、直線の約1.6倍太く見えるため（pak128 標準も斜めはレール間隔を細く描く）
- 後処理は iss と同じ: 特殊色にたまたま一致した画素は +1 ずらす。アルファ25未満は `#E7FFFF`、それ以外は不透明にする。
  そのあとで、材質に指定した特殊色を入れる（下の「特殊色」）

  iss のカーブはタイルの外まで描く別の作りで、もともと差が大きいところ（上の「カーブは描き方が違う」）
- ゲーム内のつなぎ目（`ingame/seam.nut`。比べる線路 → 検証用の線路 → 比べる線路 の順に1本につなぐ）:

    坂の下の境目で、2本のレールが段差なくつながった（`docs/seam_old.png`・`docs/seam_old_straight.png`・`docs/seam_old_detail.png`）。

  - 新描画位置と pak128 標準 Rail_100: 目立つ段差は無い。ただし Rail_100 は道床の幅も模様も違い、

### 道路（2026-11-12）

車道の幅はアドオンによってまちまちなので、SIS の一般道（`Local_Street/1-1lane` の `SIS_L_RG1-1_01S`、歩道付き 50km/h）を基準にした。

- SIS の直線セルの中心の列を測った断面（タイル半幅を 5 とした横位置）: 中央線 0、車道 ±3.2、路側の白線 ±3.3〜3.45、
  縁石 ±3.6〜3.85（奥側は立ち上がりが 2〜3px 見える）、歩道はタイルの端まで。路面は地面と同じ高さ（中央線がタイル中心を通る）
- 作り方: タイル全面の歩道（縁石の色の板 + 石畳の薄い板）から、車道の中心線に沿った型を Boolean で抜く。
  抜いた切り口が縁石の立ち上がりになる。分岐・十字は型を重ねるだけで口が開き、角は扇形に丸める（SIS と同じ）
- 斜め: SIS もタイルの半分の三角形だけを描き（残りは隣のタイル）、横幅を 2/√10 倍に縮めている。
  ただし車道の半幅は縮めた後で約 2.7 と、白線の外に余白がある。これに合わせた
- SIS とセルごとに並べた比較: `docs/road_cells.png`（上段 SIS、下段 移植版）。斜めの白線と縁石の位置は 1px 以内
- 色は SIS の直線で平均を合わせた（車道 49/45、歩道 89/84。左が移植版）。石畳とアスファルトのまだら模様はノイズで付けた
- ゲーム内のつなぎ目（`ingame/road_seam.nut`。SIS → 検証用 → SIS の順に1本につなぐ）: 東西・南北の直線、斜め、坂、
  SIS の直線から分かれる分岐で、歩道の縁・縁石・白線が段差なくつながった（`docs/road_seam.png`・`docs/road_seam_detail.png`）
- SIS と違うところ: 行き止まりの白線（SIS はコの字に回す。移植版は両脇だけ）、十字の中央の × 印、単独タイルの角の形、
  斜めのタイルの内側の歩道の端に小さな段が出る

### 高速道路（2026-11-12）

SIS の道路8種（一般道 50/70/80km/h、高速 80/100/120/999km/h）の直線を測ると、路側の白線（±22px）と中央線の位置はどれも同じだった。
違うのは白線の外側（歩道＋縁石／灰色の路肩／タイルの端までアスファルト）と線の種類で、高速道路は斜めの白線だけ約 1.08 倍外にある。
そこで道路と同じ作りに「歩道を作らない」切り替えを足し、`SIS_E_RG1-1_01S`（片側1車線、120km/h）に合わせた。

- タイル全面がアスファルト。色は SIS に合わせて暗く青みがある（平均 18,19,24 と SIS 20,20,27）。照り返しを切らないと空の色が映って明るくなる
- 分岐は枝の側の路側線を点線（約2px の四角）にする。十字と単独のタイルは東西の中央線と両側の点線。行き止まりは直線と同じ絵
- カーブは SIS と同じく、同じ向きの斜めの絵を dat で割り当てる（`image[nw]` = `diagonal[nw]`）
- SIS とセルごとに並べた比較: `docs/expressway_cells.png`（上段 SIS、下段 移植版）
- ゲーム内のつなぎ目（`ingame/road_seam.nut` の y=160〜）: 直線・斜め・坂・分岐で白線が段差なくつながった（`docs/expressway_seam.png`）
- SIS と違うところ: 分岐・十字のタイルの左右の角にある小さな透明の三角、行き止まりの白線の模様（SIS は市松模様）

## つなぎ目のバリ（2026-11-12）

ゲーム内の等倍表示で、斜め同士と坂の周りのタイルの境にバリが出ていた。原因と直し方:

- 斜めの道路の縁石の切り欠き: 車道・縁石を抜く型の経路を、辺の中点から 2.5 しか延ばしていなかった。
  45° の向きでは型の端の角がタイルの内側に入り込み、端の近くで縁石が削り残されていた → `DIAG_EXT = 8.0` に延ばした
- 白線の途切れ・暗い点・明るい点: タイルの境の画素を、それぞれのタイルが「自分の側にある部分だけの色」で描いていた
  （形をタイルの範囲で切り抜き、アルファ25以上を不透明にしていたため）。細い線が境にかかると、片側だけの色が残る
- 坂の付け根の緑の線: 本体（OTRP 版）は坂のタイルの地面を物と一緒に後から描き、奥のタイルの線路の端の画素を上書きする
  （`boden/grund.cc` の `draw_as_obj`）。手前のタイルの絵がその画素を描いていないと地面が見える

2つ目と3つ目は描き方を変えて直した（`render.py` の `render_cell`）:

- 形はタイルより `CLIP_PAD = 0.6` だけ大きく切り抜いて描く。境の画素も、隣とつながった形で画素全体の色になる
- もう1枚「持ち分マスク」（`work/<名前>_own.png`）を描く。面のワールド座標がタイルの中なら白く光る材質に差し替えたもの。
  画素の半分以上が持ち分の面なら残し、それ以外は透明にする（隣のタイルが同じ色で描く）
- つながる向きの辺だけ、持ち分を外へ広げて隣と重ねる。重なった画素はどちらも同じ色なので、
  後から描くタイルの地面に上書きされても描き直される。斜めのタイルは、残す角の頂点を通る線の手前までにする（歩道が草地へ出っ張らないように）。
  広げる幅は次の節のとおりタイルの種類で変える
- 確認用の合成: `blender/compose.py` でシートのセルをゲームと同じ位置・順番に並べる（`docs/compose_*.png`）。
  ゲーム画面にセルを当てはめると、計算どおりの位置で一致した
- ゲーム内（等倍、`gui.set_zoom(3)`）: 斜めの縁石・白線は段差なくつながった（`docs/seam_fix_road.png`）。
  坂の付け根は緑の線が消え、合成との違いは道床の縁の1px が数か所だけ（`docs/seam_fix_slope_diff.png`。左 ゲーム、中 合成、右 違う画素を紫）
- 注意: MCP の `gui.set_zoom(1)` は 1.5 倍で、等倍は `set_zoom(3)`。これまでのつなぎ目の確認画像は 1.5 倍で撮っていた

### 直線とのつなぎ目（2026-11-12 続き）

上の直し方の後、斜めとカーブはきれいになったが、直線とのつなぎ目が目立つようになった:

- カーブ↔直線（道路）の灰色の点線: 経路をタイルの辺から 0.6 しか延ばしておらず、切り抜く幅 `CLIP_PAD` と同じだった。
  車道を抜く型の端が切り抜きの縁と重なり、カーブでは型の端がわずかに斜めなので、縁石が細いくさびの形で残っていた
  → 経路の延長を `PATH_EXT = 1.5` にし、カーブの端は円の接線の向きに延ばす
- 直線↔斜めの段差（線路・高速道路の角）: 全部のタイルを 0.5（約3px）重ねていたので、直線の道床や白線が、
  半分しか描かない斜めのタイルの側へはみ出していた。逆に斜めの車道が、先に描かれた直線の白線の端を覆い、角で白線が切れていた

重ねる幅を、タイルの種類で変えた（`render.py` の `OWN_MARGIN` など）:

| タイル | 重ねる幅 | 理由 |
|---|---|---|
| 平ら（直線・カーブ・分岐など） | `OWN_MARGIN = 0.2`（約1px） | 境の画素を埋めるだけにする。0 だと斜め同士の境などに緑の線が出る |
| 坂 | `OWN_MARGIN_SLOPE = 0.5`（約3px） | 坂の地面は隣の端を広く上書きする |
| 斜め | 辺の中点から `DIAG_WIDE_*` より外は 0.5、内側は 0.2 | 外側（道床・歩道の縁）は 1px だと斜め同士の境に緑の点が残る。内側（白線・レール）を広げると直線の白線を覆う |

- 確認: `compose.py` に輪（カーブ4方向と直線）の並べ方を足した（`loop`）。高速道路のカーブは斜めの絵を使うので、合成でもそうする
- ゲーム内（等倍）: 道路の輪、高速道路の輪の角、線路の直線↔斜め、斜め同士、坂の十字がきれいにつながった
  （`docs/seam_fix_loop_road.png`、`docs/seam_fix_loop_expressway.png`、`docs/seam_fix_track_diag.png`）
- 残り: 高速道路の画面で横向きになる斜めのタイルは、中央線が画素の行の間にかかり、白でなく灰色に見える

## 特殊色（プレーヤーカラー・夜に光る色）

Simutrans の特殊色は 31 色（本体 `descriptor/image.cc` の `rgbtab`）。makeobj は RGB が完全に一致した画素だけを特殊色にする
（`descriptor/writer/image_writer.cc`）。一覧は `render.py` の `SPECIAL`。

### 意図しない特殊色を消す

- 描画結果の画素が偶然特殊色と一致したら、RGB を 1 ずつ上げてずらす（`finalize`。iss の `handleReplaceSpecialColor` と同じ）
- ずらした先がまた特殊色になる色は無い（`blender/special.py` で確認）
- 不具合を1つ直した: 色を `R*65536+G*256+B` の整数にするとき int16 で計算していて桁あふれし、見逃しと誤検出が起きていた。
  int32 に直す前は `road.png` に灰色の特殊色が 14px 残っていた（灰 2 が 10px、灰 3 が 4px。夜も暗くならない灰色として表示される）。直したあとは全シートで 0px
- 確認: `D:\bin\blender\blender.exe -b --factory-startup --python blender/special.py -- src/track.png src/road.png ...`
  （シートごと・特殊色の種類ごと・セルごとの画素数を出す）

### 意図して特殊色を入れる

- 材質に `special="<SPECIAL の名前>"` を付ける（例: `material("band", (0.35, 0.35, 0.35), special="player1")`）
- `render_cell` は特殊色の材質がある場面だけ、もう1枚「マスク」を描く（`work/<名前>_mask.png`）。
  特殊色の材質は種類ごとの番号の赤で発光させ、それ以外の材質は holdout にする。手前の物に隠れた所はマスクに出ない
- `make_sheet` は 1) 偶然の特殊色をずらす 2) マスクで半分以上覆われた画素を特殊色にする、の順に行う。
  縁の半端な画素は普通の色のまま残す（縁が特殊色だと会社の色を変えたときに輪郭がにじむため）
- 光る色（窓・照明・ランプ）は1色なのでそのまま入れる。プレーヤーカラーは 8 段階の明るさがあるので、
  描画結果の明るさがいちばん近い段階を選ぶ。材質を灰色にしておくと、日なたと日陰で段階が分かれる
- 料金所に入れた: 屋根の帯 = プレーヤーカラー1、ブースの窓 = 暗い窓（夜は黄色く光る）、
  安全島の両端の照明灯 = 黄色の光、ブースの上のランプ = 赤と緑の光
- 確認画像: `docs/special_tollbooth.png`（上: シート、下: 特殊色の画素。紫 = プレーヤーカラー、黒 = 光る色）
- 見え方の再現: `docs/special_preview.png`（上から 昼 / 会社の色を赤橙に変えたとき / 夜）。
  本体 `display/simgraph16.cc` の `calc_base_pal_from_night_shift` と同じ式で色を置き換えた（`blender/special_preview.py`）

  プレーヤーカラー1 の 1〜5 段、暗い窓(16)、黄(18)、赤(19)、緑(20)。道路だけの pak には入っていない

  - 会社の色は「プレーヤーの色」で変える。暗さは表示設定の「明るさ:」か、下のキー（`[` / `]`）で変える

## ゲーム内での確認

`addons/pak128/` に pak を置き、MCP 対応の OTRP 版をセーブ読み込みで起動して、`ingame/place.nut` を実行する。
手順は `simutrans` リポジトリの `simutrans-mcp-gui-debug` スキルと同じ。

```powershell
Copy-Item dist\bpoc.pak <Simutrans>\addons\pak128\
<OTRP版の実行ファイル> -objects pak128/ -addons -load flat -mcp-port 47123
python <simutrans>\.agents\skills\simutrans-mcp-gui-debug\scripts\mcp_client.py --port 47123 --run-squirrel (Get-Content -Raw ingame\place.nut) --capture work\ingame.png
```

- 全方位の見本: `ingame/all_dirs.nut` で、線路（新・旧）・道路・高速道路に同じ形の見本を x=20〜 y=20〜 に敷く
  （行き止まり4・直線2・カーブ4・T字4・十字・斜め2系統・坂4方向。ゲーム内で各タイルの向き15種と坂4種がそろうのを確認した）。
  料金所も4つの向きで y=42〜43 に置く。flat.sve にはこれを敷いた状態で保存してある（元の平地は `flat.sve.before-all-dirs-20261112`）
- 付属建物（type=extension）は停留所の隣にしか置けない
- 昼夜の切り替え（表示設定の「夜間は暗くする」）が入っていると短い周期で暗くなるので、数秒おきに撮って明るいものを使う
- 夜の表示を見るときは「夜間は暗くする」を切り、明るさを固定して変える。検証に使った環境では pak128 の `config/menuconf.tab` に
  `toolbar[0][44]=simple_tool[19],,[,-`（`[` で暗く）と `toolbar[0][45]=simple_tool[19],,],+`（`]` で明るく）を足した
