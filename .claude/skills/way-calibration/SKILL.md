# way のキャリブレーション（描画位置とつなぎ目）

道や線路の絵が、タイルの辺で隣のタイルの絵と段差なくつながるように、描画位置と持ち分を決める。
基準になるのは、つなぐ相手の手本（pak128 標準・SIS・iss）と、本体の描き方（地面を先に描き、物を奥から描く）である。

## 進め方の原則

1. **ツールでの自動検知を先にする。** スクショを目で見る前に、測定・合成・差分のツールを回して、候補の場所と数を出す。
2. **目で見るのは、ツールの取りこぼしとアドオン固有の観点だけ。** ツールが出した候補の座標を `zoom.py` で拡大して確かめる。
   ツールが見ていない所（下の「ツールが見ていない所」）は、撮って見る。
3. **目で見つけたものは、繰り返し確かめられる形になったらツールに足す。**
   たとえば「この種類の角は毎回この座標を見る」「この色の画素が出たら失敗」のような形にする。
   足したツールはアドオンの README の表に載せる。
4. **数値は手本の画像から測る。** 「pak128 はこうなっているはず」という思い込みで決めない。
   今回も「Rail_100 は道床ごと 4px 下」という思い込みが外れていた。重心は道床の幅や陰で 1〜2px 動くので、
   レールの位置は明るさの断面（`ref_measure.py` の「断面」）で比べる。

## ツール（`addons/blender-poc/` にある。2 つ目のアドオンで使うときは、リポジトリ直下の `tools/` へ移す）

| 段階 | ツール | 何を自動で出すか |
|---|---|---|
| 手本を測る | `blender/ref_measure.py` | 手本の画像（pak128 のソース・iss の元絵・自分のシート）で、直線・斜めの線が理想の位置から何 px ずれているか。直線のレールの行（明るさの断面） |
| 手本との比較 | `blender/check.py` | 自分のシートと iss の画像の、描画範囲と重心のずれ |
| ゲームなしの合成 | `blender/compose.py` | シートのセルをゲームと同じ位置・順番で並べた図（`diag`・`loop`・`slope`）。段・草の尖りを目で見る前段 |
| ゲームとの差分 | `ingame/all_dirs.nut` → `ingame/capture_check.sh` → `blender/ingame_diff.py` | 見本 6 か所の、ゲームの画面と予想図の違い（`[diff]` px）と、形の欠け・出っ張りの候補（`[shape]` の座標） |
| 他のアドオンとのつなぎ目 | `ingame/seam.nut`（線路）・`ingame/road_seam.nut`（道路）→ `ingame/seam_check.sh` → `blender/seam_judge.py` | 継ぎ目ごとの合否（`[seam] OK/NG`）と、継ぎ目の草・中心のずれ・幅の差・模様のずれの値、継ぎ目の拡大図 |
| 目で確かめる | `blender/zoom.py` | 指定した座標の周りを拡大して並べる。その画素に紫の印を付ける |

Blender は `blender -b --factory-startup --python <script> -- <引数>` で動かす。使い方は各スクリプトの冒頭の説明にある。

## 手順

### 1. 手本を決めて測る

- つなぐ相手を決める。線路なら pak128 標準（Rail_100 など）・SIS・iss、道路なら SIS の一般道・高速道路・pak128 標準（Road_050）。
- 元画像があるものは `ref_measure.py` で測る。pak128 のソースは `pak128/` の clone（例: `infrastructure/rail_tracks/rail_100_tracks.png`）、
  iss は `../iss/src/way/` の層。dat を見て、どのセルが直線・斜めかを確かめてから向きを指定する。
- 元画像が無いもの（SIS は pak だけ）は、ゲームでつないで撮って比べる（手順 4）。
- 自分のシートも同じツールで測り、手本と並べる。比べるのは次の三つ。
  - 直線のレール・白線の行（断面）
  - 道床・車道の重心
  - 斜めの位置（縦向きは x、横向きは y）

### 2. ゲームなしで合成して見る

`compose.py` で `diag`・`loop`・`slope` を作り、直線↔斜め・カーブ・坂の角を `zoom.py` で拡大する。
ここで段や草の尖りが見えたら、ゲームに入れる前に直す。

### 3. ゲームで差分を取る

1. pak を作ってゲームの `addons/pak128/` に置き、ゲームを MCP ポート付きで起動する（`flat.sve`）。
2. 見本は `ingame/all_dirs.nut` で敷く（`flat.sve` には保存済み。別のマップなら `--run-squirrel` で流す）。
3. `sh ingame/capture_check.sh` を回す（`SPECS` で種類を絞れる）。
4. 全か所が `[diff] 0 px` になるまで直す。`[shape]` の候補は座標を `zoom.py` で拡大し、つなぎ目か、行き止まりの端のような自然な角かを見分ける。
5. 線路の模様のくり返しで位置合わせがずれたときは、`INGAME_LOCATE=x,y` で位置を直接与える。

`[diff] 0 px` が保証するのは「各タイルが持ち分どおりに描かれている」ことだけで、絵どうしが段差なくつながっているかは保証しない。
つながり方は `[shape]` の候補と、手順 2・4 の拡大で見る。

### 4. 他のアドオンとのつなぎ目を判定する

1. `seam.nut`・`road_seam.nut` で「相手 → 自分 → 相手」の順に 1 本につないで敷く。ゲームを再起動したら流し直す。
2. `bash ingame/seam_check.sh` を回す（`BASES="名前:y"`・`KINDS` で絞れる）。
   直線（東西・南北）・斜め・坂を撮り、`blender/seam_judge.py` が継ぎ目ごとに `[seam] OK/NG` を出す。
   見るのは次の三つ。
   - 継ぎ目の草: 継ぎ目の線の上で、両側の帯の内側にある草の画素
   - 中心のずれ: 両側の帯の縁から出す段
   - 模様のずれ: 帯を横切る断面（レール・白線）の比較
3. NG の継ぎ目は `work/seam/<名前>_<種類>_judge.png` で見る。継ぎ目ごとの拡大で、紫が継ぎ目の点、黄が草と判定した画素。
   `[seam]` の行の座標を `zoom.py` で印なしに拡大し、本物か誤検出かを決める。
4. 一つの継ぎ目には「相手が奥・こちらが手前」と「こちらが奥・相手が手前」の2種類がある。両方を見る。
   はみ出しの決まり（下の「決まり」）が違う相手だと、片方だけに草の線が出る。

判定の限界（2026-11-13 に、道路の絵をわざと 2px 下げて確かめた結果）:
- 2px のずれは、こちらが手前の継ぎ目に出る草の線（23〜43px）で不合格になった
- 模様のずれは、2px 下げても 1.0〜1.5px にしか出なかった（帯を斜めに横切って測るので小さく出る）。模様だけで不合格になるのは、それより大きなずれ
- 中心のずれは、両側の縁が測れて幅がそろう（差 3px 以下）ときだけ判定する。
  歩道付きの道路・全面の道床（縁がタイルの角まで届く）、曲がり（片側の縁しか測れない）、幅の違う相手では参考値。
  幅の違う相手（Rail_100 は道床が広い）では、中心の差は段ではなく作りの違い
- 草の色は、緑が赤・青より 12 以上、青より 40 以上大きい画素。歩道の緑がかった敷石は草にしない。地面の違うマップでは確かめ直す

### 5. 直したら記録する

- アドオンの README に、何を測り、何が原因で、どう直したかを書く。数値は測った値を書き、推測とは分ける。
- 調査の経緯はリポジトリ直下の `docs/records/YYYY-MM-DD_slug.md` に新しく書く（書いたら変更しない。規約は `docs/README.md`）。
- 確認画像は `addons/<アドオン>/docs/` に置く。

## これまでに分かっている本体と手本の決まり（2026-11 時点。新しい手本では測り直す）

- **持ち分は地面の菱形で決める。** 奥のタイルが手前へはみ出した絵は、手前の平らな地面が先に描かれるので、約 1 行（＋半行）までしか残らない。
  持ち分を 2 行以上ずらすと、継ぎ目に草の線が出る。坂のタイルは地面を後から描き直すので、奥からのはみ出しを消す。
- **SIS・pak128 標準の道路** は、菱形を地面より 1px 下にずらして描き、自分の上の 1 行は奥のタイルのはみ出しで埋める。
  合わせるときは、絵と持ち分を一緒に 1px 下げ、手前の縁を半行広げる。
- **線路の新描画位置**（今の pak128・iss）でも、下がっているのはレールだけで、道床は地面の位置にある。
  斜めの絵はタイルの中心に描かれている。道床まで下げると、画面で縦向きの斜め（sw・ne）との角に段が出る。
  道床は地面の位置に置き、レールとまくらぎだけを下げる（横向きの斜めは半分）。
- **斜めの幅**: 道床・車道・白線は、経路からの距離を直線の 1/√2 にすると、タイルの辺で直線と同じ点を通る。
- **Rail_100 が手前の継ぎ目**（2026-11-13、`seam_judge.py`）: 移植版の線路（新）が奥・Rail_100 が手前の継ぎ目では、
  帯の上側に草の線（15〜28px）が出る。Rail_100 の道床は奥の辺の近くで上の数行が欠けていて、奥のタイルのはみ出しで埋める作りらしい。
  移植版は持ち分を地面の菱形どおりに切っていたので、そこが埋まらなかった。
  新の線路だけ持ち分を手前の2辺へ 1 行と半行はみ出させて直した（`render.py` の `TRACK_PROFILES` の `spill`）。
  相手の作りに合わせてはみ出しを足すときは、他の相手（SIS・道路）との継ぎ目と `capture_check.sh` の差分が変わらないことも確かめる

## ツールが見ていない所（目で確かめる。確かめ方が決まったらツールに足す）

- 他のアドオンとのつなぎ目の、1〜2px の段。`seam_judge.py` は草の線は拾うが、1〜2px のずれは模様のずれだけでは拾いきれない（手順 4 の「判定の限界」）
- 幅の違う相手との段、曲がりとの継ぎ目の段（`seam_judge.py` では参考値）
- 坂の十字の、坂の斜め隣の角のタイル。坂は地面を後から描くが、予想図はそれを再現していないので、`[diff]` が出てもゲームの画面が正しいことがある
- レールや白線の色・太さ・間隔の見た目（手本と並べて見る）
- 夜の見え方・特殊色（`blender/special.py`・`special_preview.py`）
- アドオン固有の部品（料金所の屋根のはみ出し、歩道の角など）

## つまずきやすい所

- ゲームを再起動すると、`flat.sve` に残っているのは `all_dirs.nut` の見本だけになる。`seam.nut`・`road_seam.nut` は流し直す。
- ゲームの画面はコンピューター操作ではなく MCP（`--run-squirrel`・`--capture`）で操作して撮る。
- README や `render.py` は CRLF のことがある。Python で置き換えるときは改行をそろえるか、Edit ツールを使う。
- 標準入力で Python に日本語を流すと cp932 で壊れる。スクリプトはファイルに書いて `python -X utf8` で動かす。
- Blender で、作った直後のカメラの `matrix_world` は更新されていない。向きは `rotation_euler.to_matrix()` から取る。
