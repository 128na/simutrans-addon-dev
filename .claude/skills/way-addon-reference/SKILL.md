# way アドオンのリファレンス（Blender のスクリプトで作る）

`addons/blender-poc/` で線路一式（本体・側壁 4 種・高架 4 種・橋・トンネル）を作って分かったことを、作業のときに引ける形でまとめる。
経緯と数値は [README](../../../addons/blender-poc/README.md) の各節、できたと言う条件は [ACCEPTANCE.md](../../../addons/blender-poc/ACCEPTANCE.md)、
位置合わせの手順は [way-calibration](../way-calibration/SKILL.md) にある。ここは「決まり」と「どこを直すか」だけを書く。

## 1. 進め方

1. **受け入れ条件を先に書く。** 試行錯誤が続いたのは、条件が頭の中にしか無かったため。`ACCEPTANCE.md` に条件・状態・確かめ方を書き、直すたびに表で確かめる
2. **手本を先に見る。** pak128 のソース（`../pak128/`）と iss（`../iss/src/`）の絵と dat を、作る前に見る。
   思い込みで作って手本と違った例: 斜めの壁の位置、坑口の形（タイル全体の箱で屋根は丘の上面）、橋の端の絵の種類
3. **本体のソースで決まりを確かめる。** dat のキー・絵の番号・建設の条件は `../simutrans/descriptor/`・`bauer/`・`script/api/` を読む（下の 5 章）
4. **確認用の色でセルを見る → ゲームで見る。** `BPOC_DEBUG_COLORS=1` で部品を色分けして描き（`work/debug/`）、形が合ってから通常の色で描いてゲームに入れる
5. **本体のシートを崩さない。** 試すものは別のアドオン（別のシート・dat）にする。本体を描き直したら、前のシートと全画素を比べる

## 2. 絵の作り（`blender/render.py`）

絵の元は 3D ファイルではなくスクリプトで、毎回形を組み立てて撮る。

| もの | 役目 |
|---|---|
| `Datum(drop, ground)` | 基準面。描画位置のずれは部品ではなく基準面が持つ。`bed`（路盤: 道床・壁・基盤）と `rail`（走行面: まくらぎ・レール・車止め） |
| `Part` | 部品。乗る基準面・横幅の倍率・材質・形（経路 → 頂点と面）・まとまり（`group`）。`where="end"` は行き止まりの端だけ、`tall` は高さのある部品、`corridor` は分岐で削る幅、`ground` は坂の下を埋める躯体 |
| `assemble` | 部品を経路ごとに作り、基準面の分だけ動かし、坂を当て、タイルの外を切る |
| `datum_move` | 「画面で n px 下げる」の計算はここ 1 か所（坂の割り戻し、横向きの斜めの半分） |
| `build_base` | 基盤。タイル全面の板から、残した壁の外側だけを削る |
| `render_layers` | 高さのある部品を別の層として描き、カメラに近い側を手前の絵に分ける |
| `TRACK_PROFILES` | アドオンごとの設定（シート名・基準面・使う `group`・`walls`・`snow`・`front_row`・`lower`・`band`） |

部品を足すときは、乗る基準面を選ぶだけで位置が決まる。部品ごとに位置を足し引きしない
（レールと道床を別々のやり方で動かして、急坂でまくらぎが道床に埋もれた）。

## 3. 持ち分（どの画素をそのタイルが描くか）

- **平らな部分**: 地面の菱形（`_ground_mask`）。奥のタイルのはみ出しは手前の地面に消されるので、範囲の外は描かない
- **高さのある部品**（壁・躯体）: 持ち分の全体を上へ広げる（`rise`）。奥のタイルの絵の上に出る（建物と同じ）。
  タイルの境の切り口の面は取る（`open_ends`。残すと暗い縦線になる）。輪郭の半透明の画素は捨てる（黒い点線になる）
- **坂の下・床の下が見える絵**: 平地に立つ坂（橋の Ramp）は坂の面から地面まで（`solid`）、坂から始まる橋（Start）は地面を下げた形、
  高架は床の 1 段下まで（`lower`）
- **手前/奥**: カメラは南東。東西の線路は北が奥、南北の線路は西が奥。斜めは東寄りが手前（`NEAR_AXIS`）。
  T字は、まっすぐ通る線路に対して決める

## 4. 側壁・基盤・バリエーション

- 名前の末尾は `single`（両側）・`back`（奥だけ）・`center`（なし）・`front`（手前だけ）。iss・SIS と同じ並べ方
- 壁: 経路から一定の距離の両側。斜めも同じ作りにする（タイルの辺で直線の壁と同じ点を通る）。
  分岐・十字は、ほかの経路の通り道に入る部分を削る（先の経路の壁を残し、重なった切れ端を消す）
- 基盤: 壁のある側は壁で止まり、壁のない側はタイルの端まで埋まる。経路ごとの板を足し合わせる作りは、分岐で壁を突き抜けた
- 行き止まり: 車止め + 端の壁（タイルの幅いっぱいに作り、残した側壁の外側を削る）。並べると 1 つのコの字になる
- 1 タイルだけの軌道: 全面の基盤だけ（すき間埋めの景観用）
- 高架: 側壁の版 + 橋脚 + `lower`。dat は `system_type=1`

## 5. dat と本体の決まり（本体のソースで確かめたもの）

| こと | 決まり | 確かめた場所 |
|---|---|---|
| way の手前の絵 | `frontimage`・`frontimageup`・`frontimageup2`・`frontdiagonal` | `descriptor/writer/way_writer.cc` |
| 雪の絵 | 同じキーの `[1]` | 同上 |
| way の坂の番号 | `imageup[12]` 北が高い・`[3]` 南・`[6]` 東・`[9]` 西 | ゲームで確認 |
| 橋の端 | 坂のタイルから始まる橋は `Start`（平らな絵）、平地から立ち上がる橋は `Ramp`（坂の絵）。2 段は `Start2`・`Ramp2` | `descriptor/bridge_desc.cc` |
| 橋の `Ramp[N]` | 北が高い坂の絵（本体の `slope_t::north` は南が高い坂で、そのとき `S` の絵を使う） | 同上 |
| 橋の `Start[N]` | 南が高い坂のタイルで使われる | 同上 |
| トンネルの `image[N]` | 北が高い坂のタイル | `descriptor/tunnel_desc.cc` |
| トンネルの坑口 | pak128 では 2 段の坂にしか置けない | `bauer/tunnelbauer.cc` |
| 地形の坂の番号 | 角の桁は sw=1・se=3・ne=9・nw=27。1 段の北が高い坂は 36、南 4、東 12、西 28（2 段は 2 倍） | `ingame/*.nut` で確認 |

dat は手で書かず `python -X utf8 blender/track_dat.py` で書き出す。シートの行の並びは
「奥の絵 4 行 →（手前の絵 4 行）→ 雪の奥の絵 4 行 →（雪の手前の絵 4 行）」。

## 6. 確かめ方

| 何を | どうやって |
|---|---|
| 部品の出方 | `BPOC_DEBUG_COLORS=1 blender ... render.py -- <シート>` → `work/debug/` のセルを見る |
| 全方位の表示 | `bash ingame/full_check.sh`（`ingame/full.nut` のレイアウト。way ごとに 5 か所を並べる） |
| 複線・行き止まりの並び・高架・橋・トンネル | `ingame/wall.nut`・`elev.nut`・`bridge.nut`・`tunnel.nut` |
| 雪 | `flat_snow.sve` で起動して同じ見本を流す |
| 本体が変わっていないこと | 描き直して前のシートと全画素を比べる |
| アイコンだけ直したとき | `blender/icons_only.py`（絵のセルを描き直さない） |
| 車両との重なり | 手で編成を走らせる（スクリプトの `change_schedule` は通らない。`docs/records/2026-11-13_otrp-script-change-schedule.md`） |

## 7. つまずきやすい所

- モジュールの直下のループ変数や、関数の中の変数に、既にある関数・変数と同じ名前を使わない（`_side`・`half` を上書きして形が崩れた）
- 厚みが 0 になる形は、切り抜き（Boolean）で形ごと消える。地面に切り上げるときは上面を少し上で止める
- 「タイルの境にある面」を探すときは符号を見る（両端が境にある側面まで消した）
- 見本のスクリプトで坂の向きを逆に指定すると、橋が架からない（絵の問題ではない）
- ゲームを名前でまとめて終了させない（ユーザーが開いているゲームも閉じる）。自分が起動したビルドだけを閉じる
- `flat.sve` はユーザーが保存し直していることがある。見本を敷く場所が空いているかを確かめる（「Tile not empty」）
- シェルの heredoc で `\\n` を含む文字列を書くと改行が壊れることがある。スクリプトのファイルは Write・Edit で書く
