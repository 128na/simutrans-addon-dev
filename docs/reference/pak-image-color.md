# pak の画像の色と透過（カラーキーとアルファ）

アドオンの PNG を makeobj で pak にすると、色は減らされ、透過の指定は 2 通り（カラーキーとアルファ）で読まれる。
どちらで作るかで、縁の滑らかさと色の正確さが入れ替わる。ここには、本体と makeobj のコード・pak の読み戻し・ゲームで確かめた決まりをまとめる。

- 調べた経緯と測った値の全体は [2026-11-22_alpha-png-color-check.md](../records/2026-11-22_alpha-png-color-check.md) にある（#191）。作業の手順は書かない
- 「本体」は `../simutrans`（OTRP の fork、`OTRP-KUTAv6`）。makeobj は `PATH` のもの（60.12 と名乗る）。ゲームは `addon_check` の OTRP v64.3（16 ビットの画面）。測った値は 2026-11-22
- アルファ（A）は PNG の値（0 = 透明、255 = 不透明）で書く

## 1. 2 つの透過の方式

| 方式 | 作り | 縁 | 色 |
|---|---|---|---|
| カラーキー（従来） | 透明にしたい所を #E7FFFF で塗る。PNG は RGB でよい | 画素ごとに「描く／描かない」の 2 値。縁を背景と混ぜられない（アンチエイリアスが効かない） | 各 5 ビット（RGB555、32768 色） |
| アルファ | PNG のアルファで透明度を付ける | 縁を半透明にして、下にあるものと混ぜられる | 半透明の画素は赤 3・緑 4・青 3 ビット（RGB343、1024 色）に落ちる（2 章） |

- カラーキーの縁は、背景（下の地面や車両）が描くまで分からないので、絵の側で混ぜられない。縁を #E7FFFF と混ぜて保存すると、混ざった色の画素がそのまま描かれ、白っぽい水色の輪になる（ゲームで確かめた）。
  なので描画の道具の出力は、アルファの閾値で「透明（#E7FFFF）」か「不透明」に二分する。縁はぎざぎざになる。
  ISS の組み立て（`refs/iss/py/libs/imageManager.py` の `handleTransparent`）と、このリポジトリの `tools/blender/sheetlib/cells.py` の `finalize` は、どちらもアルファ 25 未満を #E7FFFF、それ以外を不透明にする
- アルファを読むのは、本家の trunk r7788（2016-04-20、当時の版は 120.1.4 の開発中）から。それより前の makeobj はアルファを捨てていた。OTRP の fork ではタグ v32 以降に入っている（本体の git の履歴）

## 2. makeobj が画素をどう符号にするか

pak の画素は 1 画素 16 ビット。どの符号になるかは、ファイルの形式ではなく画素ごとのアルファで決まる（本体の `descriptor/writer/image_writer.cc` の `pixrgb_to_pixval`・`is_transparent`、`io/raw_image_png.cc` の `read_png_data`。pak を作って読み戻して確かめた）。

| 画素 | 符号 | 戻したときの色 |
|---|---|---|
| 色が #E7FFFF | 透明（アルファによらない。RGBA の PNG でも透明） | — |
| A ≦ 7 | 透明 | — |
| A = 255 | RGB555（各色の下位 3 ビットを切り捨て） | 最大 (248, 248, 248) |
| A = 255 で特殊色（会社の色 16・夜に光る色など 31 色、`descriptor/image.cc` の `rgbtab`） | 特殊色の番号 | 会社の色・時刻で変わる |
| 8 ≦ A ≦ 254 | RGB343（赤・青は上位 3 ビット、緑は上位 4 ビット。残りは切り捨て）と透明度 31 段 | 最大 (224, 240, 224) |
| 8 ≦ A ≦ 254 で特殊色 | 特殊色の番号と透明度 31 段 | 会社の色は色が狂う（4 章） |

- RGB の PNG は、読み込みで A = 255 を足して RGBA として扱う。なので「A が 0 か 255 だけの RGBA の PNG」と「#E7FFFF で塗った RGB の PNG」は、同じ符号になる（読み戻して一致）。
  色が減るかどうかは、ファイルが RGBA かではなく、8 ≦ A ≦ 254 の画素があるかで決まる
- 半透明の画素は、16 ビットのうち透明度に 5 ビット分を使うので、色が 10 ビットに減る。色は切り捨てなので、明るくなることは無く、多くの色が暗くなる。赤・青は緑より粗い（8 段と 16 段）。
  白 (255,255,255) は (224,240,224) になり、暗く緑寄りに見える。暗い緑 (60,90,40) は (32,80,32) になる（不透明なら (56,88,40)）。(128,128,128) のように各段にちょうど乗る色は変わらない
- 透明度の段は `30 - (255 - A) / 8`（整数の割り算）に 1 を足した値の 32 分の 1。A = 254 で 31/32、200 で 25/32、128 で 16/32、8 で 1/32。
  半透明の画素はどれも下を 1/32 以上混ぜ、完全には覆わない（本体の `display/simgraph16.cc` の `colorpixcopy`）
- 地面の気候の境目・浜・雪で本体が使う「アルファの地図」（`boden/grund.cc` の `display_alpha`、pakset の地面の画像）は別の仕組みで、アドオンの PNG のアルファとは関係ない

## 3. ゲームでの見え方

同じ色や縁を作り分けた試しの建物を草の上に置き、等倍で撮った（値は記録の表）。

- **A = 254**: 見た目は不透明のつもりでも、白が (216,236,216)、灰 (128,128,128) が (120,128,120) になった。RGB343 への切り捨てと、下の草の 1/32 が足される
- **カラーキー**: RGB555 の切り捨て（各色 7 以下）のほかは、入力の色のまま描かれた
- **縁**: 閾値で二分した縁はぎざぎざ、#E7FFFF と混ぜた縁は水色の輪、アルファの縁は滑らか。アルファの縁は、縁の 2〜3 画素が RGB343 に落ちて本体より少し暗く、拡大すると暗い輪に見えた

## 4. 半透明の会社の色は色が狂う（本体の不具合）

会社の色（特殊色の 0〜15）を 8 ≦ A ≦ 254 で使うと、その会社の色ではなく別の色で描かれる。
画像を会社ごとに作り直すとき（`display/simgraph16.cc` の `recode_img_src_target_16`）に、会社の色（RGB565）を RGB343 へ詰め直す式の緑の桁が 1 つずれている（`(rgb565 >> 3) & 0x0078`。正しくは `>> 4`）。
灰 (144,144,144) の会社では (128,32,128) の紫になり、ゲームでも A = 128 の枠が紫寄りに混ざって描かれた。本家の 2016 年の導入時からある式で、本家の今の版で直っているかは確かめていない。

- 会社の色は不透明（A = 255）で使う。夜に光る色など、会社の色以外の特殊色は、この詰め直しを通らない

## 5. どちらで作るか

- **透ける必要の無い物**（車両・建物・way の大部分）: 全画素を A = 255 か透明（#E7FFFF または A ≦ 7）にする。RGB で書き出してカラーキーにするのが確実。
  縁のアンチエイリアスはあきらめ、描画の道具のアルファは閾値で二分する（1 章）
- **縁だけ滑らかにしたい物**: 縁の画素だけを半透明にする。本体の色は RGB555 のまま残り、RGB343 に落ちるのは縁の画素だけ。縁は少し暗くなる（3 章）
- **本当に透ける物**: アルファで作る。色は RGB343 なので、狙う色は赤・青を 32 の倍数、緑を 16 の倍数（最大 224・240）で選ぶと、pak での色が予想どおりになる。明るい色ほど切り捨ての差が目立つ。手本では次の物が半透明を使っている
  - pak128: 煙（`base/smokes/misc-engine_smoke-128.png`・`misc-smoke-128.png`）だけ（dat が引く PNG 2721 枚を数えた）
  - ISS: 出力の名前が `_kt.png` の絵（44 枚）だけ、閾値の処理をかけずにアルファを残す。それ以外の 204 枚は半透明の画素が無い。
    海中の磁気浮上式の管・道路の壁（A = 51 が多い）、歩道（A = 26 が多い）、路面に重ねる色（`util/road_misc/blue_kt.png` など、A = 153 が多い）、路面の標示（`util/road_misc/intersection_kt.png`）など
  - SIS: 高速道路の透明な防音壁（`road/Expressway/sidewall/SideWall_E03/` の `…_E03F_fi.png` など、A = 48）
- **A = 254 などの取りこぼしに注意する**: 描画の道具・縮小・画像の編集で「ほぼ不透明」の画素が残ると、気づかないまま RGB343 に落ちて暗くなる。
  SIS の路面（`road/Expressway/2lane/SIS_Expwy_Road_G_1-1lane_02S.png` など）には、255 以外のアルファが 254 だけの画素が 5168 あった（意図したものかは分からない）。
  書き出した PNG の 8 ≦ A ≦ 254 の画素を数えて、意図した所だけにあるか確かめる。このリポジトリの dat が引く PNG（242 枚）は、すべて RGB だった
