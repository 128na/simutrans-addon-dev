# 景観アドオンの知見（本来の用途と違うパーツの使い方と敷き方）

景観アドオンは、本体の way・way-object・停留所などを本来の用途と違う形で使い、本体に無い物（4 車線の交差点の標示、広い歩道、街路樹、箱積みの駅ビルなど）を表す。何を表したくてその種類を選んだかが分からないと、パーツの意味を読み違える。ここには、手本と配置例を読んで確かめた決まりをまとめる。

- 調べた経緯は [2026-11-22_cityscape-demo-analysis.md](../records/2026-11-22_cityscape-demo-analysis.md) にある。作業の手順は書かない
- 確かめた場所と日付を各項目に書く。「本体」は `../simutrans`（OTRP の fork）、「配置例」はユーザーが作った保存データ `cityscape_demo.sve` とその続き（景観アドオンを多く入れた検証用のフォルダ、OTRP v64.3）
- 「ユーザー確認」は、作者・利用者であるユーザーが読みを正しいと認めたもの（2026-11-22）。推測は「推測」と書く
- 方角は Simutrans の座標で書く（北 = y が小さい側、東 = x が大きい側）。画面では北が右上、東が右下で、「奥」は西・北、「手前」は東・南

## 1. 何をどの種類で作るか

| 表したい物 | 使う種類 | なぜその種類か | 確かめた場所 |
|---|---|---|---|
| 交差点・合流の路面の標示（停止線、右折車線、導流帯、スクランブル） | 道路に重ねる路面電車の軌道（`waytype=tram_track`） | 専用の道路は市道化で上書きされる。way-object は道路の形に従うので独立した絵にできない。標識は 1 つに入る絵が少なく、置ける場所も限られる。路面電車の軌道は道路に重ねられ、車の通行を妨げず、1 つに多くの絵を入れられる | ユーザーの説明（#173、2026-11-22） |
| 歩道（石畳・煉瓦） | 運河（`waytype=water`） | 道路とつながらず、市道化で上書きされず、車も入らない | 配置例の練習 2 の (48,9) 付近。理由は推測で、分析全体をユーザーが正しいと評価 |
| 道路の外側の縁を歩道で覆う | 道路に重ねる路面電車の軌道 | 道路と同じタイルに重ねても車の通行を妨げない | 同上 |
| 生け垣・中央分離帯・街灯・縁石 | 道路の way-object | 道に沿って引け、通行に影響しない | 同上 |
| 街路樹・柵 | 運河の way-object（運河の歩道に重ねる） | 同上 | 同上 |
| 箱積みの建物 | 運河の停留所（1 段目は地面の運河、2 段目より上は高架の運河の上） | [hakozumi.md](hakozumi.md) | 配置例の練習 2 の (59,9) 付近。ユーザー確認 |
| 地面の道路に重ねた路面電車の停留所 | 高架の道路（`system_type=1`）で、絵を地面の高さに描いたもの | 同じタイルに 2 枚目の道路を置ける。地面の道路は車が通れるまま残る（推測） | 配置例の練習 2 の (59,9) 付近（`Road_Tram_Track_embedded`） |
| 道路の下をくぐる暗渠・水路にかかる跳ね橋 | ISS の運河（`iss_wwg_0050`）と、運河との交差 | 水面をタイルの面より下に描いているので、道路の両側で運河を止めると道路の下へ続いて見え、交差の床の下に余裕ができる（5 章）。水運に使うことは基本的に想定しない（ユーザーの説明） | 配置例 `cityscape_demo.sve` の (53,24) 付近、2026-11-22 |
| 道路の案内標識・信号・路面の標示 | 標識（`obj=roadsign`） | 機能は持たせず、使っても一方通行くらいにとどめることが多い（ユーザーの説明）。左側通行の設定と、車両との描く順に注意が要る（6 章） | 検証用の地図 `flat_512`・`flat_512_left`、2026-11-22 |

## 2. 道路に重ねる路面電車の軌道

- dat の `waytype=tram_track` は、本体では track の `system_type` 7（路面電車）になる。路面電車は道路と同じタイルに重ねても交差（踏切）を作らない（本体の `boden/wege/weg.cc` の `needs_crossing`。ゲームで ISS・SIS のパーツの waytype 2・system_type 7 を読んだ、2026-11-22）。
- way の絵は、隣とつながっている向き（ribi）で選ばれる。行き止まり 4・直線 2・曲がり 4・T字 4・十字 1・孤立 1 の 16 通り。景観パーツの作者は、この 16 通りを「タイルの位置の番号」として使う。同じ向きで別の絵が要る位置は、名前の違う way に分ける（ISS の `2-1`／`2-2`、SIS の `F`／`B`）。
- 道路の上に描く絵の作りは 2 通り。
  - ISS: 標示だけを描く。下の道路（ISS の道路）の路面と線がそのまま見える。`draw_as_ding` は付けない。
  - SIS: 路面ごと描いた絵で下の道路を覆う（`draw_as_ding=1`）。下は `Road_050` などでよい。道路の無いタイルにだけ敷く部品（6 車線の真ん中の列の `SIS_L_MG3_01M`）は `draw_as_ding=0`。
  - `draw_as_ding` は、タイルからはみ出す絵が、周りのタイルの物とどちらが上に描かれるかを決める（下の 2.1）。ISS が 0、SIS が 1 にした理由は確かめていない。
- 地図を回すと、way のつながる向きが回って絵が選び直され、名前は変わらない（本体の `boden/wege/weg.cc` の `weg_t::rotate90`）。つながる向きで決まる位置（行き止まり・T字・曲がり）は回しても崩れない。直線の列ごとに名前を分ける部品（SIS の `F`・`B`）は、90°（回す向きで南北か東西の一方の道）か 180°（全部）回すと側が逆になる（コードで確かめた。ゲームで回してはいない）。AMI は、このため直線を左右対称の 1 本（`ami_mark_lane4`）にした（ADR 0012）。
- このため、地図を回しても崩れない部品には、つながる形ごとに使える役の数に上限がある（本体の `weg_t::rotate90` と、形ごとの向きの数から導いた。AMI の #188 で、4 方向に敷いて名前とつながる向きを確かめた。OTRP v64.3、2026-11-22）。
  - 行き止まり・曲がり・T字は、それぞれ 4 通りの向きが地図の 4 通りの回し方と 1 対 1 に対応する。1 本の way で、それぞれ 1 役（4 通りの向きが、同じ絵を回したもの）にしか使えない。同じ形を 2 役に使うと、回したときに別の役と同じ向きになる。
  - 直線は向きが 2 通りなので、180° 回しても同じ絵に見える左右対称（点対称）の絵だけを置ける。十字と孤立は、90° 回しても同じ絵だけ。
  - 片側だけに物がある区間を長く続けるには、隣の列と横につないで T字にする（AMI の分岐・合流の平行の区間）。
  - 裏返した形（例: 分岐と合流）は、回しても重ならないので、別の way に分ける。
- 道路の無いタイルにも敷ける。SIS は、6 車線の真ん中の列（右折車線）と、高速道路の本線とランプの間（導流帯の路面）に、道路なしで敷いている。その列には車が入らない（配置例、2026-11-22）。

### 2.1 `draw_as_ding` と描く順（本体のコード、2026-11-22）

- 画面は 2 段で描く（`display/simview.cc`）。1 段目で、すべてのタイルの地面と道を奥から順に描く（`grund_t::display_if_visible`）。2 段目で、タイルごとの物（建物・車両・標識・木など）を奥から順に描く（`planquadrat_t::display_obj`）。
- way の dat の `draw_as_ding=1` は、その way のあるタイルに `draw_as_obj` の印を立てる（`boden/grund.cc` の `calc_back_image`）。後ろのタイルを隠す高い坂・壁のタイルや、地下の表示で見える・見えないの境のタイルには、本体も自動でこの印を立てる。
- 印のあるタイルは、1 段目で地面と道を描かず、2 段目でそのタイルの物の直前に描く（`grund.cc` の `display_if_visible` の終わり、`simplan.cc` の `display_obj`）。
- このため、タイルからはみ出す道の絵は次のようになる。
  - 印なし（0）: 1 段目で描くので、手前のタイルの地面に上書きされ、どのタイルの物（奥のタイルの建物・車両も）の下になる。
  - 印あり（1）: 奥のタイルの物より後に描くので、奥へはみ出した部分が奥のタイルの物の上に出る。手前のタイルの地面より後に描くので（手前のタイルに印が無いとき）、手前へのはみ出しも残り、手前のタイルの物にだけ上書きされる。
- 印のあるタイルの道は、道がつながっている北・西の縁で切り抜いて描く（`grund.cc` の `clip_way_background`）。つながっている向きの奥のタイルへは、はみ出さない。
- 見た目の違いをゲームで比べてはいない。
- タイルの内に収まる絵なら、`draw_as_ding=0` のままでも、路面ごと描いた絵で同じタイルの道路の絵（線・雪）を覆える。同じタイルでは、路面軌道の way が道路の後に描かれる（AMI の路面表示 `ami_mark_*`。OTRP v64.3、2026-11-22、[2026-11-22_ami-marking-paving-and-scramble.md](../records/2026-11-22_ami-marking-paving-and-scramble.md)）。

## 3. 敷き方の決まり

スクリプト（`command_x.build_way` など）はゲームの道具を呼ぶ。確かめたのはスクリプトからで（OTRP v64.3、2026-11-22）、GUI の操作では確かめていない。

### 3.1 way

| 決まり | 確かめた場所 |
|---|---|
| 区間を敷くと、区間の両端は内向きの 1 方向だけつながる。横に並べて敷いた区間どうしはつながらない | 小さな試験、配置例の再現 |
| 区間を重ねて敷くと、つながる向きが足される | 同上 |
| 同じ waytype の way を 1 マスだけ敷き直すと、向きはそのままで名前だけ替わる。置き換えないのは、同じ way のとき、既存の way を残す設定のとき、既存の速い way を残す設定（`keep_existing_faster_ways`）で既存の方が速いときなど。練習では同じ速さの way どうしで置き換わった | 同上、本体の `bauer/wegbauer.cc` の `build_track`（`change_desc` の条件） |
| 道路の曲がりのタイル（2 方向の斜め）を 1 マスだけ別の道路で敷き直すと、置き換わらずに向き 0 の別の道路が 1 本足された。路面電車の軌道の曲がりは置き換わった。原因は未確認 | SIS の高速道路の再現。曲がりの道路は、はじめから目的の名前で区間として敷けば避けられた |
| 高架は `system_type=1` の way を敷けばよい。2 段目より上は高さの上げ（OTRP の way の高さの指定）で敷く。高架の高さは「既定の高さ（pak128 は 2）+ 高さの上げ」 | 練習 2 の再現、本体の `simtool.cc` の `get_way_height_clearance()+height_offset` |

### 3.2 標識・way-object・建物

| 決まり | 確かめた場所 |
|---|---|
| 一方通行の標識（`single_way=1`）と経路の選択の標識は、同じタイルにもう一度立てると反対を向く（2 回で戻る）。ほかの標識は向きが変わらない（本体の `simtool.cc` の `tool_build_roadsign_t`）。これらの標識は、建てた直後は道のつながる向きのうち北・東・南・西の順で最初の 1 方向を向く（同） | 練習 2 の (48,9) 付近の方面案内の標識（`iss_sr_direction_info_1`） |
| way-object を区間で引くと、両端は端の絵になる。区間で引いて元と画素まで一致した | 練習 2 の (48,9) 付近 |
| way の無いタイルに建てる付属の建物（`Hako128_Ent_A-1` など）は、その上に高架を敷く前に建てる。後からだと「Tile not empty」で建たない | 練習 2 |
| way の無いタイルの付属の建物は、向きを指定しないと元と違う向きで建った。元に合わせるには向きを指定する（練習 2 の入口は南。4 通り試して合わせた）。指定しないときの向きの決まり方は確かめていない | 練習 2 |

### 3.3 離れた建物を 1 つの停留所にまとめる

- 停留所の合併の道具は、離れた停留所を合わせられない。距離が `allow_merge_distant_halt`（検証用のフォルダの `simuconf.tab` で 2）以上だと「遠すぎる」になる（本体の `simtool.cc` の `tool_merge_stop_t::do_work`、2 マス離れた建物で確かめた）。
- よく使う手: 間のタイルに仮の停留所を建ててつなぎ、あとで取り除く。仮の停留所は隣の停留所に入る（隣のタイルなら高さが違っても探す。本体の `simtool.cc` の `suche_nahe_haltestelle`）。そのあと建てる建物も同じ停留所に入り、仮の停留所を取り除いても 1 つのまま残る。ユーザー確認。
- 練習 2 は路面電車の停留所を先に建て、元と同じ「停」の付く名前になった。名前の付き方が最初に建てた建物で決まるかは推測で、本体では確かめていない。

## 4. 手本ごとの作り

### 4.1 ISS の交差点・ロータリー（`../refs/iss/src/util/road_misc/`）

作者の図が `../refs/iss/docs/technique/intersection.png`・`round_about.png` にある（色が way の名前、線がつながり）。

- 交差点の dat（`intersection.dat`）が指す絵は、release の `../refs/iss/release/pak128/util/road_misc/intersection_kt.png`（256px のセル、オフセット -64,-96。タイルの菱形はセルの x 64〜192、y 160〜224）。src の `intersection.png` は同じ大きさだが絵が違うので、測るときは release の方を見る（2026-11-22）。

- 4 車線どうしの交差点（`iss_wsg_intersection2-1`・`2-2`）: 道路は ISS の道路 1 本 2 車線を 2 列並べた普通の格子。軌道は 4 本の L 字（腕の外端 → 中心の角 → 隣の腕の外端）と、腕の 2 マスを横につなぐ線。
  - 中心の 4 マスは曲がり。`2-1` は角の縁石だけ、`2-2` はスクランブルの横断歩道。`2-2` の横断歩道は、各タイルの対角線（交差点の中心の角から外の角）に沿う帯で、4 マスで X（画面では +）。帯の幅は約 3.4、長さは約 10.5（タイル 1 辺 10）で、タイルの中心に置く（intersection_kt.png の 8 行目を測った、2026-11-22）。
  - 腕の内側は T字で、停止線・横断歩道・矢印。腕の外側は行き止まりで、右折車線の始まりの導流帯。
  - 腕では、入ってくる側（左側通行で交差点へ向かう車線）に `2-1`、出ていく側に `2-2` を置く。導流帯は 2 つのタイルの境の上にあり、`2-1` と `2-2` の行き止まりの絵にまたがって描かれる。
- 2 車線どうし（`iss_wsg_intersection1`）: 中心が十字、腕が行き止まり。T字の絵は 4 車線と 2 車線の交差点用（作者の図の左下）。
- 4 車線 × 2 車線: 中心は 4 車線の 2 マスで、`intersection1` の T字。T字は 2 マス並んだ相方の側を閉じ、反対側の 2 つの角に縁石を描く（南北の 4 車線なら西 nsw・東 nse、東西なら北 new・南 sew）。4 車線の腕は 4 車線どうしと同じ 2 マス × 2 列（入ってくる側 `2-1`・出ていく側 `2-2`）で、中心とつなぐ。2 車線の腕は `intersection1` の行き止まり 1 マス。この決まりだけから両方の向きを敷き、絵がつながり、南北の版は作者の図と一致した（[2026-11-22_cityscape-rule-only-exam.md](../records/2026-11-22_cityscape-rule-only-exam.md)）。
- ロータリー 1・2（`iss_wsg_round_about1`・`2-1`・`2-2`）: 道路も軌道と同じ輪の形に敷き、車が実際に輪を回る。中心の島は向き 0（孤立）のタイル。2 は外の輪 4×4 と内の輪 2×2（島）。2 では、出口側（時計回りで先に来る列）が `2-1`、入口側と内の輪が `2-2`。

### 4.2 SIS の一般道の交差点（`../refs/sis/road/Local_Street/`）

SIS は CC BY-NC-SA 4.0 なので、画像と dat は AMI に入れない（[refs-index.md](refs-index.md)）。

- 4 車線どうし: 中心の 2×2 は閉じた輪（十字の部品 `SIS_L_MGx_01`）。腕は 3 マスで、外端 `S`（普通の路面）→ 中ほど T字（横につなぐ）→ 内側の行き止まり（停止線・横断歩道）。腕と中心はつながない。
  - 内側の行き止まりは、奥（西の列・北の行）が `B`、手前（東の列・南の行）が `F`。中ほどの T字は、北・東の腕が `F`、南・西の腕が `B`。
  - T字の絵は、2 つの列の境の中央の線が横にずれる所（交差点の手前で、上り・下りの車線の幅が変わる）。`F` の T字はずれが北・東の端に、`B` は南・西の端にある（`../refs/sis/road/Local_Street/2lane/` の画像の 7 行目）。ずれが交差点から遠い側の端に来るように選ぶので、北・東の腕が `F`、南・西の腕が `B` になる。
- 6 車線どうし: 道路は奥と手前の 2 列。真ん中の列は道路なしで軌道だけ（右折車線）。中心の 3×3 は全部つないだ網で、真ん中に標示。腕は 4 マスで、真ん中の列は 2 か所で両隣へつなぐ（T字の絵が車線のずれ）。つなぐ位置は、南北の腕で `B` 側が北寄り、東西の腕で `B` 側が東寄り。
  - 列の部品は、奥の列（西・北）が `B`、手前の列（東・南）が `F`。真ん中の列は、つなぐ 2 マスだけ、つなぐ相手の側の部品（`B` か `F`）を使い、T字の絵で中央の線のずれを描く。ほかのマスは路面だけの `M`。
  - つなぐ位置は左側通行で決まる。交差点へ入ってくる側の列は、内側の行き止まり（停止線）の 1 つ外のマスで、出ていく側の列はさらに 1 つ外のマスで、真ん中の列とつなぐ。入ってくる側は、北の腕で東の列（`F`）、南の腕で西の列（`B`）、東の腕で南の行（`F`）、西の腕で北の行（`B`）。このため、どの腕でも `B` 側が北寄り・東寄りになる（配置例の書き出し、2026-11-22）。
- 名前の決まり（`../refs/sis/standards/SIStandards.xlsx` の Road の表）: `SIS_L_MG3_01F` は、L が一般道、M が路面軌道で実装、G が地上、3 が片側 3 車線、01 が部品の番号、末尾が置く位置。置く位置は `F` が手前側、`B` が奥側、`S` が単独、`C` が中間、`BF` が手前・奥の兼用（分岐の部品など）、`T` が土台だけ（隙間埋め）。`M` は表に無い。

### 4.3 SIS の高速道路の分岐・合流（`../refs/sis/road/Expressway/`）

構造の読みは [2026-11-22_ami-expwy-marking-sis-analysis.md](../records/2026-11-22_ami-expwy-marking-sis-analysis.md) にもある。

- 本線 2 マス（`SIS_E_RG2_01S`）の両側に、1 車線のランプ（`SIS_E_RG1_01B`・`01F`）を斜めに曲げて敷く。分岐部の絵は軌道（`SIS_E_MG2-1t2_01BF`・`MG2t2-1_01BF`）。本線とランプの間は `SIS_E_MGnone_01S` で埋め、ランプの外は道路なしの軌道だけ。
- 2 車線が両側に 2 車線ずつ広がる形は、`SIS_E_MG2-2t2_01BF`・`MG2t2-2_01BF` と、横 1 列につないだ `MGnone`。
- AMI は、作りだけを参考にして、高速道路の分岐・合流を本線の列とランプの列の 2 本ずつの way で作った（`addons/ami/README.md` の「高速道路の分岐・合流の路面表示の作り」。#188）。SIS のランプは 1 車線の道路で、AMI はランプを 2 車線の高速道路のまま使う。

## 5. ISS の運河を景観に使う（`../refs/iss/src/way/water/canal.dat`）

ユーザーの説明（#173、2026-11-22）: 景観用途で水運に使うことは基本的に想定しない。水面を標準の運河より下に見せることで、道路の下をくぐる暗渠を表せる。跳ね橋などの構造物も、軌道の下に余裕を持たせて表せる。

- ISS の運河は、水面をタイルの面より下に描き、周りを壁で囲う。南北の直線の絵の真ん中の列で、上の縁（笠石）の下に壁が 13px あり、その下が水面（256px のセル、`../refs/iss/release/pak128/way/water/canal_kt.png` を測った、2026-11-22）。坂の絵は閘門。
- pak128 標準の運河（`canal_030`）は、水面が地面の高さで、縁を石が囲う。
- 暗渠: 運河を道路の手前で止め、道路の向こうからまた敷く（道路のタイルには運河を敷かない）。ISS の運河は、端の絵でも水面が低いまま道路の縁まで続くので、道路の下を水路がくぐって見える。標準の運河は、縁の石で囲まれた行き止まりに見える（配置例の (52,21)・(55,21) を並べて比べた）。
- 跳ね橋: 運河の上に道路・線路を交差させると、交差（`obj=crossing`）が置かれる。ISS の交差（`../refs/iss/src/crossing/water/crossing.dat`）は、開いた絵が地面の高さの床と欄干と橋脚、閉じた絵が両側の床を跳ね上げた跳ね橋。水面が低いので、床の下に空きが見える。
  - 交差の物は、2 つの way の速さに合うものが選ばれ、運河の見た目では選ばれない（本体の `dataobj/crossing_logic.cc` の `get_crossing`）。配置例では、ISS の運河と標準の運河のどちらの交差も同じ欄干と橋脚の絵になった。どの交差の物かはスクリプトで読めず、ISS の `iss_cwr_0050x0050` だと推測している。pak128 標準にも道路と運河の交差（`CrossingRoadWater`、道路 100・運河 25）がある。
- 配置例を同じ手順で敷き直し、書き出し（way・交差）の差分 0、画面も画素まで一致した（2026-11-22）。

## 6. 標識の位置と車両との重なり

ユーザーの説明（#173、2026-11-22）: 標識は、左側通行の設定の有無で表示の位置が変わる。SIS は左側通行が前提なので、既定の設定では正しい位置に来ない。置き方によっては車両の表示と重なったり下に来たりするので、車道わきの柱の標識、道路を覆う門型の標識、路面のペイントの標識で、それぞれ注意が要る。

### 6.1 本体の決まり（`../simutrans/obj/roadsign.cc` の `roadsign_t::calc_image`）

- 道路の標識の絵をずらし、車両の奥・手前を入れ替えるのは、左側通行の設定（`drive_left`）が入っていて、かつ標識の `offset_left` が 0 でないときだけ。左側用の絵を別に持つ標識（下の OTRP の項）は、`offset_left` によらずその絵に替わる。
- `offset_left` の値は pak の形式の版で決まる（`descriptor/reader/roadsign_reader.cc`）。
  - 版 4 以降: dat に書いた値。書かなければ 14（`descriptor/writer/roadsign_writer.cc`）。
  - 版 3 以前: 14 に固定。ただし経路の選択の標識とプレーヤー専用の標識は 0。
- 左側用の置き方では、絵を横に `2×offset_left`、縦に `offset_left` だけずらす（pak128 の画面では 2 倍になり、14 なら横 56px・縦 28px。`simconst.h` の `tile_raster_scale_x`）。あわせて、車両の奥に描くか手前に描くかも入れ替える。1 方向の絵ごとに次のとおり。

| 絵の向き | 左側用でない | 左側用 |
|---|---|---|
| 東 | 手前 | 奥 |
| 北 | 手前 | 奥 |
| 西 | 奥 | 手前 |
| 南 | 奥 | 手前 |

- 「手前」の絵は同じタイルの車両の後に、「奥」の絵は前に描かれる（`boden/grund.cc` の `display_obj_vh` の後に `display_obj_fg`）。両方向の標識（一方通行でないもの）は、2 つの向きの絵を同時に出すので、片方は必ず「手前」になる。
- OTRP は、標識に左側用の絵を別に持たせられる。左側通行のときはその絵に替わるが、手前・奥は上の表のまま。1 方向だけを向いている標識には手前の絵（`frontimage`）も持たせられ、そのときは上の表によらず、絵を奥、手前の絵を手前に描く。`no_foreground=1` はすべてを奥に描く。
- 同じ名前の標識が 2 つ読み込まれると、後から読んだ方が残る（`roadsign_t::register_desc`）。

### 6.2 ゲームで確かめたこと（2026-11-22、OTRP v64.3）

入っている pak の標識を読んだ値（pak ファイルの標識の節を直接読んだ）:

| 標識 | 入っている pak | 版 | `offset_left` |
|---|---|---|---|
| ISS（`iss_sr_*`） | `iss_road_sign.pak` | 6 | 0 |
| tku の路面の標示（`tku_style_road_z0sign_*`） | addons の `all.pak` | 5 | 0 |
| SIS（`SIS_E_RSgs_*`・`SIS_L_RSsg_*`） | addons の `all.pak` | 3 | 14 |
| pak128 標準（`Minimum100`・`RoadClosed`・`NoEntry`・`autobahn_*` など） | pakset の `infrastructure.road_signs.all.pak`（版 6、`RoadClosed`・`NoEntry`・`autobahn_*` は 0）と、addons の `all.pak`（版 3） | 3 が残る | 14（`choose_point` などの経路の選択は 0。版 3 は値を持たないので、読み込み側の決まりを当てた値） |

- 景観アドオンを多く入れた検証用のフォルダでは、addons の `all.pak` に pak128 標準の標識の古い形式の写しが入っていて、後から読まれる。このため、pakset では 0 の `RoadClosed` なども 14 として動く。標識の左のずれは、dat のソースではなく、入っている pak の版と値で決まる。
- 左側通行だけが違う 2 つの地図（`flat_512_left` と `flat_512`）に同じ手順で標識を建て、絵の範囲を比べた。`offset_left` が 14 の標識（SIS、pak128 の `Minimum100`・`RoadClosed`・`NoEntry`・`autobahn_classic_entrance`）は、横 56px・縦 28px 前後ずれた。0 の標識（ISS・tku・`choose_point`）は変わらなかった。上の表どおり。
- 左側通行なしでは、SIS の門型の標識（`SIS_E_RSgs_E01BF`）は道路の外の草地に立つか柱が車線の中に立ち、SIS の信号（`SIS_L_RSsg_E01S_f`・`_b`）の柱は道路の反対側に立った。配置例 `cityscape_demo.sve`（左側通行なし）の (63,24) の門型も、草地に立っている。SIS を使うときは左側通行の設定にする。
- 標識の形: ISS の `iss_sr_crosswalk`（横断歩道）・`iss_sr_min_speed_0050`（最低速度）と tku の 2 つは、路面に描く標示。ISS の `iss_sr_direction_info_1` は柱に付いた案内板。SIS の `SIS_E_RSgs_E01BF` は道路をまたぐ門型。
- 車両との重なり（南北の道路で、バスを停留所の満載待ちで標識の上に並ばせて撮った）:
  - 路面の標示（ISS の横断歩道・tku）は、北行き・南行き、左側通行のあり・なしのどれでも、上に止まったバスに重なって描かれた。ISS の横断歩道は両方向（`single_way=0`）で `offset_left` が 0 なので、北向きの絵がどちらの設定でも「手前」になる（上の表と合う。tku はソースが無く、設定を読んでいない）。路面の標示を車線の上に置くと、車両の上に出る。
  - SIS の門型（一方通行）は、左側通行ありで、1 回建てた（北向き）ものは「奥」になり、南行きのバスが門型の手前に描かれた。2 回建てた（南向き）ものは「手前」になり、北行きのバスの上に板が描かれた。向きによって、門型が車両の上に出るか下に隠れるかが変わる。
  - 車両自身も左側通行の設定で走る車線が変わるので、標識と車両の位置関係は設定ごとに確かめる。
  - 柱の標識も、手前になる絵は車両の上に描かれた。pak128 の `Minimum100`（両方向、`offset_left` 14）は、左側通行なしの北行きで表の円板が、ありの南行きで裏の円板と柱がバスの上に出た。ISS の案内板（`iss_sr_direction_info_1`、一方通行・`offset_left` 0、1 回建てて北向き）は、表では「手前」で、左側通行ありの南行きで柱がバスの上に出た。
  - 2 車線の道路を 2 本並べた 4 車線で、西の道路に建てた標識は、柱や裏の円板が 4 車線の真ん中（2 本の道路の境）に立った。
  - 東西の道路の重なりは撮っていない。
- 一方通行の標識を南北の道路に 1 回だけ建てると、北向きになり、北行きの車両が通れなかった（車庫から出なかった）。もう一度建てて南向きにすると通れた。景観に使うときも、車両の通る向きと標識の向きを合わせる。
