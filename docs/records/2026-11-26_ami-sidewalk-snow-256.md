# 調査ログ: 256 の雪の街の道路に出る灰色の三角（#339）

## 目的 / 発端

pak256 の進捗管理から、AMI の 256 版（ami-256-alpha.6）を入れた pak256 で、雪の気候の生活道路（`ami_road_local`）の角や分かれ目の近くに灰色の細い三角が出ると知らせがあった（pak256 #127 の画面。OTRP v64、`flat_512_left_v64` の (310,142) 付近）。128 でも出るか、#321・#333 の持ち分マスクの直しと関わるかを調べた。

## 分かったこと（事実）

### 出る所

- 三角が出るのは、歩道つきの道路（街が敷いた道路）だけ。同じ 256 のゲームで手で敷いた `ami_road_local` の雪の十字・T字・直線には出ない（#333 の後の main、3658e5c）。持ち分マスクの直しとは関わらない。
- 三角は、街の道路のタイルごとに、奥の縁から外へはみ出る。

### 原因

- 歩道つきの道路のタイルは、地面を地面の絵ではなく、pak の `Obj=misc` `Name=Sidewalk` の絵で描く（OTRP の `boden/boden.cc` の `boden_t::calc_image_internal`）。
  - 番号は `imageid = ground_desc_t::slopetable[坂]`（2 段の坂は `slopetable[坂 >> 1] + 12`）。
  - 雪（高さが雪線以上か、気候が雪）なら `imageid + 1` の絵を引く。坂で、高さが雪線の 1 段下なら `imageid + 2`（雪の境）を引く。その番号の絵が無いときだけ通常の絵を使う。
- `slopetable`（`descriptor/ground_desc.cc`）は、道路の乗る形を 3 の倍数に置く。平らは 0、1 段の坂（4・12・28・36）は 3・6・9・12、2 段の坂は 15・18・21・24。間の番号は道路の乗らない坂に当たる。
- pak128 の `Sidewalk`（`landscape/grounds/sidewalk.dat`）はこの 3 枚刻みで、`Image[3k]` が通常、`3k+1` が雪、`3k+2` が `-`。
- pak256 の `Sidewalk`（`objects/gui/sidewalk.dat`）は、15 通りの 1 段の坂を 0〜14 番に、2 段の坂を 15〜26 番に詰めて描いている。dat の注は「雪の絵は無い（本体は雪の絵が無いと通常の絵を使う）」。
- そのため、雪の平らな歩道つきのタイルは 1 番（隅が 1 つ上がった坂の絵）を引く。上がった隅が、平らに描かれた道路の外へはみ出て、灰色の三角に見える。

### 確かめたこと

- 環境: OTRP v64（`addon_check` の `sim-WinGDI64-OTRPv64.exe`）、`flat_512_left_v64`。地面は pak256 の main を `tools/build.py --no-ami` で組んだ物。AMI は main（3658e5c）の 256 の生活道路とバラストの線路だけを組んで入れた。pak256 の `tools/game.py` の `Game` で起動した。
- 雪の (300,140) に街を置き（`tool_add_city`。街の道路は pak256 の `city_road` の `ami_road_local`）、育てた街の道路を撮った。
  - pak256 の main のまま: 街の道路の各所に三角が出る。
  - pak256 の写しで `Image[1]` だけを平らの絵にした: 平らなタイルの三角が消えた。
  - pak256 の写しで `3k+1`・`3k+2` の番号を全部 `-` にした: 平らなタイルの三角が消えた。
- [前後の画面](../../addons/ami/docs/339_sidewalk_snow/city_road_snow.png)（左が pak256 の main、右が `-` にした写し。街の育ち方は回ごとに少し違う）。
- 128: AMI の 128 の雪の道路の見本（`ingame/road_sample.nut`、輪と十字・分岐の並び）には三角は出ない。128 の歩道つきのタイルの地面は pak128 の `Sidewalk`（平らの雪は雪の平らな絵）で描かれ、AMI の絵は使われない。

## 推測・未確認事項

- 坂の上の歩道つきの道路（1 段・2 段の坂、温帯と雪、雪線の 1 段下）は、ゲームで見ていない。街に坂の上へ道路を敷かせる手を作っていない。今の pak256 の並びでは、雪の坂は別の坂の絵（`imageid + 1`）を、雪線の 1 段下の坂は別の坂の絵（`imageid + 2`）を引くはず（コードの読みだけ）。
- `3k+1`・`3k+2` を `-` にすると、道路の乗らない坂の番号の絵が無くなる。歩道つきの道路はその坂に乗らないので使われないと見ている（未確認）。
- 128 で、歩道つきの `ami_road_local` は敷いていない（街が pak128 の `CityRoad_030` を敷いた）。

## 結果どうしたか

- AMI の絵と道具は変えない。pak256 側で直す（`Sidewalk` を本体の 3 枚刻みに並べ直し、坂の上で撮って確かめる）。
- この記録の PR で #339 を閉じる。
