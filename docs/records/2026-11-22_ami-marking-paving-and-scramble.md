## 37: スクランブルの横断歩道

手本: iss の `iss_wsg_intersection2-2` の曲がり（`../refs/iss/src/util/road_misc/intersection.dat` の `image[nw]=intersection_kt.8.0` など）。

- dat が指すのは release の `../refs/iss/release/pak128/util/road_misc/intersection_kt.png`（1024x2304。256px のセルが 4 列 × 9 行。オフセット -64,-96）。src の `intersection.png` は同じ大きさだが、絵が違う（曲がりのセルにも腕の横断歩道が描いてある）。今回は、タイルの菱形の位置（セルの x 64〜192、y 160〜224）を確かめてから、セルの中の帯の画素の範囲を測った。
- 8 行目（2-2 の曲がり）の nw のセルは、タイルの菱形の中心を通る縦の帯（画面で x 113〜142、y 168〜215）。ne のセルは横の帯（x 80〜174、y 184〜199）。どちらも、端に角の縁石の円弧がある。
- 画面の縦・横は、タイルの対角線に当たる。nw のタイルは、北西の角（外の角）から南東の角（交差点の中心）への対角線。帯は 4 タイルで X になる（画面では + に見える）。
- 寸法: 帯の幅は約 3.4、長さは約 10.5（タイル 1 辺 = 10）。帯はタイルの中心に置かれ、交差点の中心の角から約 1.8 あいている（2 本の帯が中心で重ならない）。

前と後:

- 前: 中心の 4 タイルの内の辺（交差点の中心線）に沿う幅 1.5 の帯。4 タイルで交差点の中心線に沿う + の形（画面では X に見える）。
- 後: 中心の 4 タイルの対角線に沿う幅 3.0 の帯（腕の横断歩道と同じ幅）。内の端は交差点の中心から 1.9、外の端はタイルの中心から 4.6（角の円弧の内）。4 タイルで X（画面では +）。縞は帯に直角で、幅 0.5・周期 1.0。

## 38: 路面ごと描く

### 確かめたこと

- `draw_as_ding`: [cityscape.md](../reference/cityscape.md) の 2.1 のとおり、違いが出るのはタイルからはみ出す絵の描く順だけ。表示の絵はタイルの内に収まるので 0 のままにした。ゲームで 0 と 1 を比べてはいない。
- 下の道路の雪（`tools/blender/sheetlib/road_parts.py` の `SNOW_LAYERS`）: 路側線の 0.9 内から外へ、まだらの雪 3 段（`slush0`〜`2`）、路側線の 0.35 外から積もった雪（`snowbank`）。車道の中は夏と同じ。
- 下の一般道路の十字は、交差点の中に線を引かない（開いた十字）。T字は、枝の口を点線で渡す（`sheetlib.py` の `mouth_dash`。太さ 0.3 で、口の端 ±3.37 まで）。

### 作り

- 表示に路面の板を足した（`marking.py` の `_Plan.pave`。材質は一般道路のアスファルト。`blender/render.py` の `MARKING_PAVING`）。板は白線より下。
- 覆う範囲は、外の路側線から 0.9 内より内（`MARKING_PAVE_IN` = 2.47。下の道路の `slush0` の始まり）。そこから外は、下の道路の絵（夏の路面・雪）をそのまま見せる。こうすると、雪の版を表示に描かなくても、覆う所と覆わない所の境が下の道路の雪の始まりに合う。
  - 4 車線の腕: 2 タイルを通して、外の路側線の 0.9 内まで（帯は全部）
  - 2 車線の腕: ±2.47
  - 中心: タイルの全面から、外の角の 2.47 より外の四角と、閉じた側（2 車線の T字路）の 2.47 より外の帯を除く
- 4 車線の直線は、直線の形からは相方の列がどちらの側か分からない。1 本のままだと、帯だけを覆うことができない。そこで、`lane4` を `lane4_b`（奥の列。南北の道は西、東西の道は北）と `lane4_f`（手前の列）に分けた（SIS の B・F と同じ）。
- `ami_road_general_blank` と `sheetlib.py` の `no_lines` を外した。表示が下の道路の中央線と内の路側線を覆い、覆わない所の線（外の路側線・角の円弧）は表示の線と同じ位置にある。そのため、下を一般道路のままにできた。blank はこの PR で足し、配っていないので、名前は消えない。

### Blender の出力を重ねて見たこと

表示のシートを一般道路のシートの同じ形のセル（夏・雪）に重ね、画素で見た（一時の置き場のスクリプト。残していない）。

- 路面の色: 下の道路の路面と見分けがつかなかった。表示の路面は走行跡を描かないが、浮いて見えなかった。
- 線の重なり: 外の路側線と角の円弧は、下の道路の線と 1 本に重なった。
- 2 車線の T字路の中心（`junction2_t` の T字を一般道路の T字に重ねた所）: 下の道路の口の点線の端が、覆わない角の四角に 1 画素ずつ白く出た。枝の側の角の内側に、2.47〜3.57 の小さな四角の路面を足して消した（`MARKING_TEE_MOUTH_COVER`）。降雪では、角の内の小さな四角が除雪された形になる。

### ゲームで見たこと

`ingame/marking_sample.nut` を `sample_parallel.sh`（`OTRPv64_3.exe`、`flat_512.sve` の写し、ポート 47210〜）で敷いて撮った。下の道路は全部 `ami_road_general`。

- `[check]` の返り値は ok（道路と表示の名前が期待どおり）。
- 温暖: どの区画も、白線と路面が途切れずにつながった。表示の路面と、下の道路の路肩の境は目立たない。
- 降雪: 4 車線の帯（直線の中央の帯と腕の右折車線）、交差点の中心のタイル、右折の矢印・導流帯は、除雪された路面で見える。雪は路肩と交差点の外の角だけに見え、ふつうの一般道路と同じ所に積もる。表示の区間とふつうの一般道路（X42 の 2 車線の腕の先）のつなぎ目も合った。
- スクランブル（X4S）: 横断歩道が中心の 4 タイルの対角線に沿い、画面では + に並んだ。外の端の縞は、降雪でも雪に埋もれなかった。

画面は `addons/ami/docs/marking187_<temperate|snow>_<区画>.png`（前の画面を上書きした）。

## 案からの逸れ

- `ami_road_general_blank` を外した（進捗管理の読みの「blank が要らなくなるかも検討」の結論。理由は上の「作り」）。
- `ami_mark_lane4` を `ami_mark_lane4_b`・`ami_mark_lane4_f` の 2 本に分けた（4 車線の直線の帯を覆うため。敷き方は列ごとに way を選ぶ）。

## 推測・未確認事項

- `draw_as_ding` の 0 と 1 を、ゲームで比べてはいない。
- 坂の `lane4_b`・`lane4_f`、車両との重なり、斜めの道路は、見本で確かめていない（前の作業と同じ）。
- 表示の路面は走行跡を描かない。今の画面では目立たないが、ズームを変えたときの見え方は確かめていない。
- 地図を回すと、way のつながる向きが回って絵が選び直され、名前は変わらない（本体の `boden/wege/weg.cc` の `weg_t::rotate90`）。そのため `lane4_b`・`lane4_f` は、90° 回すと東西の道の列で、180° 回すと全部の列で、路面で覆う側が逆になる。夏の絵は見分けがつかない（下の中央線はいつも覆い、帯の側の下の路側線は表示の路側線と同じ位置）。降雪では、帯に下の道路の雪が出て、外の路肩が除雪された見え方になる。腕と中心はつながる向きで絵が決まるので崩れない。本体のコードで確かめた。ゲームで回してはいない。
