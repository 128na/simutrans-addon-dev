# 作業ログ: 生活道路の雪のカーブで、隣の直線との境に地面が透けた（#378）

## 目的 / 発端

[#378](https://github.com/128na/simutrans-addon-dev/issues/378)。256 の町で、生活道路の地上の基盤の版（`ami_road_local_base_single`）の雪の絵で、カーブのタイルと隣の直線のタイルの境に、地面の色の点線が出た（pak256 の担当の画面）。#360（[PR #363](https://github.com/128na/simutrans-addon-dev/pull/363)）で雪の路面の板を内へ寄せて削るようにした後に出た。

## 分かったこと（事実）

- 生活道路のカーブは L 字（`MiterPath`。辺の中点 → 中心 → 辺の中点）。壁の外側を削る型（`assemble._beyond_prisms` の L 字の節）は、2 本の脚の柱をどちらも両端の先へ 30 延ばしている
- 角の内側の壁の柱は、中心を越えてもう一方の脚の上まで延び、壁の外の面（中心から `uw`）より外、つまりもう一方の脚のタイルの辺に沿った帯（壁の外の面 4.95 からタイルの辺 5 まで、幅 0.05）を削る。温帯の絵では帯は画素にならない
- 雪の絵では路面の板だけを `ROAD_SNOW_ASPHALT_RECESS`（0.1）内で削る（`uw` が 4.85）ので、帯の幅が 0.15 になり、路面の板がタイルの辺で欠けた。路肩の雪の板も 0.05 欠けた
- カーブのセルと隣の直線のセルを本体と同じ並びに重ねて透ける画素を数えると、雪の行で 256 は 85 画素（sw 22・nw 28・ne 21・se 14）、128 は 6 画素（sw 3・se 3）。温帯の行は、タイルの菱形の頂点の近くを除いて 0
- 高架（`ami_road_local_elev_single`）の躯体も同じ型で削っていて、辺の側面が帯の分だけ削れた形が今の絵になっている。柱を全部の版で止めると、高架のセルが変わった（差が 40 を超える画素が 4051）

## 推測・未確認事項

- 256 の pak をゲームに入れては見ていない（シートをつないで数え、拡大して見ただけ）。ゲームの見た目は pak256 の担当とユーザーが見る
- 温帯の行の幅 0.05 の帯は残した（画素にならず、高架と同じ形を保つため）

## 結果どうしたか

- `_beyond_prisms` に `ell_inner_stop` を足し、真なら L 字の角の内側の柱を、もう一方の脚の壁の外の面（中心から `uw`）で止める。`sheetlib._road_sheet` は雪の絵（`snow_recess` の行）だけ、壁の外側の型（`beyond`）と路面の板の型（`inner`）の両方で止める
  - 最初は路面の板の型（`inner`）だけを止めたが、路肩の雪の板が帯の分だけ欠けたまま路面の板が辺まで残り、板の切り口がタイルの下の端に出て `check_snow_edge.py`（#360 の検査）が落ちた。両方を止めて通った（同じ箇所の修正 3 回: 全部の版で止める → 路面の板だけ → 雪の行の両方）
- 変わったのは `ami_road_local_base_single` の雪のカーブ 4 セル（行 6・列 5〜8）だけ。128 の生活道路のほかのシート（通常・橋・高架・トンネル・壁の L 字）は描き直して変わらないことを確かめた
- 検査 `addons/ami/check_curve_join.py` を足し、`check.sh` で 128 と 256 に流す。直した後は 128（季節 48 組）・256（6 組）とも 0（頂点の近くを除く）
