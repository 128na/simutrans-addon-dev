# 作業ログ: AMI に弾性まくらぎ直結軌道（ami_rail_concrete）を足す（#62）

（2026-11-21）

## 目的 / 発端

バリエーションのロードマップ（#61）の第 1 弾の最初の 1 件。iss の `iss_wtg_0240_*`（コンクリートまくらぎ、240 km/h）に当たる線路を、在来線（`ami_rail_ballast`）の部品の使い回しで足す。

## 分かったこと（事実）

- iss は線路の種類をまくらぎの材料で分けている。木（`track_wood.dat`、120 km/h）は褐色の道床と暗いまくらぎ、コンクリート（`track_concrete.dat`、240 km/h）は明るい灰色の道床と白いまくらぎ（`../refs/iss/release/pak128/way/rail/standard_*_g_center.png` の直線のセルを 4 倍で見た）。
- AMI の在来線は、精細化（#56）のラウンド 4 で、すでに明るい PC（コンクリート）まくらぎに描いてある（`render.py` の `SLEEPER_RGB`）。そのため、iss の分け方（まくらぎの色）では見分けられない。
- この前提を進捗管理経由でユーザーに上げた。答え（2026-11-21）は次のとおり。見分け方は、ユーザーの案の「弾性まくらぎ直結軌道」（道床をコンクリートにして路面で見分ける）。ラダー軌道は候補（「面白いかも」）。名前と値は案のとおりで `ami_rail_concrete`・240 km/h・30000・600・1960 年。版は在来線と同じ一式。文書は、README の表に 1 行足し、ADR 0006 を新しく書く。
- 鉄道総研の構造力学研究室のページ（`https://www.rtri.or.jp/rd/division/rd50/rd5040/`）には、ラダー軌道とフローティング・ラダー軌道の説明があり、弾性まくらぎ直結軌道の説明は見つからなかった。層の重ね方は一般的な構造（コンクリートの道床に、ゴムの靴をはいた PC まくらぎを埋める）から決めた。
- まくらぎの靴（まくらぎを囲む暗い縁）を一度描いたが、縁の幅は画面で 0.4px ほどで見えなかった。0.12 単位（約 0.9px）まで広げても、まくらぎの間が暗くなるだけで靴には見えず、くどさの値も在来線とほぼ同じだったので、部品ごと外した（以下の値は外した後のもの）。
- 何も変えずに在来線とスラブを描き直すと、シートは元と同じになった（描画は再現する）。新しい種類を足した後も、在来線とスラブのシート（通常の版・基盤 4 版・トンネル）は変わらなかった（`git status` で差分なし）。
- `sheet_audit.py --compare ami_rail_ballast ami_rail_concrete`: 基盤・高架・橋・トンネルの全セルで、塗りの範囲が在来線と同じ。検査の候補 112 件は、どれも既存の壁・架線のシート。
- 見本（`TRACK=ami_rail_concrete BASE_PORT=47310 bash ingame/sample_parallel.sh`、208 画面）と、在来線の同じ見本の「地面でない画素」の範囲を、画面ごとに比べた。新しい線路の方で欠けた画素は、温暖側の全画面で 0。新しい線路だけが塗る画素は、温暖側で 1 画面あたり最大 1138 個。拡大すると、道床の奥の縁に沿った 1px の線だった（在来線は斜面の裾の画素が地面の色に混ざる）。降雪側は最大 4857 個で、道床の縁の垂直の面が灰色に出る分。降雪側では在来線だけが塗る画素も最大 530 個あり（坂の区画 `DE` とその基盤・高架の版）、拡大すると坂のタイルの手前の縁に沿った線だった。在来線は斜面の裾が雪より少し暗く出るが、新しい線路は縁が垂直なので裾が無く、そこは地面の雪になる（すき間ではない）。
- くどさ（`calib_capture.sh`・`busy_measure.py`、`flat_512.sve`、等倍、線を除く）:

  | 気候 | 名前 | 細かさ | 孤立点/千 |
  |---|---|---|---|
  | 温暖 | 在来線 | 0.0720 | 21.51 |
  | 温暖 | 弾性まくらぎ直結軌道 | 0.0638 | 18.85 |
  | 温暖 | 高速線 | 0.0594 | 30.43 |
  | 温暖 | pak128 `Rail_160_Tracks` | 0.0608 | 58.13 |
  | 降雪 | 在来線 | 0.0234 | 5.37 |
  | 降雪 | 弾性まくらぎ直結軌道 | 0.0188 | 4.85 |
  | 降雪 | 高速線 | 0.0355 | 2.72 |

  温暖は物差し（`way-addon.md` の 11 章）の「許容」（細かさ 0.058〜0.078・孤立点 5.9〜32）。雪は物差しの境を使わない決まりで、在来線より少し無地に寄った。
- 継ぎ目と坂の判定: AMI には判定用の見本が無かったので、blender-poc の `seam.nut`・`steep.nut` と同じ並びの見本 `addons/ami/ingame/seam_slope.nut` と、撮って測る `ingame/seam_slope_check.sh` を足し、在来線・弾性まくらぎ直結軌道・高速線を同じ見本で測った（`PORT=47300`、`flat_512.sve`）。
  - つなぎ目（pak128 `Rail_160_Tracks` との東西・南北・斜め・坂）: 3 種とも東西・南北・坂は OK、斜めは NG（継ぎ目の草が在来線と新しい線路で 1px、高速線で 3px。同じ画素 (365,375)）。中心のずれは新しい線路で最大 -1.0px（在来線 -0.5px、許容 1.0px）。
  - 坂の寄り（十字の坂 4 タイル。平地との差の許容は ±0.5px）: 急坂は在来線・新しい線路とも 1 合格・3 不合格、1 段の坂は 2 合格・2 不合格（高速線は 2・2 と 4・0）。不合格のタイルは 2 種で同じ（急坂の坂 72・24・8、1 段の坂の坂 12・4）。差は坂 24・8・12・4 で在来線 -0.55〜-0.59px、新しい線路 -0.54〜-0.57px とほぼ同じ。坂 72 だけ、在来線 -1.00px に対して新しい線路 -1.50px と大きい（平地の道床の中心が、奥の縁の 1px の分だけ在来線より 0.5px ずれるため）。平地のタイルの寄りも、新しい線路 +1.73〜+1.76px に対して在来線 +1.22〜+1.26px（同じ原因）。つなぎ目の中心のずれ -1.0px も許容ちょうどで、在来線より 0.5px 大きい。
  - 靴を描いていたときは、新しい線路の坂 24・8・12・4 の差が -0.71〜-0.74px で在来線より大きかった。靴を外して在来線並みに戻った。
- 確認画像（ユーザーがゲームで見る場所）: `addons/ami/docs/rail_concrete_cmp_<気候>_<区画>.png`。同じ見本の同じ区画を、在来線・新しい線路・高速線の順に並べた（`sample_parallel.sh` で 3 種を撮った 208 画面ずつから）。
- 検証のスクリプトの癖: `sample_parallel.sh`・`calib_capture.sh` の `MCP_CLIENT` の既定（`../../../simutrans/...`）は、worktree（`.claude/worktrees/<名前>/`）からは届かない。`MCP_CLIENT` に絶対パスを渡して動かした。`sample_parallel.sh` の `BASE_PORT` の既定は 47140 で、割り当ての範囲（47300〜47319）の外なので、毎回渡した。
- `calib_capture.sh` の既定の並びに含まれる `iss_wtg_0240_single` は、`addon_check` に iss の pak が無く、敷けなかった（`Call function failed` で、それより後の降雪側が空になった）。iss を外して撮り直した。

## 推測・未確認事項

- 雪の絵の見た目、温暖の道床の色の加減は、ユーザーがゲームで確かめる。
- 本物の弾性まくらぎ直結軌道は、中央に排水溝があるものや、2 ブロックのまくらぎのものもある。画面で 1px ほどの差になり、くどさが増すので、今回は描いていない。

## 結果どうしたか

- `blender/catalog.py` に `RAIL_CONCRETE` を、`blender/render.py` に「弾性まくらぎ直結軌道」の設定（道床の断面 `_CONC_SECTION`、色 `CONC_BED_RGB`）を、`blender/ami_dat.py` に値を足した。
- 判断の理由は [ADR 0006](../adr/0006-ami-track-variants-by-track-form.md)。作りは `addons/ami/README.md` の「弾性まくらぎ直結軌道の作り」。
- 確認画像は `addons/ami/docs/rail_concrete_cmp_*.png`（左から在来線・弾性まくらぎ直結軌道・高速線。下は黄色の枠の中の 4 倍）。
- 継ぎ目と坂の見本と測り方（`ingame/seam_slope.nut`・`seam_slope_check.sh`）を足した。

## 道床の縁を在来線と同じ所で止めた（同じ日、ユーザーの決定）

上の値は、道床の上面を ±1.75 まで延ばしてほぼ垂直の縁にした版のもの。奥の縁が在来線より 1px 外まで塗られ、坂の寄りとつなぎ目の中心のずれが在来線より 0.5px 大きかったのを PR #66 に書き、ユーザーが「在来線と同じ所で止める」と決めた。

- シートの塗りの範囲（不透明の画素）を在来線と比べると、上面の半幅 1.55・1.6・1.65 でも、在来線より外の画素が 1300〜1600 個残った（通常の版のシート）。在来線の肩と同じ 1.45 で 0 になったので、`CONC_BED_HALF = BALLAST_SHOULDER` にした。道床の形は在来線と同じで、違いは色と肌（砕石のまだらか、コンクリートの細かいまだらか）だけになる。通常・基盤・高架・橋・トンネルの全版で、塗りの範囲が在来線と同じ（`a_only=0 b_only=0`）。
- 見本の 208 画面の範囲の比べ: 違いが出たのは区画 `BT_B1`（橋）だけで、在来線の画面が #64 の前に撮ったものだったため（温暖 0・41 画素、降雪 12・41 画素）。前に降雪の坂で出た 530 画素の差は消えた。
- つなぎ目: 新しい線路の中心のずれ・継ぎ目の草は、全か所で在来線と同じ値（斜めの草 1px で NG も同じ）。
- 坂の寄り（平地との差）: 急坂は坂 72 が -1.00px、24・8 が -0.56・-0.58px で、在来線（-1.00・-0.56・-0.59px）とそろった。1 段の坂は坂 12・4 が -0.54px（在来線 -0.55px）。合格の数も在来線と同じ（急坂 1・1 段の坂 2）。平地の寄りは +1.22〜+1.26px で在来線と同じ。
- くどさ（線を除く）: 温暖 細かさ 0.0646・孤立点 19.70/千（許容の範囲）。降雪は 0.0234・5.37 で在来線と同じ（雪の絵は道床の形と雪の色で決まり、形が在来線と同じになったため）。way の画素数も温暖・降雪とも在来線と同じ。
