# 作業ログ: 精細化のラウンド 1（在来線一式、#56）

（2026-11-20）

## 目的 / 発端

#56 の流れ（直す → 精細化と省略の釣り合い → 前のラウンドと比べる）を在来線一式で 1 周回し、流れが成り立つかを確かめる。くどさの物差しは前の記録（`2026-11-20_ami-busyness-calibration.md`）で合わせたもの。

## やったこと

- ラウンドの版の作り方を足した（`addons/ami/blender/round.py`）。在来線一式（通常・基盤 4 版・高架 4 版・橋・トンネル・壁と架線つきの壁・橋脚 2 種の 23 個）を、名前の末尾に `_round<n>` を付けて `rounds/ami_round<n>.pak` にする。ラウンド 0 は今の `src/` をそのまま付け替えたもの
- 見本（`ingame/sample.nut`）に `SUFFIX` を足し、`ami_` で始まる名前にだけ付ける（pak128 の道路などには付けない）。橋とトンネルの名前にも付ける
- `ingame/sample_parallel.sh` に `SUFFIX` と `EXTRA_PAKS` を足した。その途中で、`TRACK` を渡さないと後ろの置き換えが飛ばされる不具合を見つけて直した（置き換えが無いときに `sed -e b` を渡していて、`b` が残りの置き換えを飛ばした）
- ラウンド 0 と 1 の見本を 208 画面ずつ撮り（`OTRPv64_3.exe`、`flat_512.sve`、8 台で約 40 秒）、くどさの見本に 2 つと手本を並べて測った

## 1. 直す所

- #44 の在来線の候補 2 件を見た
  - 4 件目（橋の端の坂で線路が途切れて見える）: 欠陥ではない。奥（北・西）へ下る坂は、画面で上下に縮んで細い帯に見える（壁なしの橋で確かめた）。壁を重ねると、両側の壁がその帯を隠す。手前の端の坂は普通に見える
  - 7 件目（高架の行き止まりの端の下の薄い板）: 床の板が端の壁の外へ 1px ほど出て見える。欠陥か作りどおりかは決めていない（ユーザーに報告する）
- ほかの区画を目で全部読むことはしなかった。#43 で、画面を読むエージェントの指摘は確度が低かったため。代わりに、ラウンドで新しい欠けやはみ出しが入っていないことを、シートの輪郭（透過の範囲）の差で確かめた

## 2. 精細化

- 描き込みを、物差しで「ちょうどよい」とした段 3 と同じにした（`round.py` の `ROUND_SETTINGS[1]`: 砕石のまだらの明暗差 2.4 倍・細かさ 12、汚れの色 1.8 倍、まくらぎの間隔 0.54）。在来線の道床を使う描き分けだけを替え、高速線・路面軌道は替えていない
- 現実の部品を足すこと（部品の一覧を作り、描いたか省いたかを付ける）は、このラウンドではしていない

## 3. 評価（ラウンド 0 → 1）

| 観点 | 結果 |
|---|---|
| ① 欠陥 | 変わったシート 21 枚のどれも、輪郭の差は 0 px。ゲーム画面でも、差は線路の画素だけに出て、草や周りには出ていない（208 画面）。新しい欠陥は無い |
| ② 写実 | 変えていない（部品は同じ） |
| ③ くどさ | 温暖: 細かさ 0.0553 → 0.0771、孤立点 5.37 → 27.41。「物足りない」から「許容」に入った（良くなった）。雪: 0.0675 → 0.0694、16.80 → 21.54（雪は物差しを合わせていない） |
| ④ そろい | 在来線の way・基盤・高架・橋・トンネルは同じ値でそろった。高速線（スラブ）・路面軌道は前のまま |

- 壁・架線つきの壁のシートで変わったのは、アイコンのセル（道床を描いている）だけだった（224 px）。橋脚は変わっていない

## 流れについて分かったこと

- 回せた: 名前の付け替え、ラウンドの pak、見本の撮影、ラウンドの間の差、くどさの数値は、人の手を待たずに回った
- ①は、輪郭の差と画面の差で「増えていない」ことは言えるが、前からある欠陥を新しく見つける手段が弱い
- ②は、部品の一覧と手本（写真や資料）が無いと進められない
- ラウンドの pak は 1 つ約 6.5MB（在来線一式）
