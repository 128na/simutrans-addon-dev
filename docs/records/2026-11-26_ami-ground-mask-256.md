# 作業ログ: 256 の持ち分マスクを拡大せず直接作る（#321）

## 目的 / 発端

pak256 のテストプレイで、AMI の 256 の道路の直線の奥の縁が、横 2px・縦 1px の段でなく、横 4px・縦 2px の階段に見えた（pak256#111）。pak256 の調べで、原因は `tools/blender/sheetlib/cells.py` の `_ground_mask` が、256 の持ち分マスクを pak128 の大きさで作って最近傍で 2 倍にしていること（#266 の作り）と分かった。#266 のときの 256 の地面は pak128 を 2 倍にした `pak256poc`（縁の段が 4×2）だったが、今の pak256 の地面（`objects/ground`）は 2×1 の段で描き直してあり、前提が変わった。道路はタイル全面を塗るので、縁がそのままマスクの形になる。

## 分かったこと（事実）

- pak256 の地面の形は、`objects/ground/temperate/draw_ground.py` の `column_span`: 列 x ごとに列の中心（x + 0.5）で上の辺（左→上→右の角）と下の辺（左→下→右の角）を引き、行 y を `上 <= y < 下` で塗る。256 四方のマスで、平らな菱形の左の角は (0, 192)、上の角は (128, 128)。
- 同じ決まりでマスクを道のセル（512 四方）に直接作ると、平らと坂の 65 形（四隅の高さ 0〜2、最低 0）すべてで、地面のマスをセルの (128, 62 + `GROUND_PHASE`) に置いた形（マスクの角の行 `GROUND_CY + GROUND_PHASE` = 254 + `GROUND_PHASE` から、地面のマスの左の角の行 192 を引いた値）と画素で一致した（bpy を差し替えて `cells` を読み、`draw_ground.column_span` と比べた）。平らのマスクを格子に並べると、隙間も重なりも 0。`side`（上下・左右の半分）は重ならず、合わせると全体になる。
- 今までの 4 隅の凸多角形の内外（画素の中心）の判定のままだと、凸でない坂（3 つの角が上がった形など）で欠ける（pak256 の作業者の模擬で 15 形）。
- pak128 のマスク（`GROUND_CY = 127`、画素の中心で判定）は、pak128 の地面（`refs/pak128` の `texture-lightmap.png` の平ら）とも画素では一致しない。差の少ない置き方は (64, 30) と (64, 31) で同点（128 画素ずつ）。マスクの行の数が偶数、地面が奇数で、半行ずれている。拡大したマスクと pak256 の地面も、(128, 61) と (128, 62) で同点（256 画素）。
- 縦の位置は紙の上では決められないので、ゲームで比べた（OTRP v64、pak256 の main を `--no-ami` で組んだ地面、`flat_512_left_v64` の (40, 40) 付近）。生活道路と線路（バラスト）を、東西と南北に 1 段・2 段の台を越えて敷き、等倍で撮った。
  - `GROUND_PHASE = 1`（地面を (128, 63) に置いた形）: 平らな道路のタイルの継ぎ目に、1 画素の草の線がタイルごとに出た。
  - `GROUND_PHASE = 0`（(128, 62)）: 平らな継ぎ目は出ない。坂の継ぎ目の縁に 1 画素の草の欠けが出た。
  - `GROUND_PHASE = -1`（(128, 61)）: どちらも出ない。
- 1 段・2 段の坂の継ぎ目と平らな継ぎ目は、`-1` で目視して草が見えなかった。画面の中で灰色に挟まれた細い草を数える道具（作業者の手元の物）では、`-1` で 10 か所ほど当たったが、拡大すると縁の角で、継ぎ目の草ではなかった。
## 推測・未確認事項

- `-1` が合うのは、pak128 のマスクが地面の約 1.5 行上（(64, 30) と (64, 31) の間）にあるのを 2 倍にした位置（61）だからと見ている。本体が地面と道をどの行に描くかをコードで追ってはいない。
- 確かめたのは生活道路と線路（バラスト）の平らと単坂・急坂。運河・歩道・踏切の踏板・高架の `lower`・橋の端の `solid`・斜めの `side` は、新旧のマスクの差が縁から 3 画素以内であること（bpy なしの比べ）までで、256 の絵は描いておらず、ゲームでも見ていない。
- 雪の気候・地中海などほかの気候の地面は見ていない（地面の形は気候によらず同じ `column_span`）。

## 結果どうしたか

- `cells._ground_mask` の 256 以上の大きさを、拡大をやめて `_ground_mask_direct`（列ごとの判定 `_column_mask`）で作るようにした。広げ方（`spill`・道路の半行・坂の地面の位置・`solid`・`lower`）は pak128 と同じ意味で、pak128 の半行を `SCALE // 2` 画素にした。`lower` は 2 倍に切り上げずに、渡された画素のまま使う。
- 縦の位置は `GROUND_PHASE = -1`。
- pak128 の道（`_ground_mask_1x`）は変えていない（全シートを変更前のコードで描いた絵とバイトで比べた。PR に書く）。
- PR は #321 の PR。pak256 は `vendor/ami/build.env` の `AMI_COMMIT` を上げて組み直す（pak256#111）。
