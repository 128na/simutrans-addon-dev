# SIS の高速道路の合流・分岐パーツの分析（#167）

対象: `refs/sis/road/Expressway/` の `2to2-1`・`2to2-1R`・`2to2-2`・`3to3-1`。画像は `SIS_Expwy_Tram_G_*.png`（256 画素のセルを 5 列 × 8 行）。SIS は CC BY-NC-SA 4.0 なので、画像・dat は AMI に入れない。ここに書くのは構造の読みだけ。

## 作り（dat）

- どれも `obj=way`、`waytype=tram_track`、`system_type=0`、`draw_as_ding=1`。道路のタイルに路面軌道として重なり、物として描かれる（道路は残る）。AMI の #156（交差点の路面表示、ADR 0011）と同じ作り。
- 各パーツは向きごとに 2 本（例: `2to2-1` と `2-1to2`）。`2to2-1R` は左右を反転した版。
- セルの割り当て: `.1.x` = 端 W/N/E/S、`.2.x` = 斜め、`.3.0/.3.1` = EW/NS の直線、`.3.2` = 孤立、`.3.3` = 十字、`.4.x`・`.5.x` = 坂、`.6.x` = 端の NE/SE/NW/SW、`.7.x` = T字 NSE/NSW/SEW/NEW。

## 画素で読んだこと（2to2-1。暗い背景に重ね、5 倍で拡大して読んだ）

- 直線のセル（`.3.0`・`.3.1`）の路面の面積は、孤立のセル（`.3.2`、全面 4096 画素）の約 46%（暗い画素 1554 + 白い画素 220〜338）。つまり半幅の帯で、内側の縁に点線、外側の縁に側壁と実線。SIS では 1 車線が半タイル、2 車線が 1 タイル。
- 十字のセル（`.3.3`）は全面の約 89% で、向かい合う 2 辺のそれぞれ別の側にゼブラ。
- T字のセル（`.7.x`）は全面の路面で、中央線は破線（2 本）、片側の縁は実線＋側壁、反対側の縁は点線で、その側のタイルの端にゼブラ（斜線の梯子形）。ゼブラは同じタイルの片端に付く。
- 端のセル（`.6.x`）は、狭い側の端では路面が側壁（曲がる縁石）に寄り、広い側の端に向けて中央線が曲がって車線が横へずれ、広がった側の縁にゼブラの斜線（扇形）が付く。路面の面積は全面の約 28〜30%。
- 2-1R は 2-1 の左右反転（ゼブラと側壁の側が逆）。3to3-1 は車線の線が 3 本（破線 2 本）で、ゼブラが同じく広がる側の縁に付く。

## 寸法（2to2-1。白い画素を、タイルの座標 u・v（0〜1。u はタイルの右下へ、v は左下へ）に直して数えた）

- T字のセル（`.7.0`。道路は v の向きに走る）:
  - 実線の路側線: u ≈ 0.1（全長）。中央線の破線: u ≈ 0.5、1 タイルに 2 本（周期 0.5、1 本の長さ約 0.2）。
  - 点線（車線の境）: u ≈ 0.82（全長）。その外側の帯（u 0.82〜1.0、幅 0.18）に、v 0.4〜1.0 の 0.6 の長さでゼブラ（斜線）。v 0〜0.4 は点線だけ。
- 端のセル（`.6.0`。道路は u の向きに走る）:
  - 狭い側（u 0.55〜1.0）に v ≈ 0.25 の実線。u 0.5 で線が曲がり始め、タイルの端（u 0）へ向けて v 方向に約 0.3 ずれる。
  - ゼブラ: 曲がる線と元の線のあいだ。長さ u 0.5（0.5 → 0）、幅は曲がり始めの 0 から端で約 0.3 へ広がる扇形（斜線 4〜5 本）。
- 十字のセル（`.3.3`）: 白は v ≈ 0.1・0.5・0.85 の 3 本の線（中央線は実線）と、u 0.4〜1.0 に v ≈ 0.1・0.85 のゼブラ。

## 作る案（承認のあと、実装はしないことになった。下の「結論」）

- 作りは #156 と同じ tram_track の重ね（ADR 0011）。名前 `ami_mark_expwy_<diverge|merge>_<l|r>_<taper|gore>` の 8 つ（分岐・合流 × 左・右 × 2 タイル）。
- SIS の 1 タイル 2 車線 = AMI の高速道路 1 タイル。拡幅は 4 車線（2 タイル）への移り変わりとして作る。ゼブラは上の寸法（長さ 0.5、最大幅 0.3、曲がり始め 0.5）を初期値にして、AMI の絵で描く。
- 新しいファイルに分ける: `tools/blender/sheetlib/marking_expwy.py`、`src/ami_mark_expwy_*`、`ingame/marking_expwy*`。共通のファイル（catalog・ami_dat・render・icons・lineup・build）は行を足すだけにする。#156 の作り直しで `marking.py` の形が変わる（`ami_mark_branch` を外し、導流帯・停止・広い版・広い横断歩道に組み直す）ので、`marking.py` は呼ばず、必要な部分は `marking_expwy.py` に持つ。
- 着手は #163 が main に入ってから（進捗管理の決定）。そのあとで main から作業ブランチを切り直す。
