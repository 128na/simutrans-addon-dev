# 作業ログ: 複線の直角のカーブで基盤の形が合わない件の整理（#94）

（2026-11-21）

## 目的 / 発端

#88（PR #93）で iss と AMI を同じ配置で並べたとき、複線のカーブ（区画 dc。`addons/ami/docs/curve_study_dc.png`）で、角を曲がった後に back の線が手前の側に来て、基盤の形が合わなかった。
4 方向の角で back・front の基盤がどう入れ替わるかを整理し、直し方の案を出してユーザーが決める（[#94](https://github.com/128na/simutrans-addon-dev/issues/94)）。

## 分かったこと（事実）

### 絵の選ばれ方

- 平らなタイルの way の絵は、タイルの向き（ribi）だけで選ばれる（`../simutrans/boden/wege/weg.cc` の `weg_t::calc_image`、`set_images(image_flat, ribi, snow)`。斜めの並びのときだけ `diagonal` の絵に替わる）。同じ way の同じ向きのタイルは、どこに置いても同じ絵になる
- 基盤の版のカーブのセル（行 2 の列 5〜8、`image[sw]` `[nw]` `[ne]` `[se]`）は、在来線の基盤の back・front で次の形だった（`addons/ami/src/ami_rail_ballast_base_back.png`・`_front.png` のセルを切り出して見た）

| カーブ | 経路が画面で | back の基盤 | front の基盤 |
|---|---|---|---|
| `nw` | 横（タイルの上の角の側） | 経路の下（タイルの大きい側）を埋める | 経路の上（小さい三角）を埋める |
| `se` | 横（下の角の側） | 経路の下（小さい三角） | 経路の上（大きい側） |
| `sw` | 縦（左の角の側） | 経路の右（大きい側） | 経路の左（小さい三角） |
| `ne` | 縦（右の角の側） | 経路の右（小さい三角） | 経路の左（大きい側） |

- 画面で横向きのカーブ（`nw`・`se`）は、奥・手前がそのまま上・下になる。画面で縦向きのカーブ（`sw`・`ne`）は、奥・手前が決まらず、back は「壁が左・基盤が右」、front は「壁が右・基盤が左」に描いてある

### 4 方向の角

複線の輪（外の線と、1 タイル内の線）で考える。版の決まり（`addons/ami/README.md` の「奥と手前の決め方」）は、南北の線なら西が奥・東が手前、東西の線なら北が奥・南が手前。

| 角（画面で） | 外の線の 2 辺の版 | 内の線の 2 辺の版 | 線の途中で版が替わるか | 角のタイルが合う版（外 / 内） |
|---|---|---|---|---|
| 上（北西） | back・back | front・front | 替わらない | back / front |
| 下（南東） | front・front | back・back | 替わらない | front / back |
| 右（北東） | back（東西の辺）→ front（南北の辺） | front → back | 替わる | front / back（南北の辺の版） |
| 左（南西） | back（南北の辺）→ front（東西の辺） | front → back | 替わる | back / front（南北の辺の版） |

- 右と左の角では、角の前後の直線のタイルそのものが、外の線で back・front、内の線で front・back でなければ基盤が合わない。直線の絵は向きだけで選ばれるので、**線の途中のどこかで版を替えることは、どの案でも避けられない**。選べるのは替える場所と、角のタイルの絵だけ
- 角のタイルを南北の辺の版にすると、4 方向とも外の線の基盤が角の内側を、内の線の基盤が角の外側（2 本の間）を埋め、2 本の間がつながる。これは `addons/ami/README.md` の「複線の輪では、角のタイルを南北の辺と同じ版で敷く」と、`ingame/sample.nut` の区画 W1 の敷き方と同じ
- #88 の区画 dc は、外の線を角の後も back のまま敷いていた（右の角）。基盤が合わなかったのは、絵ではなく敷き方による

### ゲームで並べた結果

- 環境: `OTRPv64_3.exe`、addon_check の `flat_512.sve` をゲームの写し（`addons/ami/work/study_game/47200/`）で開き、MCP のポートは 47200。温暖、等倍。pak はこのブランチの `build.py` で作った `dist/ami.pak` と iss の `iss_rail_way.pak`
- 見本: `addons/ami/ingame/curve_base_study.{sh,nut}`。複線の輪（外 (0,0)-(6,6)・内 (1,1)-(5,5)）を、組（iss の `iss_wtg_0240_*`・AMI の在来線の基盤・それに壁・架線つきの壁）ごとに 3 通りの敷き方で並べた（輪の原点は x=150・162・174、y=20・32・44・56）
  - N: 線ごとに版を通す（外の線は全部 back、内の線は全部 front。#88 の区画 dc と同じ）
  - R: 辺ごとに奥を back・手前を front にし、角のタイルを南北の辺の版にする
  - X: R と同じ辺の版で、角のタイルを東西の辺の版にする
- 敷いた後に角のタイル 8 か所の way・way-object の名前を読み、3 通りとも思ったとおりの版だった（壁の way-object は、角に残したい版の辺を先に敷いた）
- 画像: `addons/ami/docs/curve94_rings.png`（輪の全体）、`curve94_right.png`（右の角）、`curve94_left.png`（左の角）。どれも行が上から iss・AMI・AMI＋壁・AMI＋架線つきの壁、列が左から N・R・X。`curve94_wall_zoom.png` は R の壁の右の角（外・内）を 4 倍にしたもの

| 敷き方 | 上・下の角 | 右・左の角 |
|---|---|---|
| N | 下の角と南・東の辺は、外の線の基盤が外へ出て、2 本の間に草の帯が出る | 角の後の辺で同じ。角の先に基盤の三角が突き出る |
| R | 4 組ともつながる | 4 組ともつながる。壁・架線もつながる |
| X | R と同じ | 角の 2 タイルの間に草の穴が開き、外の角の先に基盤が突き出る（4 組とも） |

- iss も、N と X で草の穴が開き、R でつながった（穴の形は基盤の幅の違いで AMI と少し違う）
- R の壁の右の角では、外の線の back の壁と front の壁の継ぎ目に、壁の上の縁が 1〜2px 縦に出て見える（`curve94_wall_zoom.png`）。左の角では目立たなかった。見た目の判断はユーザーに残す

### 画面の道具で敷き替えられるか（ソースを読んだだけ）

- way: 道具（`tool_build_way_t`）は、Ctrl を押さないと「速い way を残す」で敷く（`simtool.cc` の 3300〜3305 行付近）。残すのは今の way の方が速いときだけ（`bauer/wegbauer.cc` の 2906〜2915 行付近）。back・front は速さが同じ（在来線は 160）なので、Ctrl なしで上から敷けば置き換わるはず
- 壁（way-object）: 道具は Ctrl を押さないと、同じ速さの物を後から敷いても前の版のまま向きだけ足す（`simtool.cc` の 4723 行付近、`obj/wayobj.cc` の `extend_wayobj`）。角のタイルの壁を替えるには、Ctrl を押して敷き直すか、先に南北の辺の壁を敷く
- どちらもゲームの画面では試していない（スクリプトの `build_way` は Ctrl を押した扱い）

## 推測・未確認事項

- 試したのは在来線の基盤の版と、その壁・架線つきの壁だけ。ほかの線路 3 種・道路 3 種の基盤の版、高架の版、雪の絵は並べていない。カーブのセルの作りが同じなので、同じ結果になる見込み
- 斜めに走る複線から直線への角、T字・十字が角に来る形は見ていない
- 画面の道具で敷き替えられるかは、上のとおりソースを読んだだけ

## 結果どうしたか

- 案を 3 つ出した
  - A. 敷き方の説明で済ませる（おすすめ）: 角のタイルを南北の辺の版にする決まりは既に README と見本にあり、4 方向とも今の絵のまま合う。遊ぶ人向けの `release/readme.txt` の既知の課題の行を外し、「使い方」に次のような注意を足す。絵・dat は変えない
    - 案の文: 「複線のカーブでは、画面で右と左に曲がる角で、外の線と内の線の版（back・front）が入れ替わります。角のタイルは南北の辺と同じ版にしてください（直線を先に敷き、角のタイルだけ南北の辺の版で上から敷き直す。壁は Ctrl を押して敷き直す）」
  - B. 角に置く専用の版を足す: 直線のタイルの版はどのみち角で替える必要があり、専用の版を足しても替える場所が角のタイルになるだけで、R と見た目が変わらない。版が 1 つ増えて選ぶ手間が増える
  - C. 縦向きのカーブ（`sw`・`ne`）の back・front の絵を入れ替える: 角のタイルが合う版が「東西の辺の版」に変わるだけで、版の入れ替えは残る。T字・十字（通り抜ける線の版に合わせる）や見本の区画 W1 と決まりがそろわなくなる
- 本番の `src/`・dat・シート・`release/readme.txt` は変えていない。足したのは見本のスクリプトと画像だけ
