# 作業ログ: AMI の線路・路面軌道に分岐の追加画像（Y字分岐・三方分岐）を入れる（#57）

（2026-11-21）

## 目的 / 発端

OTRP は、T字・十字の way に ex 画像（26〜35 番）があると、Y字分岐・三方分岐の形でそれを選ぶ（`docs/reference/way-addon.md` の 9.4）。makeobj は 26 番以降のキーを持たないが、pak への継ぎ足しで入れられることは確かめてあった（9.1、記録 [2026-11-19_way-ex-image-pak-graft](2026-11-19_way-ex-image-pak-graft.md)）。#57 で、AMI の線路（在来線・弾性まくらぎ直結軌道・高速線と、その基盤・高架の版）と路面軌道に Y字分岐（26〜29）・三方分岐（31〜34）の絵を描き、その上に重ねる way-object にも同じ番号の絵を持たせ、pak に入れる道具を作る。道路（#46）は範囲の外。

## 分かったこと（事実）

- 本体の選び方（`boden/wege/weg.cc` の `select_switch_image`、`boden/grund.cc` の `is_use_track_wt_ex_image`）: Y字分岐は T字のタイルで `nw` = false の枠（根元が東 = `nse` の 26、北 = `new` の 27、西 = `nsw` の 28、南 = `sew` の 29）。三方分岐は十字のタイルで、1 本側の向きの T字の枠の `nw` = true（31〜34）。十字の枠（30・35）は線路の自動選択では使われない。固定の道具 `tool_set_switch_image` は値 4 で 26〜30、値 3 で 31〜35。
- way-object（`obj/wayobj.h`・`obj/wayobj.cc`・`descriptor/way_obj_desc.h`）: T字・十字のタイルで分岐の絵を探すのは 16 番が空でないときだけ。ex は、絵の数が 26 を超え 26 番が空でなく、隣のタイルにも way-object があって way が ex の形のとき。`way_obj_writer` は手前・奥とも 26 枚の並びを書く（キーの無い絵は空）。架線つきの壁は 16〜25 番が空だったので、ex を足すだけでは使われない。
- 公開版の OTRP `v63_3`: KUTA_v6 のコミット（`53ca75e21`）を含む。`../simutrans` で `v63_3` と `feature/script-save`（`1cc2e78b9`）・`v63_4`（2026-11-21 のタグ）を `git diff` で比べた。`weg.cc`・`grund.cc`・`wayobj.cc`・`wayobj.h`・`way_desc.h`・`way_obj_desc.h`・`way_reader.cc`・`way_obj_reader.cc` の差は、`v63_4` の `weg.cc` の情報表示の 1 行（車両のずれの表示の入れ替え）だけ。`origin/OTRP-KUTAv6` は `v63_3` と同じコミット（`20ed2495b`）だった。exe は切り替えず、ソースで確かめた。
- 見本（`addons/ami/ingame/ex_sample.nut`、`OTRPv64_3.exe`、addon_check の `flat_512`、ポート 47300）: 変える前の pak（HEAD の `src/` から作った）では、Y字は `plain`（通常の T字）、三方分岐は通常の十字の絵（`got` が十字の番号）。変えた後は 8 組（在来線・直結軌道・高速線・路面軌道、在来線の基盤 4 版と架線つきの壁 4 版）× 温暖・降雪の 16 行で、8 つの形がどれも `ok`（自動で選ばれた絵が固定の絵と同じで、通常の絵と違う）。
- 継ぎ足しの前に、仮の単色の絵を継ぎ足した pak で同じ見本を流し、在来線の 8 つの形が温暖・降雪とも `ok` になることを確かめてから描いた。
- 画面（`ex_capture.sh`、ズーム 3、温暖・降雪 × 8 区画 × 8 形 = 128 枚ずつ、前後とも）: ex のレールが Y字・三方分岐の経路をたどり、架線つきの壁の線も同じ経路に張られた（way-object の ex が選ばれている）。
- シート: 変わったのは、線路の 27 シート・路面軌道・架線の 4 シートと、壁だけの single・back・front のシート（同じ壁のシートを架線と共有するので、ex のセルが描かれる。壁だけの dat は指さない）。`sheet_diff.py` で、変わったのは行 0・1・4・5 の列 10〜13 だけで、ほかのセルの色の差は 0。
- `sheet_audit.py`（`--skip-holes "_catenary(__ex_donor)?$"`）: ex を足していない dat の候補は前と同じ 18。増えた候補は提供用の way（`src/ex_donors.dat`）の分で、架線の手前の絵の穴（線だけの絵なので、架線の dat では外している種類。提供用は 1 ファイルにまとめたので外す正規表現に掛からない）と、壁の奥の絵の小さな点（`(8, 79, 111)`・`(9, 176, 110)`。前からある T字・十字の 3.6・3.7・3.9 と同じ位置・大きさ）だけ。
- 坂・つなぎ目（`ingame/seam_slope_check.sh`。変える前の pak はポート 47301、変えた後は 47300）: `[seam]`・`[slope]` の 87 行が前後で同じ（在来線・直結軌道・高速線とも。斜めのつなぎ目の草 1〜3px と、十字の坂の寄りの不合格は前からのもの）。ただしこの見本（`seam_slope.nut`）に Y字・三方分岐のタイルは無い。
- ex のセルのつなぎ目は、シートで元の T字・十字のセルと比べた（作業用の Blender のスクリプト。透過色 (231,255,255) 以外の範囲を輪郭とする）: 線路・路面軌道の 28 シートと架線の 4 シートの全部の ex セル（夏・雪、手前の絵）で、輪郭は 1 画素も変わらない。輪郭の縁（透過色に接する画素）で色が違うのは 1 セルあたり 9〜38 画素で、どれもセルの中ほど（x 88〜168・y 104〜144、セルは 256px）の、T字・十字の道床の内側の切れ目の縁。タイルの端に差は無いので、隣のタイルとのつなぎ目は T字・十字と同じ。
- 壁だけの way-object（`ami_wall_rail_single`・`back`）を在来線の基盤の版に重ねた見本も流した（`WAYS` を差し替え）。way の判定は 4 行とも `ok`。壁は通常の T字・十字の絵のまま（`addons/ami/docs/rail_switch_ex_wallonly.png`。左上から温暖の single の Y字 東・三方分岐 東、back の Y字 北、降雪の back の三方分岐 南）。
- ゲームのスクリプトの癖: `local a = d[1], b = d[2];` で `b` に違う値が入り、東西の形が敷けなかった。`local` を 1 つずつにして直した（reference の 8.2 に書いた）。

## 結果どうしたか

- `tools/blender/sheetlib/sheetlib.py` の `track_sheet` に `ex_switches` を足した（行 0 の列 10〜13 に Y字、行 1 に三方分岐。三方分岐は十字の道床・壁・型の上に、直進と両側の枝のレールを張る。架線の線もレールの経路に張る）。`cells.py` の `near_frame` は `y_nse` などの名前から T字の軸を取る。
- `addons/ami/blender/render.py` で、線路・路面軌道の設定に `ex_switches` を入れた（二重架線は外す）。
- `addons/ami/blender/ami_dat.py` が `src/ex_donors.dat`（提供用の way 28 個と way-object 4 個、名前は `<対象>__ex_donor`）を書く。架線つきの壁の dat には 16〜25 番（`[nse1]`〜`[nsew2]`）に通常の T字・十字の絵を入れた。
- `addons/ami/ex_graft.py`（標準ライブラリだけ）を足した。提供用の pak の 16〜25 番を、対象の 26 枚の画像リストの末尾へ写し、数を 36 にする。`build.py` が pak を作った後に呼ぶ（`ami.pak` で 32、`ami_rail.pak` 27、`ami_tram.pak` 1、`ami_extra.pak` 4）。変えない pak を読んで書くと、バイトまで同じになる。
- 見本と撮影の道具 `ingame/ex_sample.nut`・`ex_check.sh`・`ex_capture.sh` を足した。
- 確認画像は `addons/ami/docs/rail_switch_ex_<気候>_<区画>_<形><根元の向き>.png`（左が前、右が後）。
