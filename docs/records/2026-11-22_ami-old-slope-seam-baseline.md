# 作業ログ: 旧描画位置の線路の坂の継ぎ目（#178）— SIS 同士の基準値

## 目的

[旧描画位置の記録](2026-11-22_ami-old-draw-position-seam.md)で、在来線（+1.0px）・直結（+1.1px）の坂の継ぎ目が NG になった（`seam_judge.py` のしきい値 1.0px）。SIS 同士の坂の継ぎ目でも同じくらいずれるのか（基準値）を測り、旧の描き方の問題かを切り分ける。

## 測り方

2026-11-22、`addon_check` の `OTRPv64_3.exe`、`flat_512.sve` の温暖側、ポート 47200。`ingame/seam_slope_check.sh` の坂の継ぎ目（x=152、南が低い 1 段の坂、`seam_slope.nut` の `sl`）。

- 基準: SIS の新幹線の砂利 E01（`SIS_ST_TGbl_E01-999B`）を `REF`、同じ砂利の E03（`SIS_ST_TGbl_E03-999B`）を「自分側」にした。E01 と E03 は劣化度違いの別 pak で、絵の作りと位置は同じ。判定は、一時的に `seam_judge.py` の `PREFIX` を `SIS_ST_TGbl_E03` にし、`SHEETS` に仮の対応を足した版で行った（測った後に戻した。リポジトリには残していない）。`rng=0` では AMI のシートは位置合わせに使われず、帯の測定は画面の画素だけで行われる
- 比較: 同じ条件で旧 4 種（`ami_rail_*_old`、SIS E01 と同じ pak に統合）を測り直した
- 一度、SIS の dat を写して名前だけ `ami_` に替えた版も試したが、ゲームで絵が崩れて（4 つの欠片になった）測れなかった。原因は調べていない（E03 で足りたため）

## 結果（坂の継ぎ目、模様のずれ。しきい値 ±1.0px）

| 組 | SIS → 坂（152,101 の南側の継ぎ目） | 坂 → SIS（北側の継ぎ目） |
|---|---|---|
| SIS E01 → SIS E03（基準） | +0.4px（相関 0.83） | +0.1px（相関 0.74） |
| SIS E01 → 旧 在来線 | **+1.0px NG**（相関 0.88） | +0.3px |
| SIS E01 → 旧 直結 | **+1.1px NG**（相関 0.81） | +0.4px |
| SIS E01 → 旧 ラダー | -3.0px OK（相関 0.48、弱いので判定なし） | -2.7px |
| SIS E01 → 旧 スラブ | +0.4px OK | +0.0px |

- 東西・南北の直線は SIS 同士も +0.1〜+0.2px。斜めの継ぎ目は SIS 同士でも NG（草 4px・模様 -4.0px。曲がりの継ぎ目の測り方の限界で、坂の問題とは別）
- 幅の差: SIS 同士は幅の差なし（片側の縁だけでそろう）。旧の坂は SIS の平地より狭く測れる（在来線・直結 -17px、スラブ -20px）。坂のタイルと平地のタイルの帯の広さの差で、SIS 同士の坂（`E01` の平地 → `E03` の坂）では同じ差は出ていない（縁の片側だけが測れた）。比べるには測り方が足りない
- 坂の十字（`slope_measure.py`）の基準は測れていない。この道具は AMI のシートの形を前提にしていて、SIS では坂の判定が不安定だった（SIS 同士で急坂の 4 タイルが全部 NG・レールが見つからない）。使えない

## 読み

- 基準値は +0.4px で、しきい値 1.0px の半分以下。旧の在来線・直結は、基準より 0.6〜0.7px 大きく、しきい値をわずかに超える。「検査が厳しすぎる」だけでは説明できない
- ただし 1.0px 前後は画素の丸めで出る大きさで、画像（`work/seam_old/rail_ballast_old_sl_judge.png`）では、レールが継ぎ目で 1px ほど段になって見える程度。SIS 同士は段が見えない
- ラダーは相関が弱く、判定なしで OK。スラブは +0.4px で基準と同じ
- 原因は未特定。旧の在来線・直結の坂の絵（28・36 などの坂のセル）の位置が、SIS の坂の絵に対して 1px 近くずれている可能性が高い。SIS の dat の坂の `Image` のオフセット（`-64,-96` など）と、AMI の旧の坂のオフセット・レンダの位置合わせを比べる必要がある

## 次に調べること

- 旧の在来線・直結の坂のセルを、SIS の同じ坂の絵と重ねて、どの方向に何 px ずれているか測る
- ずれの原因が描画の丸めなら、旧のレンダの坂（`TRACK_PROFILES["old"]` の坂の位置合わせ）を 1px 直す
- 雪の側の坂は未測定

## ずれの向きと量（旧の坂のセルを SIS の坂と重ねた）

画像 [`2026-11-22_ami-old-slope-seam-baseline_cmp.png`](2026-11-22_ami-old-slope-seam-baseline_cmp.png): 左から SIS E01→E03、旧 在来線、旧 スラブ。`seam_slope.nut` の坂の継ぎ目（x=152、南が低い 1 段の坂 36）を等倍の 3 倍で拡大。同じ画面の位置（jump 先 152,102、画面 x230〜420・y300〜470）。

- 継ぎ目の列（x=340・346。SIS 側の平地は x=358・364）で、レールの y を比べた。平地の SIS 側は 4 列とも一致。坂のセルでは、旧の在来線のレールが SIS の坂より **1px 下**（x=340: SIS 354・361 に対し旧 355・362。x=346: SIS 349 に対し旧 350）
- つまり旧の在来線・直結の坂のセル（36）は、レールが SIS の坂の絵より 1px 下に描かれている。直すなら坂のセルを 1px 上（dat の `Image` のオフセットなら y を 1 小さく、またはレンダで基準を 1px 上）
- スラブは同じ基準面・同じレンダの流れで OK（+0.4px）。在来線・直結は道床の形（上面 ±1.45 の肩から底 ±1.9 まで斜面）が違う。ずれの原因は、坂のセルの全体の位置ではなく、道床の斜面の形が坂のセルで 1px 低く描かれることかもしれない（未確認）
- 見た目の差でいちばん目立つのは、このずれではなく、坂のセルの道床が SIS より狭く（-17px）、色が青みの灰である点（旧・新に共通の作り。#70 の決定）
- 測ったのは坂 36（南が低い）だけ。ほかの向きの坂（4・12・28・8・24・56・72）は同じ測り方では未確認

## 坂のセルの縦位置をずらして直す試し（dat のオフセット。採用しない）

旧の在来線・直結の坂の絵（`imageup`・`imageup2`）の dat の y のオフセットを 1px 上げ（-32 → -33）、`seam_slope_check.sh` と、坂の向きごとの見本（`work/dir_*.nut`。1 段の南が低い 36・北が低い 4・西が低い 12・東が低い 28、2 段の南 72・東 56。SIS 平地 → AMI の坂の高い側の継ぎ目で測る）で、`seam_judge.py` の模様のずれを見た。

| 坂 | 直す前 | 全部 1px 上げた | 判定 |
|---|---|---|---|
| 南が低い 36（現行の見本） | +1.0px NG | +0.1px | OK |
| 東が低い 28 | +1.1px（相関 0.40） | +0.4px | OK |
| 北が低い 4 | -0.2px | -0.7px | OK だが悪化 |
| 西が低い 12 | 0.0px | -0.9px | OK だが悪化 |
| 2 段 南 72 | +1.2px NG | +0.4px | OK |
| 2 段 東 56 | +2.1px（相関 0.40） | +1.5px（-2 なら +0.9px） | 相関が弱く判定されない |

- 南・東が低い坂だけ（`imageup[12]`・`[9]` と `imageup2` の同じ向き）を上げると、旧 4 種の `seam_slope_check.sh` は NG 0 になった（在来線・直結 +0.1px）。ラダー・スラブは変えていない
- **ただし採用しない**: 画像（[`2026-11-22_ami-old-slope-seam-fix_before-after.png`](2026-11-22_ami-old-slope-seam-fix_before-after.png)。上段 在来線、下段 直結。左が直す前、右が上げた後）のとおり、坂のセルだけを 1px 上げると、坂の低い側の端で隣の AMI の平地のタイルとの間に 1px の草の線が出る。絵の外形（地面の形）は動かせず、レールの位置だけを SIS に合わせる必要がある
- 直すなら、dat ではなくレンダ（`tools/blender/sheetlib` の坂のセルで、レール・まくらぎ・道床の形を 1px 上げ、タイルの辺では外形を地面に合わせる）で、旧の在来線・直結の南・東が低い坂のセルだけを変える。基盤・高架・橋・トンネル・壁の坂のセルも同じ位置に合わせる必要があるかもしれない（未確認）。共有の道具（sheetlib）に触れる
