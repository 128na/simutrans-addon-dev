## 分岐の絵を入れていたときの作り（2026-11-19〜20 の README から移した）

以下は README の文をほぼそのまま写した。リンクと画像のパスは、この記録の場所に合わせて直した。

道路でも switch 画像は使われる。本体のソース（`../simutrans`）で確かめた:

- 自動選択: `boden/wege/weg.cc` の `weg_t::calc_image`（OTRP-KUTAv6 の 732〜739 行）が、switch 画像を持つ way の T字・十字で、`track` なら `select_switch_image`、`road` なら `select_switch_road_image`（988 行〜）を呼ぶ。道路の条件は線路と違い、T字の枝の側の隣が T字か十字（`ribi_t::is_threeway` は十字も含む）で、本線の両隣が分岐でないときに「1」（`nw` = false、dat の `image[nse1]` など）を選ぶ。十字は、ex 画像が無い way では、隣のどれかが T字か十字のとき、その隣の向きの T字の「2」の絵（東なら `image[nse2]`、西なら `image[nsw2]`、北なら `image[new2]`、南なら `image[sew2]`。この順に見る）を十字のタイルに出す。十字の 1・2 は、ex 画像が無いと自動では選ばれない
- 固定: 固定の道具（`tool_set_switch_image`）は `128na/simutrans` の `feature/switch-image-override` のブランチにあり、OTRP-KUTAv6 には無い（`simtool.cc` の `tool_set_switch_image_t::work`、`boden/wege/weg.cc` の `can_fix_switch_image`・`apply_switch_image_override`）。waytype を問わず、道路でも T字・十字を固定できる。選択 1 が `nw` = true（dat の「2」）、選択 2 が `nw` = false（dat の「1」）。アドオンを確かめる `OTRPv64_3.exe` にはこの道具がある（見本の `[check] pin tool=true`）

自動で「1」が選ばれるのは、道路を 2 本隣り合わせに並べ、渡り口でつないだ形（枝の先がすぐ隣の道路の T字）なので、絵は次のようにした（`sheetlib` の `road_sheet` の `switch_lines`）:

| 絵 | 中身 | 出る場面 |
|---|---|---|
| 通常の十字（`image[nsew]`） | 開いた十字: 交差点の中に白線を通さない。腕の路側線は角の円弧でつなぎ、中央線は腕の口まで（下の「隣り合う十字と優先道路の十字」） | 普通の十字路 |
| 通常の T字 | 本線の中央線と、枝の無い側の路側線（実線）を通す。枝の側は、本線の路側線を角の円弧で枝の路側線へつなぎ、枝の口を点線で渡す | 普通の T字路 |
| 1（`image[nse1]` など） | T字の形。通常の T字と同じ白線で、枝の口を点線で渡さない（隣の道路とのあいだを開ける）。轍は直進と、枝と名前の反対側の端をつなぐカーブ 1 本（下の「T字の 1・2 の轍」） | 2 本並べた道路の渡り口（自動）・固定の選択 2 |
| 2（`image[nse2]` など） | 1 と同じ白線の T字。違いは轍のカーブの向きだけ | 隣が T字か十字の十字（自動）・固定の選択 1 |
| 十字の 1（`image[nsew1]`） | 南北が優先道路の十字（下の「隣り合う十字と優先道路の十字」） | 固定の選択 2（ダイアログの「十字（上下が直進）」）だけ |
| 十字の 2（`image[nsew2]`） | 東西が優先道路の十字 | 固定の選択 1（ダイアログの「十字（左右が直進）」）だけ |

### 隣り合う十字と優先道路の十字（2026-11-19、ユーザーの決定）

十字が隣り合う形（道路を 2 本並べた 4 車線を、別の道路が横切る）では、本体は十字のタイルに T字の「2」の絵を出す（上の「自動選択」）。前は T字の形に描いていたので、十字の 4 本目の腕の側に路側線が引かれ、横切る道路をふさいで見えた（`addons/ami/docs/road_GE_L_zoom.png`）。その後、「2」を十字の形にして停止線を引いた作りを試したが、道路を 3 本以上並べた交差点（複雑な十字交差）では内側の腕にも停止線が出て合わなかった（記録 [2026-11-19_ami-road-stopline](2026-11-19_ami-road-stopline.md)）。ユーザーの決定で次のようにした:

- T字の「2」（`nse2`・`nsw2`・`new2`・`sew2`）: 前は通常の十字（`nsew`）と同じ絵にしたが、固定した T字が十字の絵になったので、ユーザーの指摘で T字の形に戻した（下の「T字の 1・2 の轍」）。そのため、隣り合う十字（自動）ではまた、横切る道路の側に路側線が引かれる（下の「多車線の十字」）
- 通常の十字は開いた十字（2026-11-19、ゲームを見たユーザーの指摘）: 前は東西の中央線と東西の路側線の点線が交差点を通り、隣り合う十字（4×2 の交差点など）で片方の道路が優先道路に見えた。交差点の中に走行車線を横切る白線を引かず、腕の路側線を角の円弧でつなぎ、中央線は腕の口（円弧の端）まで引く。3 種とも同じで、高速道路の十字の点線もやめた。1 タイルの道路（`single`）も同じ絵（`addons/ami/docs/road_GE_cross_open_zoom.png`・`road_EX_cross_open_zoom.png`・`road_LO_L_open_zoom.png`・`road_GE_4x4_cross_zoom.png`・`road_GE_6x6_cross_zoom.png`）。道路を 2 本ずつ並べた交差点（4×4・6×6）では、並べた道路のあいだ（路肩どうし）の角の円弧が交差点の中ほどで閉じ、角の丸い四角の枠が出る（6×6 では 4 つ）
- 角の円弧（2026-11-19、ゲームを見たユーザーの指摘）: 分岐の絵（T字・十字・1・2・優先道路の十字）で、隣り合う腕の路側線を角で 4 分の 1 の円弧でつなぐ。円弧の半径は `EDGE_CORNER_R` = 0.8（`tools/blender/sheetlib/road_parts.py`）。中心は路側線の交点から角の外へ (0.8, 0.8)。円弧の中ほどは路側線の交点から縦横とも 0.234 外で、車道の半幅 3.6 の交点にちょうど来る（それより大きいと路面の角の外へ出る）。T字の枝の口の点線と、優先道路の十字の口の点線は、口の幅（両側の路側線のあいだ、-3.37〜3.37）だけに引き、そこから円弧の端（4.17）までは路面のまま（`addons/ami/docs/road_GE_tee_arc_zoom.png`。渡り口の「1」は `road_GE_HV.png`・`road_LO_sew1_zoom.png`）
- 十字の分岐の絵（`nsew1`・`nsew2`）は優先道路のある十字。自動では出ず、固定の道具・タイルの詳細ダイアログでだけ選ぶ（Standard は通常の十字のまま）
  - `nsew1`: 南北が優先道路。`nsew2`: 東西が優先道路
  - 優先道路: 中央線を交差点の中も通し（生活道路は中央線なし）、路側線は交差点の口を点線で渡す。従道路の路側線は、角の円弧で優先道路の路側線へつなぐ
  - 従道路: 2 つの口の、交差点へ進入する車線（半分）に停止線を引く。中央線は停止線からタイルの辺まで。通行の側は左側通行（日本）で、`nsew1` は西の腕の北半分と東の腕の南半分、`nsew2` は北の腕の東半分と南の腕の西半分
  - 停止線の形: 白で幅 `STOP_LINE_W` = 0.35（画面で約 2px。路側線・中央線は約 1px）。線の中心はタイルの中心から `STOP_LINE_D` = 4.0（優先道路の路側線 3.37 の延長より外、タイルの辺 5 の手前）。線は腕の中心線から路側線の中心（`STOP_LINE_SPAN` = 3.37）まで。値は `tools/blender/sheetlib/road_parts.py`。3 種とも同じ位置
  - 確かめた絵（3 倍）: `addons/ami/docs/road_{LO,GE,EX}_priority_ns_zoom.png`（`nsew1`）・`road_{LO,GE,EX}_priority_ew_zoom.png`（`nsew2`）
- 本体の選択肢との対応: `128na/simutrans` の `feature/switch-image-override` の `gui/ground_info.cc` の選択肢は、値 1「十字（左右が直進）」が `image_switch` の `nw` = true（dat の `nsew2`）、値 2「十字（上下が直進）」が `nw` = false（`nsew1`）（`boden/wege/weg.cc` の `apply_switch_image_override`）。この「左右・上下」は線路の絵の、タイルの左右の角・上下の角を結ぶ直線のこと（[reference](../reference/way-addon.md) の 9.2）で、道路の南北・東西の軸（画面ではどちらも斜め）とは対応しない。`nsew1` を南北優先にしたのは、前の作り（十字の 1 が南北優先）に合わせたため。ダイアログの言葉と合うかは、ユーザーが見て決める
- 切り替え: `blender/render.py` から `sheetlib` の `road_sheet` に `switch_ruts`（T字の 1・2 を同じ白線の T字にし、轍のカーブで分ける）・`priority_cross`（十字の 1・2 を優先道路の十字にする）・`open_cross`（通常の十字を開いた十字にする）・`corner_arcs`（角の円弧）・`drive_left`（`DRIVE_LEFT`。偽にすると停止線が進入する車線の反対の半分へ移る。右側通行の版は今は作らない）を渡す

- 生活道路は中央線が無いので、前は T字の 1 と 2 が同じ絵だった。今は轍のカーブで違う絵
- 線路の「カーブの向き」の考え方（[reference](../reference/way-addon.md) の 9.2）は持ち込んでいない。道路の自動選択は隣のタイルが曲がるかどうかを見ないため

### T字の 1・2 の轍（2026-11-19、ユーザーの指定）

T字の 1 と 2 は、どちらも枝の無い側を路側線の実線でふさいだ T字の形で、白線は同じ（「1」の白線。枝の口の点線なし）。違いは轍（走行跡。車線ごとの暗い帯）だけで、直進の轍に、枝とつなぐカーブの轍を 1 本足す（`sheetlib` の `road_sheet` の `switch_ruts`、向きは `road_parts` の `SWITCH_RUT_ARCS`）。普通の T字（固定しない絵）は今までどおり、両方のカーブの轍がある。

カーブの向きは、固定の道具の選択肢の名前（`128na/simutrans` の `feature/switch-image-override` の `gui/ground_info.cc` の `switch_choice_label`）から決めた。選択 1 が「2」の絵、選択 2 が「1」の絵で、名前の向きは sew の選択 1 が東、nse が南、new が西、nsw が北（選択 2 はその反対）。轍のカーブは、枝と、名前の反対側の本線の端をつなぐ（名前の向きへ走ってきた車が枝へ曲がる跡）。ユーザーの指定（sew1 は「西（左上）」で南–東、sew2 は「東（右下）」で南–西）に合わせた:

| 絵 | ダイアログの名前 | 轍のカーブ |
|---|---|---|
| `nse1` | 北（右上）へ分岐 | 東–南 |
| `nse2` | 南（左下）へ分岐 | 東–北 |
| `new1` | 東（右下）へ分岐 | 北–西 |
| `new2` | 西（左上）へ分岐 | 北–東 |
| `nsw1` | 南（左下）へ分岐 | 西–北 |
| `nsw2` | 北（右上）へ分岐 | 西–南 |
| `sew1` | 西（左上）へ分岐 | 南–東 |
| `sew2` | 東（右下）へ分岐 | 南–西 |

線路の分岐の絵（名前の側の端と枝をつなぐ。[reference](../reference/way-addon.md) の 9.2）とは向きが逆になる。ゲームで 3 種とも 8 枚を固定して撮り、轍の向きが表のとおりであることを見た（2026-11-19、`OTRPv64_3.exe`、`flat_512.sve`、`road_sample.nut` の区画 I。画像は記録 [2026-11-19_ami-road-switch-ruts](2026-11-19_ami-road-switch-ruts.md)）。

### 多車線の十字（T字の「2」を T字の形にしたので）

本体は、ex 画像の無い道路の十字で、隣が T字か十字のときに、その隣の向きの T字の「2」を十字のタイルに出す（上の「自動選択」）。「2」を T字の形にしたので、道路を並べた交差点では、十字のタイルの 4 本目の腕の側に路側線の実線が引かれ、横切る道路がふさがって見えた（画像は記録 [2026-11-19_ami-road-switch-ruts](2026-11-19_ami-road-switch-ruts.md)）。4×2 では、並べた道路の外側の 2 か所で横切る道路がふさがる。6×6 では、どの行も `nse2 nse2 nsw2` なので、内側の境にも実線が出る。

アドオンの絵だけでは両方を満たせない（1 枚の「2」を、自動の十字と固定の T字の両方に使う）。ex 画像を足しても、直るのは十字が 2×2 に並ぶ 4×4 だけ（[reference](../reference/way-addon.md) の 9.3）。そのため今は分岐の絵を外している（上の「分岐の絵（switch 画像 1・2）」の冒頭）。本体の分岐の絵の仕様を整理してから戻す。
