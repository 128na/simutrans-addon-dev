# 作業ログ: 精細化のラウンド 2（在来線の構造の試し、#56）

（2026-11-20）

## 目的 / 発端

ラウンド 1（`2026-11-20_ami-refine-round1.md`）は、まだらの明暗差とまくらぎの間隔を変えただけで、ユーザーの評は「見た目そんなに変わっていない」だった。
ユーザーが求めたのは、作っている物の意味を考えて構造を試行錯誤するループ（例: 線路 → 一定尺の軌条をつなげたもの → つなぎ目がある → 欠けで描くか継ぎ目板を足すか、ロングレールなら溶接痕か、断面は I 字…）。
このラウンドから、各ラウンドを「意味の木の葉を 1 つずつ試す」形に変えた。

## 意味の木（在来線のバラスト軌道）

画面での大きさは `docs/reference/way-addon.md` の 12 章。本物の寸法は記憶の値で、確かめていない。

- 軌条（レール）
  - 頭頂面: 車輪で磨かれて銀色に光る → 試した（head・headx・headx2）
  - 側面・腹部: さびの茶色 → 側面を暗くして頭との差を付けた（headx2）
  - 断面は I 字（頭・腹・底）→ 1px 未満。頭と影の 2 色で表す（headx2）
  - 定尺 25m をつなぐ → 継目（継目板・遊間）→ 試した（joint）
  - ロングレール → 溶接で継目が無い。溶接痕は 1px 未満 → 描かない
- 締結装置: まくらぎ 1 本に 4 か所 → 試した（fasten）
- まくらぎ: PC（灰白色）か木（茶色）。間隔は約 0.6m
  - 道床に埋まっていて、上面だけが見える → 試した（embed）
  - タイルの継ぎ目でも同じ間隔で並ぶはず → ラウンド 1 の欠陥を見つけて直した（下の「直した所」）
- 道床: 砕石。肩とのり面がある → このラウンドでは変えていない（今の台形のまま）
- 線路の脇（ケーブルトラフ・側溝・キロポスト）→ このラウンドでは扱っていない

## 直した所

- ラウンド 1 のまくらぎの間隔 0.54 は、タイル 1 辺（10）を割り切れない。経路はタイルの辺の外へ 1.5 延びていて、最初のまくらぎの位置（0.31）も辺にそろっていないので、タイルの継ぎ目のまくらぎの間が 0.82（ふつうの 1.5 倍）になっていた（`along()` の並べ方からの計算）。間隔を 10/18 ≈ 0.556 にし、最初のまくらぎを辺から半ピッチの位置にそろえた（`round.py` の `sleeper_align`）。継ぎ目の間も 0.556 になる

## 試した葉と結果

土台（2base）は「ラウンド 1 + 継ぎ目の直し」。葉を 1 つずつ足した版を描き、直線のセルで土台と比べた（色の差が 0.04 を超える画素の数）。

|---|---|---|---|---|

## 分かったこと

- 物差しの「くどさ」は、まだらの細かさを段階に分けて合わせたもので、構造の線（レールの明るい頭）による明暗差も同じに数える。構造を足すと値が上がり、手本に近づくほど「くどい」に寄る。構造の試しのラウンドでは、くどさを上限の目安としては使えるが、良し悪しは決められない
- 葉ごとに入り切りした版を並べると、「1px に届くか」がすぐ分かる。実寸で描いて見えないものは、誇張するか省くかを、意味（例: 幹線はロングレール）から決められる
- 同じ対象を別のラウンドで同時に描くと、`work/` の一時ファイルを取り合って失敗した。`round.py` で一時ファイルの置き場をラウンドごとに分けた
- `slope_measure.py`（坂の判定）はレールの色で行を探すが、ラウンドの絵（`work/rounds/`）には流していない。採る前に確かめる
