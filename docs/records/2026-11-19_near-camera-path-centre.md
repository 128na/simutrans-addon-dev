# 調査/作業ログ: 手前と奥の判定を部品の頂点数に左右されないようにした

（2026-11-19）

## 目的 / 発端

`near_camera` は、本体の部品の頂点の重心から壁までの向きで手前と奥を決めていた。頂点の多い部品（スラブ軌道の締結装置）を足すと重心がずれ、基盤と高架の back・front の絵が入れ替わった（[前の記録](2026-11-19_ami-autocheck-without-user-review.md)）。部品ごとの `centre=False` で避けていたが、指定を忘れると再発する。判定そのものを直した。

## 分かったこと（事実）

全シート（AMI 30 対象、blender-poc 29 対象）を描きながら `near_camera` の入力を記録し、案ごとの判定を描き直さずに比べた。絵に効く判定は 7,275 件。絵に効かないもの（残すかどうかを選ばない版の選択、位置に関わらず手前に描く架線の線）は除いた。

| 基準の案 | 今の判定と違う件数 |
|---|---|
| 本体の頂点の重心（`centre=False` なし） | 60 |
| 本体の範囲の中心 | 251〜265 |
| 部品ごとの範囲の中心の平均 | 58〜90 |
| 本体の面の面積で重みを付けた重心 | 69〜99 |
| タイルの中心 | 553 |
| 壁ごとに、自分の経路の最寄りの点から測る | 170（分岐の測り方を変えない場合） |
| 経路の中心線（タイルの中の部分）の中心 | 80 |

経路の中心線で測ると、経路が 1 本のセルの側壁は全部、今の判定と同じだった。違いは次の 2 か所に集まった。

- **T字の奥・手前の絵の分け方**: 残す壁の選択（`select_walls`）はまっすぐ通る道に対して決めるのに、絵の分け方（`render_layers`）は本体の重心とカメラの向きで決めていて、2 つが食い違っていた。分岐の絵（`nse1`・`nse2` など）は走行面の部品の数が違うので、分岐の向きでも判定が変わっていた。
- **行き止まりの端の壁**: タイル幅の壁は、残す側を削ると範囲が左右へ寄るので、位置では決まらない。

変更前の判定は、手前と奥の境に 0.003 しか余裕がなかった（しきい値 0.3 に対して、手前の最小が 0.303）。新しい判定は奥の最大が 0.017、手前の最小が 0.399。

## 判断したこと

- 手前/奥を測る向きと点を `near_frame` にまとめ、壁の選択と絵の分け方で同じものを使う。向きは T字ならまっすぐ通る道、それ以外はカメラの向き。点は、経路が複数ならタイルの中心、1 本なら経路の中心線の中心
- 壁の位置は頂点の重心ではなく範囲の中心で測る。経路 1 本のセルでは結果が変わらず、壁の頂点数にも左右されない
- 行き止まりの端の壁は、線路の外へ向く向きで決める
- `Part.centre` は要らなくなったので外した
- 中心線だけに揃える案（T字も経路の中心から測る）は採らなかった。差は少ない（判定 76 件）が、まっすぐ通る道に対する決まりに反する壁を新しく作る

## 絵の変化

描き直して変わったのは 23 枚で、理由は上の 2 つだけ（2026-11-20 に main の a23b649 の後へ載せ直し、増えたシートを含む全部を描き直した。AMI 70 対象、blender-poc 29 対象）。

| アドオン | シート | 変わったセル |
|---|---|---|
| AMI | `ami_wall_rail_{single,back,front}` と架線つき、`ami_wall_rail_twin_catenary_{back,front}` | T字（`nse`・`new`・`sew`）と分岐の絵の壁 |
| AMI | `ami_wall_road_{single,back,front}` | T字（`new`・`sew`）の壁 |
| blender-poc | `track_{wall,elev}_{single,back,front}` | T字と分岐の絵の壁、`front` の行き止まり `n` の端の壁 |
| blender-poc | `expressway_{wall,elev}_{single,back,front}` | T字の壁 |

動いたのは、壁の短い切れ端が奥の絵と手前の絵の間を移った分。奥の絵に手前の絵を重ねた結果の差は、セルあたり 11〜61 画素（重なる所の前後が変わった分）。AMI の way のシート（基盤・高架・道路・路面軌道・歩道を含む）は変わらない。AMI の `dat` を作り直しても中身は変わらず、blender-poc の `dat` が参照しないセルに新しく絵が出ることもない。

重ねた結果が正しいかは、壁を分けずに 1 層で描いた絵と比べて確かめた。対象は AMI の `ami_rail_ballast_base_*`、blender-poc の `track_wall_*`・`expressway_wall_*` の `single`・`back`・`front` で変わった 37 セル（雪の絵を除く）。1 層の絵と違う壁の画素は、変更前が合計 630、変更後が 0 で、全部のセルで良くなった。AMI の道路の壁（`ami_wall_road_*`）で変わった 4 セルも、変更前 98 から変更後 0 になった。奥と手前を合わせた塗りの範囲は 25 セルで同じ、12 セルで 1 画素だけ違う。

`sheet_audit.py`（`--compare ami_rail_ballast ami_rail_slab --skip-holes "_catenary$"`）の候補は、載せ直す前は 12 件のままだった。載せ直した後は変更前（main）も変更後も 42 件で、中身も同じだった（増えた分は main で足したシートの分）。

## ゲームでの確認

検証用のフォルダの写しで `flat_512.sve` を開き、T字を 5 つ敷いて車両を走らせ、画面を続けて撮った（2026-11-20）。線路は基盤の版 `ami_rail_ballast_base_single` に `ami_wall_rail_single` を重ねた `new`・`sew`・`nse`（蒸気機関車 3 両の編成）、道路は `ami_road_general_base_single` に `ami_wall_road_single` を重ねた `new`・`sew`（トラック）。車両が分岐のタイルを通る画面で、奥の壁が車両の上に描かれる所、手前の壁が車両の下に隠れる所は無かった。

## 確かめられなかったこと

- 変更前の pak で同じ場面を撮って並べることはしていない（変更前後の違いは上の 1 層の絵との比べで見た）
- 基盤の版の `back`・`front` を組んだ T字での車両の見え方
