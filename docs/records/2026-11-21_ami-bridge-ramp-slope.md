# 作業ログ: 橋の坂の傾きを測り、坂から始まる端の躯体の下の縁を直す（#90）

## 目的 / 発端

#83（PR #86）の見た目の承認のとき、ユーザーが「橋のアプローチ部分（スロープ部分）の傾斜は画面表示でちょうど 45 度になるので少しずれていそう」と気づいた。指摘のあった区画は BT_B1・BT_B4。

## やったこと

- 入れた pak: main（ea53b02）の `dist/ami.pak`。`addon_check` の写し（`OTRPv64_3.exe`・`flat_512.sve`・等倍）で撮った
- 見本は 2 つ。1 つは `ingame/sample.nut` の橋とトンネルの区画（`BT_ONLY`）。もう 1 つは試しの nut で、pak128 の `Rail_160_Bridge`・AMI の線路の橋・道路の橋を、平地に東西と南北で並べた
- 縁の位置は、画素を列ごとに読んで直線に当てはめた。傾きは縦/横で、1.000 が 45 度
  - ゲームの画面: 緑でない最初の行。帯の幅は、躯体と崖の間の緑の帯の上端と下端
  - シートのセル: 透過でない範囲
- ポートは単発に 47300、並列に 47310〜47313 を使った

## 分かったこと（事実）

### 平地から立ち上がる坂（Ramp2）: ずれは無い

- AMI の橋は `Ramp2` を持つ。そのため、平地の端の坂は 2 段（32px）上がる（`descriptor/bridge_desc.cc` の `get_ramp`）
- `Rail_160_Bridge` は `Ramp2` を持たない 1 段の橋で、坂は約 37 度（シートで横 64px・縦 47〜48px）
- 測った値:

| 測ったところ | 傾き |
|---|---|
| シートの `Ramp2`（線路 4 種・道路 3 種）、床の奥の縁 | n −1.000、w +1.000、s・e 0.000 |
| 同じセルの手前の床の縁・レール | 0.99〜1.07（模様のため点がばらつく） |
| ゲームの BT_B1 の東の坂の上端 | 1.000（x=492〜556 で 64px 下がる）。#83 の確認画像 `addons/ami/docs/wallpier83_temperate_BT_B1.png` でも、直す前と後の両方で同じ |
| ゲームの BT_B1 の西の坂の上端 | 68px にわたり水平 |
| ゲームの南北の橋の南の坂 / 北の坂 | 1.000 / 水平 |

### 坂から始まる端（Start・Start2）の躯体の下の縁: 約 3px ずれていた

| 見本 | 躯体の下の縁（直す前 → 後） | 坂の縁 |
|---|---|---|
| BT_B4 の東の端（2 段、東が高い） | +0.047 → +0.003（64px で 3.0px → 0.2px） | 水平（−0.017） |
| BT_B4 の西の端（2 段、西が高い） | +0.963 → +0.997 | +0.976 |
| BT_B2 の西の端（1 段）、躯体と坂の縁の間の草の帯の幅 | 15〜18px で広がる → 17〜19px でほぼ一定 | — |

シートでも同じずれが見えた。`ami_rail_ballast_bridge` の行 3 の列 8（`start2_w`）では、下の縁が 152→154 から 152 で一定になった。

### 原因

`tools/blender/sheetlib/assemble.py` の `build_start_body` の作りにあった。

- 躯体の下の頂点を、地面の高さに合わせる。ただし基盤の下面（`BASE_H` = 0.35）より上には出さない
- 頂点はタイルの辺にしか無かった
- 高い側の辺では、地面が基盤の下面より上にある。そのため、下の縁がそこで基盤の下面の高さに止まり、辺から辺まで 1 本の直線になった
- 結果として、下の縁は坂より `BASE_H`（画面で約 2.7px）だけ緩く傾いた

地面が基盤の下面の高さを横切る点にも頂点を置くと、下の縁が坂と平行になった。

### シートの差

`sheet_diff.py` で直す前と比べた。

- 変わったのは、線路 4 種・道路 3 種の橋の行 3（`start`・`start2`）と、雪の行 7 だけ
- 線路は 1 シートあたり透過の範囲 1162px、道路は 236px
- 道路の橋は躯体がタイルの幅いっぱいなので、ゲームの画面で変わったのは 80〜143px（`ingame/road_struct_sample.nut` の GE_B2・GE_B4・EX_B2）
