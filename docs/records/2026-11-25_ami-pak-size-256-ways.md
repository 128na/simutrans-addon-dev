# 調査/作業ログ: 道路 4 種・路面軌道・歩道・標識・路面表示を 256 で組む（#261 の B）

## 目的 / 発端

#261（AMI の全部の物を 256 で組めるようにする）の 3 本目（A = 検査の道具 #271、B = この記録）。#266 は生活道路だけを 256 で組めるようにした（[2026-11-25_ami-pak-size-256.md](2026-11-25_ami-pak-size-256.md)）。B は way の通常の版と小物を足す。範囲は、道路の通常の版 3 種（一般・幹線・高速）、路面軌道、歩道（舗装 3 種。高架は C）、標識 8 種（板つき 6・路面の横断歩道 2）、路面表示 16 種。基盤・壁・高架・橋脚・橋・トンネル・架線・盛土は C、踏切・車庫・運河・モノレール・分岐の追加画像（ex）は D。

進め方はユーザーの決定（2026-11-25、判断 28）による。256 の PNG は dat と生活道路だけをコミットする（全部で約 260MB 増え、描き直すたびに増えるため）。256 の全部の検査は手元の `check.sh`（`CHECK_256_FULL=1`）と zip で行う。

## 分かったこと（事実）

- **pak128 の全シートが変更前のコードで描いた絵と全画素で一致した**（2026-11-25）。変更前は `origin/main`（`9c8f7cd`）の別の worktree で、変更後は変更したコードで、AMI の 221 シートを描き（踏切は道路の後。最後に `icons.py` を全部）、RGB の全画素（透明色を含む）を比べた（Pillow で 221 枚。差のあるシート 0・欠けたシート 0）。シートの横の控え（`*.road_cells.txt`・`*.icon_sources.txt`）も同じ。変更前の絵はコミット済みのシートと一致した（git の差分なし）。
- 画素で書いた値は、#266 で共通の部品（`CELL`・高さ 1 段・基準位置・持ち分を広げる行数など）に `SCALE` を掛けてあった。B で直したのは次の 3 つだけ。
  - **画面で横向きになる斜めの白線の半画素のずらし**（`sheetlib.py` の `DIAG_CENTER_SHIFT`・路側線の丸め）: pak128 は線の画面での太さが約 1px で、線を画素の行の中心に置くために 0.5px ずらす。256 は太さが約 2px（偶数）で、行の境に置くべきなので、ずらさない。そのままだと線が 1 行の白と両側の半端な 2 行に割れ、白線が細く灰色に見えた。偶数の倍率では 0、奇数では 0.5（`DIAG_HALF_PX`）にした。倍率 1 は同じ値。256 では白線が 2px の白でそろった（行の値 255・238）。生活道路（#266 のシート）の縁の白線も同じ理由で描き直した（`src256/ami_road_local.png`）。
  - **標識の板**（`roadsign.py`）: 板は 3×5 の数字などの画素の絵（pak128 の大きさ）を、柱の上に押している。256 は最近傍で `SCALE` 倍に拡大して押す（倍率 1 は同じ絵）。柱の高さ・太さは世界の単位なので変えない。
  - **標識の左側通行のずらし**（`ami_dat.py` の `ROADSIGN_OFFSET_LEFT`）: 本体（`obj/roadsign.cc` の `calc_image`）は画素で足すので、14 を `SCALE` 倍にした。
- `ami_dat.py` は、256 のとき `catalog.SCALED_SHEETS` の物だけ dat を書く（`put` に集約）。`SCALED_SHEETS` に、道路 4 種・路面軌道・歩道・標識・路面表示（33 シート）を足した。分岐の追加画像の提供用の dat（`ex_donors.dat`）は 256 では書かない（D）。
- `build.py` は、環境変数 `BUILD_SKIP_MISSING=1` で、絵のシートが無い dat を組まない（CI は 256 の PNG が生活道路だけなので、これで絵のある物だけを組む）。`check.sh` は、`CHECK_256_FULL=1` が無いときにこれを付ける。`addons/ami/.gitignore` に `src256/*.png`・`src256/*.txt`（生活道路を除く）を足した。
- **256（pak512 で組む）**: 33 シートを描き、手元の makeobj `pak512` が警告なしで通った（`ami.pak` 33 dat・`ami_road.pak` 20 dat・`ami_tram.pak`・`ami_extra.pak`・`ami_scenery.pak`）。アイコン・カーソルは `icons.py` を、描いた対象の名前を渡して流す（`render_parallel.py` はアイコンのセルを書かない）。`SHEET_PAK_SIZE=256` の `check_icons.py`（33 物・33 シート）・`check_cells.py` が通った。
- **256 のシートを pak128 の大きさに縮めて、今の pak128 のシートと比べた**（2×2 の 4 画素のうち不透明が 2 つ以上なら不透明、色は不透明な画素の平均）。透過の範囲の差は、アイコンのセル（256 は 32px のまま）を除くと、1 セルあたり 0〜128 画素（セルの不透明な画素は 1000〜5000 のうち。ほとんどは 0〜64）。縁の階段の違い。色の大きく違う画素は、道路・路面表示・歩道・標識・路面軌道とも少ない（道路の 1 セルで最大 260 画素ほど。白線の縁の半端な画素）。
- **ゲームでの確認**（OTRP v64、地面は pak128 を 2 倍にした `pak256poc`、`dist256/ami.pak`、画面は 704×560 の等倍の 3 倍）: 一般・幹線・高速の見本（行き止まり・1 タイル・斜め・輪と十字・坂の十字（1 段・2 段）・近い斜め・分岐の自動選択と固定・pak128 標準の道路とのつなぎ目）が、地面・坂・つなぎ目に合って見えた（温暖と降雪。作業者の目視。ユーザーの確認は PR のスクリーンショットで頼む）。路面表示（4 車線の交差点）・歩道（交差点の四隅）・標識（最高速度）・路面の横断歩道・路面軌道（輪と十字）も敷けて、周りと合った。見本の `[check]` の行（分岐の自動選択・固定・一方通行の向き）も期待どおりだった。スクリーンショットは `addons/ami/docs/261_b_pak256_ways/`。

## 推測・未確認事項

- 路面軌道の横向きの斜め（`TRAM_HDIAG_HEAD`・`TRAM_HDIAG_GROOVE`）は変えなかった。256 の絵では、レールの頭と溝が暗い線として見えた（縮めて比べて、128 の絵と同じ並び）。ゲームで細く見えるかは、ユーザーの確認と、線路（C）で測ってから決める。
- 標識の板は 128 の画素の絵の拡大で、256 らしい細かさではない（pak256 の標識の絵は別に決める）。
- ゲームの確認は、見本の全部の場所ではなく、種類ごとの代表の場所（スクリーンショットの場所）。路面表示の雪・標識の雪（標識は季節の絵を持たない）・歩道の舗装 3 種（敷石の材質の違いだけ。絵は縮めて比べた）はゲームで見ていない。
- 標識の `offset_left`（左側通行のずらし）を `SCALE` 倍にした根拠は、本体のコード（画素で足す）の読み。左側通行の地図（`flat_512_left_v64`）で標識は柱の位置に合って見えたが、右側通行は確かめていない。
- CI は 256 の PNG が生活道路だけの状態で動く（PNG はコミットしない）。CI が 256 で makeobj に通すのは生活道路 1 つだけで、今回足した 32 個の dat の組みは、手元（makeobj 60.12 系）の結果だけが根拠。CI の makeobj（本家 125.0 の Linux 版 60.10）で通るかは、この PR では確かめられない。
- `CHECK_256_FULL=1`（256 の 5 つの検査を全部の物に厳しく流す）は、踏切・車庫・盛土のシートが 256 に無い間（C・D が済むまで）は通らない。この PR の完了条件には使えない。
- 白線の半画素の規則（偶数は 0、奇数は 0.5）は倍率 1・2 だけで確かめた。3 以上は未確認（README に書いた）。

## 結果どうしたか

#261 の B の PR（Part of #261）で、上の変更・`SCALED_SHEETS` の拡張・256 の dat・README・ゲームのスクリーンショットを入れた。残りは C（線路と高さのある部品）・D（踏切・車庫・運河・モノレール・分岐の追加画像）。
