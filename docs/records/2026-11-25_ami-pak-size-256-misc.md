# 調査/作業ログ: 運河・踏切・車庫・操車場・モノレール・分岐の追加画像を 256 で組む（#261 の D）

## 目的 / 発端

#261（AMI の全部の物を 256 で組めるようにする）の最後（A = 検査の道具 #271、B = 道路・路面軌道・歩道・標識・路面表示 #272、C = 線路と高さのある部品 #273、D = この記録）。範囲は、運河（実用・景観）、踏切（線路 × 道路・水路。dat 23 個とシート 8 枚）、車庫 5 種（線路・路面軌道・道路・モノレール・運河）、操車場、モノレール（跨座式・懸垂式・電化。13 シート）、分岐の追加画像（ex）。進め方は B・C と同じ（[B](2026-11-25_ami-pak-size-256-ways.md)・[C](2026-11-25_ami-pak-size-256-rail.md)）。256 の PNG は dat と生活道路だけをコミットする（ユーザーの決定、2026-11-25）。

## 分かったこと（事実）

- **描画のコードの変更は、画素で書いた値の 4 つだけ**（倍率を掛ける前に、本体での単位を確かめた。画像の位置合わせの `,x,y` は画素なので倍にする。標識の `offset_left` のようなタイルの幅に対する比の値は D の dat に無い）:
  - 車庫・操車場の建物の絵のタイルの中心を置く位置 `BUILDING_DROP`（64px）と、dat のオフセット `BUILDING_OFFSET`（−64,−96。`depot.py` では描画に使わず、dat を書く側の `DEPOT_OFFSET` と同じ値を持つ記録。倍にしても絵は変わらない）。`ami_dat.py` の `DEPOT_OFFSET`（−128,−192）は #266 で倍にしてあり、`depot.py` の側が 128 のままだったので、256 だと絵の位置が dat と合わなかった（描く前に気づいた）。`depot.py` に `SCALE` を掛けた。
  - 景観の運河の水面の深さ `SCENIC_DEPTH_PX`（13px。高さ 1 段 16px の 13/16）と、笠石の厚みの持ち分を上へ広げる行数（1 行）。
  - ほかの D の部品（踏切・水路の踏切・操車場の寸法・モノレール）は、世界の単位か、#266 で `SCALE` 済み（`SUSP_RISE`・`POWER_RISE`）。読んで確かめた。
  - `SCALE` が 1 のとき値は同じ。**pak128 の D の 8 シート（運河 3・車庫 4・操車場）を描き直したところ、`src/` に差が出なかった**（git の差分なし）。
- `catalog.SCALED_SHEETS` に D の 52 名（運河 2・踏切のシート 8・踏切の dat 23・車庫 5・操車場 1・モノレール 13）を足し、250 名になった（`src/` の dat は `ex_donors` を除いて全部入った。`check_scaled.py` が、名前の実在と、src/ の dat の入れ忘れを CI でも確かめる）。踏切の dat は絵のシートを持たず（`SCALED_DAT_ONLY`）、踏切のシートは dat を持たない（`SCALED_NO_DAT`）。
- **分岐の追加画像（ex）**: `ami_dat.py` と `build.py` が 256 で飛ばしていた分を外した。ex の絵は線路の物のシートの中のセル（行 0 の列 10〜13 など）で、C までに 256 で描いてあった。提供用の dat（`ex_donors.dat`）を 256 でも書き、`build.py` が継ぎ足す。256 の PNG をコミットしない CI（`BUILD_SKIP_MISSING=1`）は、提供用の dat が指すシートが欠けているので継ぎ足さない。
- **256 の描画**: D の 21 シート（運河 2・車庫 5・操車場 1・モノレール 13）は Blender 16 本で約 113 秒、踏切 8 枚は約 26 秒（踏切は道路のシートの後に描く）。モノレールのトンネルは、別のシート（跨座式の地上の版）のアイコンを読むので、同時に描くと「シートが無い」で 1 度失敗した（描き直して通った）。
- **本物の 256 のシートで**:
  - `check_depot.py`（車庫の絵が箱 1 段 64px の六角形に収まるか）が、**半画素の許し無しで 96 枚とも通った**（A では 128 の拡大で確かめて、半画素の許しが要るかを残していた件の答え。要らない）。
  - `check_crossing.py`（踏切 8 枚・道路のセル 44 個）・`check_icons.py`（319 物・211 シート）・`check_cells.py`（20770 参照・13147 セル）が通った。
  - **`CHECK_256_FULL=1 bash addons/ami/check.sh`（ビルドを含む）が通った**。256 の pak の構成は 128 と同じ（`ami.pak` 182 dat。種類別の pak も同じ数）。分岐の追加画像は、`ami.pak` 41・`ami_rail.pak` 36・`ami_rail_old.pak` 40・`ami_tram.pak` 1・`ami_extra.pak` 4 個に継ぎ足した。
- **256 のシートを pak128 の大きさに縮めて、128 のシートと比べた**（B・C と同じ方法）: アイコン・カーソルのセルを除くと、運河・踏切・水路の踏切・車庫・操車場は差の大きいセルが無い（車庫の建物のセルは最大 208 画素、不透明な画素 約 7000）。モノレールは、細い線（給電レール・懸垂式の柱と梁の細い部分）のセルが大きい（最大 508 画素、不透明な画素 4124。給電レール 229 / 453）。拡大して並べて、形・位置は同じで、細い線の階段のでき方が違うだけと確かめた（C の架線と同じ）。
- **ゲームでの確認**（OTRP v64、地面は pak128 を 2 倍にした `pak256poc`、`dist256` の pak、画面は 704×560 の等倍の 3 倍）:
  - 車庫は、**敷いてからゲーム内の時間が進む（約 100 秒）まで、本体が「工事中の穴」の絵を出す**（pak128 でも同じ。AMI の絵ではない）。時間を置くと、線路・路面軌道・道路・運河の車庫が、道の行き止まりに建ち、口が道に合って、タイルの中に収まって見えた。壁つき・架線つきの壁の線路の上にも建った。
  - 運河（輪・坂・近い斜め）、運河の車庫、踏切（線路 × 道路 4 種）、水路の踏切（線路・道路 × 運河。跳ね橋）、跨座式の高架、懸垂式の高架、操車場が、地面・坂・つなぎ目に合って見えた。踏切・水路の踏切の `[check]` の行（way の名前・踏切か・速さ）は期待どおり。
  - 分岐の追加画像（ex）は、`ex_sample.nut` の `[check]` 144 行が全部 `ok`（自動で選ばれた絵が、固定の道具で選んだ絵と同じで、通常の T字と違う。線路 4 種・新旧・雪を含む）。絵そのものは目で見ていない（番号の一致で確かめた）。
  - スクリーンショットは `addons/ami/docs/261_d_pak256_misc/`。

## 推測・未確認事項

- モノレールの車庫と、モノレールのトンネルは、ゲームの画像を撮れていない（撮影の座標がずれた。絵の作りは同じ）。懸垂式の地上の版・複線・電化の重ね方は、`suspended_sample.nut` の `[check]` の行が通ったが、画像は高架の center だけ見た。
- 踏切の閉じた絵（列車が来たとき）、水路の踏切の跳ね橋が開いた絵、車両・船が通る様子は見ていない。
- 景観の運河の水面の深さ・笠石の行数（`SCALE` を掛けた 2 つ）は、検査が無く、ゲームの画像（運河の坂・輪）を目で見ただけ（回帰は CI で拾えない）。
- 雪は、運河・踏切・車庫・モノレールのどれも、ゲームで見ていない（C で、線路の高架・架線つきの壁の坂だけ見た）。
- CI は 256 の PNG が生活道路だけの状態で動き、CI の makeobj（60.10）で D の dat の組みが通るかは確かめていない（手元では警告なし）。
- 分岐の追加画像は、提供用の dat が指すシートが全部ある環境だけで継ぎ足す。CI では継ぎ足しの検査（`ex_graft.check_ex`）が 256 で走らない。

## 結果どうしたか

#261 の D の PR で、上の変更・`SCALED_SHEETS` の拡張（250 名で全部）・256 の dat（残り分と `ex_donors.dat`）・README・ゲームのスクリーンショットを入れた。A〜D で、AMI の全部の物が 256 で描き・組めるようになった（ユーザーの確認は PR のスクリーンショットで頼む）。
