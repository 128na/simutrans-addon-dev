# 調査/作業ログ: 景観に使う ISS の運河と、標識の左側通行と車両との重なりを確かめる（#173）

（2026-11-22）

## 目的 / 発端

[#173](https://github.com/128na/simutrans-addon-dev/issues/173) の残りの候補のうち、ISS の運河と標識を分析した。ユーザーが配置例と説明を用意した。

- ISS の運河: `cityscape_demo.sve` の (53,24) 付近にサンプル。説明: 景観用途で水運は基本的に想定しない。水面を標準より下に見せることで道路の下をくぐる暗渠を表せる。跳ね橋などの構造物も、軌道の下に余裕を持たせて表せる。
- 標識: pak128 標準の道路で違いが分かる `drive_left.sve`・`no_drive_left.sve`、検証用の `flat_512_left.sve`。説明: 標識は左側通行の設定の有無で表示の位置が変わる。SIS は左側通行が前提なので、既定の設定では正しい位置に来ない。置き方によって車両と重なる・下に来るので、柱の標識・門型の標識・路面のペイントの標識でそれぞれ注意が要る。景観用途なので標識としての機能は持たせず、一方通行くらいにとどめることが多い。

決まりは [cityscape.md](../reference/cityscape.md) の 1・3.2・5・6 章に書いた。

## やったこと

- 景観アドオンを多く入れた検証用のフォルダのゲーム（OTRP v64.3）を MCP つきで起動し、スクリプトで書き出し・敷き直し・撮影をした。ユーザーが別に開いていたゲームには触れていない。保存データは読むだけで、保存していない。
- 運河: サンプルの way・交差を書き出し、ISS の dat と画像（運河・交差）を読み、絵の画素を測った。同じ手順で y+40 に敷き直して比べた。
- 標識: 本体の `roadsign_t::calc_image`・`tool_build_roadsign_t`・標識の dat の書き手を読み、左側通行の有無と車両の手前・奥の表を作った。左側通行だけが違う 2 つの地図に同じ手順で標識を建て、1 つずつ建てて撮った画面と標識の無い画面の違いから、絵の範囲を比べた。バスを満載待ちの停留所で標識の上に並ばせ、重なりを撮った。
- 左側通行の設定は、スクリプトの `settings.get_drive_on_left()` で読んだ。`drive_left`・`flat_512_left` が true、`no_drive_left`・`flat_512`・`cityscape_demo` が false。

## 分かったこと（事実）

### 運河

- サンプルは、ISS の運河 `iss_wwg_0050`（x=52）と pak128 標準の `canal_030`（x=55）を並べたもの。道路（y=21）の所では運河を途切れさせ、道路（y=25）・線路（y=27）とは交差させている。北の端は T字。
- ISS の運河の南北の直線の絵は、真ん中の列で上の縁（笠石）の下に壁が 13px あり、その下が水面（256px のセル）。標準の運河は水面が地面の高さで、縁を石が囲う。
- 運河を途切れさせた所では、ISS の運河は水面が低いまま道路の縁まで続き、道路の下へくぐって見えた。標準の運河は縁の石で囲まれた行き止まりに見えた。
- ISS の交差の絵は、開いた状態が地面の高さの床・欄干・橋脚、閉じた状態が両側の床を跳ね上げた跳ね橋。2 つの運河の交差は、どちらも同じ欄干と橋脚の絵になった。交差の物は 2 つの way の速さで選ばれる（`dataobj/crossing_logic.cc` の `get_crossing`）。
- 敷き直した結果は、書き出し（way と交差の 45 行）の差分 0、画面も比べた範囲で画素まで一致した。

### 標識

- 本体: 道路の標識は、左側通行が入っていて、かつ `offset_left` が 0 でないときだけ、絵をずらし、車両の手前・奥を入れ替える。`offset_left` を書かない dat は 14。ISS は 0、SIS の信号の dat は書いていない。
- `drive_left.sve` と `no_drive_left.sve` は同じ配置で、pak128 標準の標識・信号が道路の反対側へ移っていた。
- 2 つの地図での比べ（南北・東西の道路、1 回建てたものと 2 回建てたもの）:
  - 位置が変わった: SIS の `SIS_E_RSgs_E01BF`・`SIS_L_RSsg_E01S_f`・`_b`、pak128 の `Minimum100`・`RoadClosed`・`NoEntry`・`autobahn_classic_entrance`。絵の範囲の端が横 56px・縦 28px 前後動いた。
  - 位置が変わらなかった: ISS の `iss_sr_min_speed_0050`・`iss_sr_crosswalk`・`iss_sr_direction_info_1`、tku の `tku_style_road_z0sign_01a`・`01b`、pak128 の `choose_point`。
- pak128 の `RoadClosed`・`NoEntry`・`autobahn_classic_entrance` は、参照のソースでは `offset_left=0` だが、位置が変わった。
- 左側通行なしでは、SIS の門型の標識が草地に立つか柱が車線の中に立ち、信号の柱が道路の反対側に立った。`cityscape_demo.sve`（左側通行なし）の (63,24) の門型も草地に立っている。
- バスとの重なり: 左側通行ありで、SIS の門型の板と信号の柱は下を通るバスの手前に描かれた。tku の路面の標示は、どちらの設定でも、止まったバスに重なって描かれた。バスも設定によって走る車線が変わった。
- 一方通行の SIS の門型を南北の道路に 1 回だけ建てると、北行きのバスが車庫から出なかった。もう一度建てて向きを反対にすると出た。

## 推測・未確認事項

- 交差の物が ISS の `iss_cwr_0050x0050` かは、スクリプトで読めず、絵が同じことからの推測。
- 入っている pak128 の標識の `offset_left` が参照のソースと違う理由（版の違いと推測）。
- 位置のずれの量（56px・28px）が `offset_left` のどの値によるか。本体の式（横 `2×offset_left`）とは合わせきれていない。左側用では方向ごとに逆向きにずれ、2 つの絵の組を比べているためと推測している。
- 東西の道路での車両との重なり、ISS の柱の標識と車両の重なりは撮っていない。
- 運河で船を走らせたときの見た目（跳ね橋が閉じる様子）は確かめていない。
- 検証用のフォルダの `script/` は本家 125.0.1 のままで、OTRP の `schedule_entry_x(pos, load, wait)` の形が使えない。座標で作ってから `load` を入れる本家の形で時刻表を作った。
