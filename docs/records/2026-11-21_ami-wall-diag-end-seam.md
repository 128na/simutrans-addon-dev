# 作業ログ: 斜めと行き止まりの角の壁に出る 1px の暗い縦線を消す（#63）

（2026-11-21）

## 目的 / 発端

目視なしの検査の候補 8（[記録](2026-11-21_ami-autocheck-candidates.md)の「8 番」）。見本の区画 C（斜めの階段）の下の端で、斜めのタイルの内側の壁が、行き止まりのタイルの奥の壁に当たる角に、暗い縦線（画面で約 1×3〜5px）が出る。在来線・スラブ、架線あり・なしで同じ。

## 分かったこと（事実）

- 縦線は、斜めのタイル（ne。画面で縦向き）の手前の絵（`frontdiagonal[ne]`、壁のシートのセル 6.2）にある。セルを 1 枚ずつ重ねて切り分けた。行き止まりのタイルの奥の絵（セル 0.6）には無い
- 斜めの側壁は、タイルの辺の外へ `TALL_PAD`（0.15）だけ延ばして切り抜き、辺の切り口の面を取ってある（`core.open_ends`。[way-addon.md](../reference/way-addon.md) の 2 章）。取った口から、壁の中（裏面。影で暗い）が見える。画面で縦向きの斜めの壁は、長い面が真横を向くので、口は縦 1 列・壁の高さ（シートで 9px）の暗い線になる
- 隣のタイルの壁が後から描かれれば、口は隠れる。この角では、斜めのタイルの手前の絵が、隣（東）の行き止まりのタイルの奥の壁の絵より後に描かれるので、口が見えた。上の端の角は、口がカメラの反対を向くので見えない
- 同じ線は区画 B（輪と十字）の T字・十字の角や、高架（VS）、近い斜めの複線（W2a）などにもあった（直した後の撮影の差分で分かった）

## 試したこと

1. 高さのある部品の層を、全部、裏面を描かずに描いた（EEVEE の材質の `use_backface_culling`）。口は透明になり、角の縦線は消えた。しかし行き止まりの手前の絵（セル 4.6・4.7）の端の壁が丸ごと消えた。端の壁は基準面の分（在来線の路盤で約 0.31）だけタイルの外へ動き、外の面ごと切り口として取られていて、口から見える壁の中が外の面の代わりになっていた
2. 斜めのタイルの側壁（`wallL`・`wallR` で横幅の倍率が 1 より小さいもの）だけにした。シートの差分は「口の暗い列が透明になる」だけになったが、ゲームの区画 W2b（近い斜めの複線。画面で横向き）で、斜めの壁の端が 2px 短くなり、隣の行き止まりの壁との間に草が出た。画面で横向きの斜めでは、口が長い面の端より画面で約 2px 先へ出ていて、その暗い色が切り口の面の代わりになっていた
3. 画面で縦向きの斜め（北東⇔南西に延びる側壁）だけにした（採用）。頂点の xy の共分散の符号で向きを見る（`cells._screen_vertical`）

## 直したこと

- `tools/blender/sheetlib/cells.py`: `render_layers` に `cull_diag_wall_ends` を足した。真なら、高さのある部品の層を描く間だけ、画面で縦向きの斜めの側壁の材質を、裏面を描かない写しに差し替える（材質は名前で共有されるので写しを作り、描いた後に戻す）
- `tools/blender/sheetlib/sheetlib.py`: `track_sheet` がプロファイルの `cull_diag_wall_ends` を渡す（既定は偽。blender-poc のシートは変えない）
- `addons/ami/blender/render.py`: 線路の基盤の版のプロファイルで真にした（架線つきの壁・近い斜めの分け合うタイル用の壁も、このプロファイルから作る）

## 確かめたこと

- シート（`tools/blender/sheet_diff.py` を `ALL=1` で、直す前のシートと比べた）: 描き直したのは線路の基盤 12・高架 12・橋 3・架線つきの壁 4・分け合うタイル用の架線つきの壁 2 の 33 対象。変わったのは壁の way-object の 8 枚（`ami_wall_rail_{single,back,front}`・`_{single,back,front}_catenary`・`ami_wall_rail_twin_catenary_{back,front}`）だけ。way のシート（基盤・高架・橋）と `ami_wall_rail_center`・`_center_catenary` は画素で同じ
- 変わったセルは、どれも縦 1×9px の 1 列が不透明から透明になっただけ（色の差 0、透明から不透明 0、消えた画素の色は平均 RGB 113 前後の暗い灰色）。セルは斜め（行 2・6 の列 0・2）、斜めの形のカーブ（列 5・7）、T字・十字の斜めの部分（行 2・3・6・7 の列 6〜14 の一部）
- ゲーム（`addon_check` の `OTRPv64_3.exe` を `ingame/sample_parallel.sh` で `work/` の写しから起動、ポート 47310〜47317、`flat_512.sve`、ズーム 3）: 在来線・スラブ・弾性まくらぎ直結軌道の見本を、直す前と後でそれぞれ全 208 画面撮り、上のツールバーと下の状態行を除いて画素で比べた
  - 変わった画面は 3 種で 348 画面（1 種あたり 116）、差分の塊は 1128 個。どれも 12px 以下で、暗い点・縦線（平均 RGB 104〜124）が明るくなった（壁の面 160 前後、雪の壁 166〜173、スラブの道床 96〜128 など）もの。暗くなった塊・草や雪の色が出た塊は 0
  - 区画 C の下の端の角（在来線・スラブ・弾性まくらぎ直結軌道、壁だけ・架線つき、温暖側・降雪側）で縦線が消えた
- 画像（`addons/ami/docs/wallseam63_*.png`。上が前|後の画面の切り抜きを 2 倍、赤い枠が見る所、下が見る所の 10 倍）
