# 操車場の建設費が 576 cr・640 cr に見えた理由（#160）

操車場 `ami_rail_yard` の dat は `cost=60000`（600 cr）だが、ゲームで建てると所持金の減りが 576 cr・640 cr になった（記録 `2026-11-22_ami-rail-yard.md`）。理由を調べた。

## 結論

建設費はずれていない。測り方が原因だった。スクリプトの `get_current_cash()` は 32 ビット浮動小数で、検証用の保存データ `flat_512` は残高が大きく負（約 -6.5×10^8 cr）なので、この大きさでは数値の刻みが 64 cr になり、差が 64 の倍数に丸められる。

## 調べたこと

- 本体（`E:\addon_dev\simutrans`、2026-11-22）の費用の式: `simtool.cc` の駅の建設（5816 行付近）は `-desc->get_price(welt) * get_x() * get_y() * platforms`。`building_desc_t::get_price`（`descriptor/building_desc.cc`）は、dat に `cost` があればその値をそのまま返す（`building_reader.cc` が読んだ値を持つ）。公共でない所有者の駅だけ維持費 × 60 が足されるが、自分の駅には掛からない。式からは 600 cr になる
- 仮説: 残高が大きくて float の刻みに丸められる。`get_current_cash()` は `get_account_balance() / 100.0`（`script/api/api_player.cc`）で、Squirrel の float は 32 ビット。5.4×10^8〜1.07×10^9 は 1 刻みが 2^6 = 64、576 = 9×64、640 = 10×64
- 実測（`OTRPv64_3.exe`、`flat_512`、dist/ami.pak、`addons/ami/ingame/cost_probe.sh`）。同じ線路に連続して建てた結果:

  | 建物 | 所持金（float）の差 | 純資産（整数）の差 |
  |---|---|---|
  | 操車場 1 個目 | 640 cr | 60000（600 cr） |
  | 操車場 2・3・4 個目 | 576 cr | 60000 |
  | 乗客の駅（pak128 の一覧の先頭） | 640 cr | 60000 |

  - 所持金の差は建てる位置で変わり、純資産の差は毎回 60000。乗客の駅も同じずれ方をしたので、操車場の値の問題ではない
  - 線路 31 タイルの建設費も 4608 cr（= 72×64）と、64 の倍数で出た
  - 降雪側（原点 276,20）の 640 cr は測り直していない。残高が同じ範囲なら同じ丸めで説明できる
- 維持費: dat の `maintenance=1800` が、スクリプトの `get_maintenance()` では 3600 になる。API が月の長さで掛ける（`scale_with_month_length`、`script/api/api_obj_desc.cc`）。保存データの月の長さの設定のためで、dat の値は変わっていない

## ほかの駅・車庫

- 同じ測り方をした駅・車庫の費用のずれは、すべてこの丸めで説明できる（乗客の駅で確認した）。dat の `cost` を直す必要は無い
- 車庫（`ami_rail_depot`、`cost=850000`）は費用の式が別（`tool_build_depot_t`、`simtool.cc`）で、測っていない。必要なら純資産の差で測る

## 確かめていないこと

- 降雪側・車庫の実測
- 残高が小さい保存データでの、所持金の差そのもの（純資産の差で足りるため）
