# 調査/作業ログ: pak の大きさの設定と、生活道路を 256 で組める所まで（#266）

## 目的 / 発端

#261（pak の大きさを設定 1 つで選べるようにする）の 1 本目。pak256（タイル 256px の新しい pakset）が、街が建てる道路に AMI の生活道路（`ami_road_local` の通常の版）を使うため（128-bit-net/pak256 の #7）。ユーザーの判断（2026-11-25、判断 19・22）で、#261 を分けて、設定と共通の値と道路 1 種を先に出し、256 版の pak だけを入れた zip を別に作れるようにした。

## 分かったこと（事実）

- 設定は `tools/blender/sheet_settings.py` の `SHEET_PAK_SIZE`（タイルの幅の画素数。既定 128）1 つ。`SCALE`（pak128 に対する整数の倍率）・`PAKSET`（makeobj の大きさ。128 は `pak256`、256 は `pak512`）・`SUFFIX`（出力先の後ろ。256 は `256`）を出す。Blender を使わないので `ami_dat.py`・`build.py`・`release.py` も読む。128 の整数倍だけを受け付け、それ以外は止める（整数でない倍率は #261 の残り）。
- 世界の単位（タイル 1 辺 = 10）で決めた形は、倍率を変えても同じ。変わるのは画素数で、`CELL`（256 → 512）と高さ 1 段の画素数（16 → 32）で、`H`（世界の単位での高さ）は同じ。画素で書いた値（`GROUND_CY`・`ROAD_CY`・基準位置 128・`BALLAST_DY`・`DIAG_PX`・持ち分を広げる行数・基準面の下げ幅・`spill`・dat の位置合わせ）に `SCALE` を掛けた。`SCALE` が 1 のとき、掛けた式の値は掛けない式と同じなので絵は変わらない。
- **pak128 の全シートが変更前のコードで描いた絵と全画素で一致した**（2026-11-25）。変更前は `origin/main`（`bee768a`）の別の worktree で、変更後は変更したコードで、AMI の全 221 シートを描き（`render_parallel.py` で並べて描き、踏切は道路の後、最後に `icons.py`）、`sheet_diff.py` で比べた（221 組すべて「透過の範囲の差 0 px・色の差 0 px」）。RGB の全画素の完全一致（透明色を含む）も別に確かめた。シートの横の控え（`*.road_cells.txt`・`*.icon_sources.txt`）も同じ。blender-poc の 28 シート（`icons` の見本を除く）も全画素で一致した。
  - 比べる前の確かめ: 変更前の描画の対象名は `src/*.png` の名前から作ったので、`ami_wall_rail_*` の 8 枚は対象でなく失敗（「unknown target」）になった。これらのシートは `ami_rail_*_base_*` の対象が書く（ログで確かめた）ので、比べる範囲から漏れていない。
  - 変更前のコードの描画は、コミット済みの AMI のシートと全画素で同じだった。blender-poc は 4 枚（`track_wall_single`・`track_wall_back`・`track_elev_single`・`track_elev_back`）が、変更前のコードの描画とコミット済みのシートで違う（前からのずれ。この作業の変更ではない）。
- **256（pak512 で組む）**: `ami_road_local` を描き、makeobj `pak512` が警告なしで通った（`build.py` はログの警告・エラーで止まる）。シートを pak128 の大きさに縮めて、今の pak128 のシートと比べると、不透明な範囲の差は直線・斜め・T字・十字・カーブ・近い斜めでほぼ 0、坂のセルで 100 画素前後（縁の階段の違い）。
- **持ち分マスクを大きさに合わせて菱形から引き直すと、坂の継ぎ目に草の画素が出た**: 256 のゲームの確認用の地面（`pak256poc`）は pak128 の地面を画素ごとに 2 倍にしたもので、菱形の縁の階段は 4×2 の段。マスクを 2×1 の細かい段で引くと、坂のタイルと隣のタイルの継ぎ目に、1 画素の草が 4 画素おき（地面の段ごと）に出た（ゲームの画面で、坂の道の継ぎ目に沿って約 20 画素）。pak128 の絵を最近傍で 2 倍に引き伸ばした絵では出なかったので、原因は絵でなく階段の違い。マスクを pak128 の大きさで作って最近傍で拡大する（`cells._ground_mask`）と、出なくなった（ゲームで確認）。ゲームを使わない合成（セルを並べて隙間を数える）では 1 画素ほどしか見つからなかった。ゲームでだけ見える（坂の地面を後から描き直す順序が関わる、と推測。未確認）。
- アイコン（32px）は大きさによらず 32px のまま（pak256 のツールバーのアイコンの大きさは未決: `pak256/docs/roadmap.md`、`config/menuconf.tab` は `icon_width = 32`）。アイコンの絵にするセルを切る大きさと、カーソルの札の位置・大きさは `SCALE` 倍にした。
- 256 の確認の手順: `ingame/game_lib.sh` に `PAKSET`・`PAKSET_SRC` を足した。`pak256poc` は 1.6GB あるので写さず、写しの中にジャンクションを作る。写しを消すときは先にジャンクションだけ外す（`rm -rf` が元の中身を消さないように）。外した後に元の `pak256poc` が残っていることを確かめた。
- 256 の zip は `ami-256-<版>.zip`（`release.py` を `SHEET_PAK_SIZE=256` で動かす）。256 の pak だけを zip の直下に置く。pak256 の `tools/fetch_ami.py` は zip の中の `.pak` を全部取る。

## 推測・未確認事項

- 雪（シートの行 4〜7・dat の `[1]`）は同じ作りで描いて 256 の dat にも入れたが、ゲームで見ていない（#261 の残り）。
- 基盤・高架・橋・トンネル・壁・踏切・ほかの way・標識・カーソルは、画素で書いた値を大きさに合わせていないので、256 では描けない（`catalog.SCALED_SHEETS` 以外は止める）。`sheetlib` の画素で書いた値のうち、行数や基準位置のように明らかに画素の物は `SCALE` を掛けたが、256 で確かめていない。
- 地面の階段が細かい版（pak256 で描き直した地面）に替わると、マスクの拡大の前提が変わる。そのときは、拡大をやめて引き直すか、見直す。
- 横向きの斜めのレールが細くなる件・倍率が整数でない大きさの丸め・高さ 1 段の画素数を pak の `tile_height` から求めるか、は #261 の残り。

## 結果どうしたか

#266 の PR で、設定・共通の値・dat・build・release・check.sh（256 の dat の書き忘れと 256 の pak のビルド）・アイコン・README・`src256/`（256 のシートと dat。生活道路 1 種）を入れた。256 のゲームでの見え方は `addons/ami/docs/266_pak256_road_local/` のスクリーンショット。残りは #261。
