# 調査/作業ログ: blender-poc のタイルのつなぎ目（道路・高速道路・線路）

（2026-11-12〜13 の作業。対象は [addons/blender-poc](../../addons/blender-poc/README.md)。
手順や数値の詳細はアドオンの README の各節にある。この記録は、何が原因で何が分かったかを残す）

## 目的 / 発端

iss のインフラアドオン（pak128、256px セル）を Blender で作り直す検証で、
つなぎ目を「POC で完璧に決め切る」ことを目標にした。ゲームで見て、次の順に直した。

1. 高速道路の直線↔斜めの段と、白線の切れ目
2. SIS の道路・pak128 標準の道路（Road_050）とつないだ所の、草の線と 1px の段
3. 線路の直線↔斜めの角の、道床の段と草の尖り（旧描画位置、新描画位置の横向きの斜め）
4. 新描画位置の線路の、画面で縦向きの斜め（sw・ne）↔直線の角のずれ

## 分かったこと（事実）

### 本体（OTRP）の描き方

- 各タイルは地面を描いてから物を描く。平らな地面は先に描かれるので、奥のタイルが手前へはみ出した絵は、
  およそ 1 行（＋半行）までしか残らない。それより深い行は、手前のタイルの地面が消す。
- 坂のタイルは地面を物と一緒に後から描き直すので、奥からのはみ出しを消す。
- そのため、どの画素をどのタイルが描くか（持ち分）は、ゲーム内の地面の菱形
  （`render.py` の `GROUND_CY = 127`、画素の中心で判定）で決めるのが合う。

### 道路

- SIS と pak128 標準の道路は、菱形を地面より 1px 下にずらした絵で描かれている。自分の菱形の上の 1 行は描かず、
  奥のタイルのはみ出しで埋めている。
- 移植版も絵と持ち分を一緒に 1px 下げた（`ROAD_CY = 128`）。手前の縁（下の2辺）は半行広げた。
  坂では、地面の位置の菱形も持ち分に足した。これで SIS の高速道路・SIS の一般道・Road_050 のどれとも、
  奥・手前の継ぎ目に草の線や段が出なくなった。
- 斜めの車道・縁石・白線は、経路からの距離を直線の 1/√2 にすると、タイルの辺で直線と同じ点を通る。
  横向きの斜めの白線は「整数＋0.5」px に丸めると、画素の行に収まる。

### 線路の描画位置（pak128 と iss のソースを測った結果）

- 測った元絵は次の三つ。
  - pak128 の `infrastructure/rail_tracks/rail_100_tracks.png`
    （直線 1.5・1.6、縦向きの斜め 3.6・4.1、横向きの斜め 3.7・4.0）
  - iss の `src/way/rail/` の各層（`standard_fix.png`・`standard_slab.png`・`standard_concrete.png` など）
  - 移植版の `src/track.png`
- 直線のレールの位置は、Rail_100・iss・移植版の新描画位置の三つで同じだった。
  直線を横切る明るさの断面で見ると、レール上面の明るい行が同じ位置にある。
- iss のレール・まくらぎの層は、直線も斜めもタイルの中心に描かれている。縦向きの斜めは辺の中点の真上にある。
  iss の組み立て（`definitions.json` の層の重ね合わせ、`imageManager.py` の `alpha_composite`）では、どの層もずらしていない。
- Rail_100 の道床は、地面の位置からほとんど動いていない（直線で 1px ほど下）。縦向きの斜めもほぼタイルの中心にある。
- 移植版の新描画位置は、道床まで丸ごと 4px 下げていた。絵を下げることは、マップ上で線路全体を南東へずらすことと同じになる。
  直線は辺を横切る点が辺に沿ってずれるが、縦向きの斜めにはそのずれに合わせられる位置が無い。これが角のずれの原因だった。
- 持ち分も 4 行下げる案は、ゲームで、手前のタイルへはみ出した 2〜4 行目を手前の地面が消し、すべての継ぎ目に草の線が出た。
  斜めの端だけ辺に直角にする案も試したが、斜めの道床がタイルごとに大きく波打った。どちらもやめた。

### 確かめ方

- `blender/ingame_diff.py`: ゲームの画面と、シートのセルを同じ位置・順番で貼った予想図を比べる。
  `ingame/capture_check.sh` で、見本の 6 か所を等倍で撮って比べる。
- `ingame/sis_check.sh`: SIS・pak128 標準とのつなぎ目を撮る。
- 線路は模様がくり返すので、道に沿ってずれた所で位置が合ってしまうことがある。
  そのため `INGAME_LOCATE=x,y` で位置を直接与えられるようにした。

## 推測・未確認事項

- Rail_100 の道床の「1px ほど下」は、道床の不透明な画素の平均から見積もった値。
  道床に厚みと陰があるので、地面の位置との差は ±1px 程度の誤差を含む。
- レールには高さがあるので、新描画位置でレールだけを下げても、辺を横切る点のずれは 1〜2px と見積もった。
  ゲームの画面で角に目立つ段は見えないが、レールの位置を画素単位では測っていない。
- 坂のタイルでは、レールを地面の上で水平に動かしたあとで坂の高さを当てている。
  そのため画面での下げ幅は、平らな所の 4px と ±1px ほど違うはず。ゲームの予想図との違いは 0px だったが、
  坂のつなぎ目のレールの段そのものは測っていない。

## 結果どうしたか

- 道路・高速道路: 絵と持ち分を 1px 下げ、SIS の決まりに合わせた（4f7135a）。
  斜めの位置もそろえた（e6499f6）。持ち分は地面の菱形で決めた（cf3015a）。
- 線路: 斜めの道床の幅を 1/√2 にし、辺で直線とそろえた（5f15329）。
  新描画位置では、道床を旧と同じ地面の位置に描き、レールとまくらぎだけを画面で 4px 下げた
  （横向きの斜めは 2px。`render.py` の `BALLAST_DY`・`build_track(rail_drop=)`、47f42f7。
  その前の横向きの斜めだけの対処は 8dbcfe3）。
- ゲームでの確認: 線路の新・旧の 12 枚すべてで、ゲームと予想図の違いは 0px だった。
  新に残った形の候補 6 点は、行き止まりの端の角だった。
  道路・高速道路は 12 枚のうち 10 枚が 0px だった。坂の十字の 2 枚の差は予想図側の再現漏れで、ゲームの画面は正しい。
- 確認画像は `addons/blender-poc/docs/` にある（`seam_fix_track_vdiag.png`、`seam_new_rail100_ns.png`、
  `rail100_cells.png`、`seam_sis_expressway.png`、`seam_default_road.png` など）。
