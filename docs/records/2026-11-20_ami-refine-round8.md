## 高架の端の段（#44 の 7 番）の原因

- 在来線の基盤と壁は、どちらも基準面 `bed`（画面で 2px 下げる）に乗る。`datum_move` で測ると、動きは (0.3125, −0.3125, 0)。どちらもタイルの軸の向きに 0.31 手前へ動く
- 壁は動いた後に、タイルの辺の近く（`TALL_PAD` 0.15）で切り抜かれる。基盤は、端の壁の外の面（タイルの端）で削ってから動かし、タイルより 0.6（`CLIP_PAD`）大きく切り抜かれる
- そのため、カメラの側を向く端（外向きの動きが正）でだけ、基盤が動いた 0.31 の分、壁の外の面より外に残った。奥を向く端では、基盤も壁も内へ動くので段が出ない。ラウンド 7 で 0.3 削ると面がそろった（0.6 ではへこんだ）ことと合う
- 直し方: `assemble._beyond_prisms` の `endw_edge`（タイルの端に立つ端の壁）で、削られる物の動き（`ref_move`）のうちタイルの外向きの分だけ、内で削る。動きから求めるので、奥を向く端と、動かない基準面の版は変わらない
- スラブ軌道の基盤・高架の行き止まりにも同じ段があり、同じく消えた（`addons/ami/docs/rail_ballast_round8_slab_end.png`。シートのセルで、上が前、下が基盤だけを直した後。南西・南東を向く端、4 倍）。コンクリート道床ののぞき（下の章）も直した後のゲームの画面は `rail_ballast_round8_slab_end_game.png`（左から 2026-11-19 の見本、基盤だけを直した後、コンクリート道床も直した後。上が南東、下が南西を向く端、9 倍）

## ラウンド 5〜7 に入っていた欠陥（本番に入れて分かった）

- ラウンド 5 の道床の肩（`round.py` の `shoulder`）は、道床の形を経路に沿う断面だけで作り直していた。本番の道床は、行き止まりでタイルの端まで延ばす形（`bed_to_edge_shape`。2026-11-17 のユーザーの指摘）だったのが外れていた
  - 地上の行き止まりで、道床が車止めのすぐ奥で切れた（`addons/ami/docs/rail_ballast_round8_end_cells.png`。上がラウンド 7、下が本番）
  - 壁の中の行き止まりで、車止めの奥に草がのぞいた（`rail_ballast_round8_end_grass.png`・`rail_ballast_round8_W3.png`。左がラウンド 7、右が本番）
  - ラウンド 5〜7 の評価（区画 B・H3・VS_B など）では見落としていた
- 本番では、肩の断面のまま `bed_to_edge` でタイルの端まで延ばした
- 延ばした最初の版では、高架の行き止まりで、端の壁の外の面の下に砕石がのぞいた。道床をタイルの端より 0.5 外まで延ばしていて、基盤と同じく手前へ 0.31 動くため。壁のある版（基盤・高架・橋。`render.py` の `_EDGE_BED`）では、道床を端の壁の内側の面で止めた
- 高速線（スラブ軌道）のコンクリート道床（`slab_bed`）も、行き止まりでタイルの端より 0.5 外まで延びていた。基盤の段を直した後のゲームの画面で、カメラを向く端の壁の外の面の下に、明るい 2〜3px の帯としてのぞいた。コンクリート道床は壁の 2 倍（4px、0.625）手前へ動くので、止める位置を壁と道床の動きの差から求めた（`render.py` の `_stop_at_end_wall`。動いた後の道床の端が、動いた後の壁の内側の面に来る。在来線の道床は壁と同じ動きなので、`WALL_W` 内で止めるのと同じ）。`sheetlib` の `bed_to_edge`・`slab_bed_shape` は、止める位置を経路の向きから求める関数も受ける
