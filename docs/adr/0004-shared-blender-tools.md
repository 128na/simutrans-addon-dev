# ADR: Blender の描画の道具を tools/ に移し、blender-poc と AMI で共通に使う

> ステータス: Accepted (2026-11-15)
> 由来: [ADR 0002](0002-ami-scope.md)

## 背景と問題

blender-poc の `blender/render.py`（約 2400 行）が、形の組み立て・持ち分・描画・シート化をまとめて持っている。
`blender/` には、判定や比較の道具（`seam_judge.py`・`ingame_diff.py`・`sheet_diff.py`・`slope_measure.py` など）と、
`ingame/` の見本のスクリプトもある。AMI はこれらを使って絵を描き、確かめる。

リポジトリの決まり（`AGENTS.md`）では、2 つ目のアドオンが別のアドオンの道具を使い始めるときは、その変更の最初のコミットで `tools/` へ移す。

## 決定

- AMI の実装の最初のコミットで、blender-poc の描画と判定の道具を `tools/` へ移し、blender-poc と AMI の両方から使う
- アドオンごとの設定（シート名・部品の組み合わせ・dat の書き出しの中身）はアドオンの中に置き、`tools/` には持たせない
- 移した後も、blender-poc の pak が前と同じ絵で描けることを、前のシートとの全画素の比較で確かめる

## 検討した代替案と却下理由

- 道具ごと AMI に移し、blender-poc を凍結する → 決まりでは、凍結しても別のアドオンの道具を参照し続ける形になる。POC の見本で作りを確かめ直す道も無くなる
- AMI にコピーを持たせる → 同じ道具が 2 か所にでき、直した決まり（持ち分・基準面）が片方にしか入らない

## 影響・トレードオフ

- 最初のコミットが大きくなる（道具の移動と、blender-poc からの呼び出しの付け替え）
- どこまでが共通で、どこからがアドオンの設定かを、移すときに分ける必要がある。分け方は移すときに決め、`tools/` の README に書く
