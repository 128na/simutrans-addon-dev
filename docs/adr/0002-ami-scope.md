# ADR: blender-poc の成果を新しいアドオン AMI として作り、線路 3 種・道路 3 種から始める

> ステータス: Accepted (2026-11-15)
> 由来: [addons/blender-poc](../../addons/blender-poc/README.md) の POC の完了

## 背景と問題

blender-poc で、Blender のスクリプトで way アドオン（線路・道路・高速道路、壁・高架・橋・トンネル、雪・汚れ）を描けることを確かめた。
POC は検証用で、名前（`bpoc_*`）・値（速度・費用・登場年）・ライセンスが仮のまま。配る形にするには、移す先と範囲を決める必要があった。

- iss（Illustrator で作ったインフラアドオン、CC BY 4.0）は更新を止めている
- POC の線路は 1 種類（100km/h）、道路は一般道（歩道付き、50km/h）と高速道路（120km/h）だけ
- 動かす版は、POC は OTRP で確かめてきた。本家 125.0.1 で `bpoc.pak`（分岐の絵・近い斜めを含む）が動くことはユーザーが確かめた（2026-11-15）

## 決定

- 新しいアドオン **AMI**（AI Marunage Infrastructure）を `addons/ami/` に作る。オブジェクト名の頭は `ami_`。iss・blender-poc の名前は引き継がない（置き換えの互換は作らない）
- ライセンスは CC BY 4.0
- 対象は pak128 の本家 125.0.1 と OTRP。OTRP だけで使う絵（分岐の switch 画像・近い斜め）も入れ、本家では使われないだけにする
- 収録は次の 6 種類から始める

  | 種類 | waytype | 速度 | 見た目 |
  |---|---|---|---|
  | 路面軌道 | tram（道路に重ねる） | 60 km/h | コンクリートで固めた線路 |
  | 在来線 | track | 160 km/h | バラスト軌道 |
  | 高速線 | track | 480 km/h | スラブ軌道 |
  | 生活道路 | road | 40 km/h | 中央線なし |
  | 一般道路 | road | 120 km/h | 中央線は白線 |
  | 高速道路 | road | 360 km/h | 中央線は破線 |

- 道路 3 種は、どれも POC の高速道路と同じ断面（片側 1 車線、タイル全面が路面、歩道なし）にする。違うのは中央線だけ
- 壁・高架・橋・トンネルは、在来線・高速線と道路 3 種に作る。路面軌道には作らない。作りは [ADR 0003](0003-ami-walls-base-piers-as-separate-objects.md)
- 分岐の絵（switch 画像の 1・2 の 10 枚）は全種類に入れる。近い斜めは、壁の無い way の全種類に入れる
- 線路の描画位置は、新描画位置（今の pak128・iss に合う）で全部を作り終えてから、旧描画位置（SIS に合う）をまとめて作る。旧は別の PR に分けてよい
- POC の穴（`ACCEPTANCE.md` の × と ？）は、初版で直して確かめる。新しい作りに当て直した扱いは `addons/ami/ACCEPTANCE.md`
- 配布の pak は、全部入りのまとめと、種類ごとの pak の両方を作る（iss と同じ）
- 速度以外の値（費用・維持費・登場年）は、実装の前に一覧で決める
- 架線は、線路の壁の way-object に持たせる形で作る。壁の無い `center` の版が架線だけの way-object になる（[ADR 0003](0003-ami-walls-base-piers-as-separate-objects.md)）
- 建物（blender-poc の料金所）は移さない

## 検討した代替案と却下理由

- iss の後継にして名前を引き継ぐ → iss と作りが変わる（壁・橋脚の分け方、版の並び）ので、`compat.tab` で置き換えても見た目と使い方が合わない
- blender-poc をそのまま育てる → POC は検証の道具・試作（`ex_proto` など）・経緯の記録を抱えていて、配る物と混ざる
- OTRP だけを対象にする → 本家 125.0.1 で動くことを確かめたので、狭める理由が無い
- 新描画位置と旧描画位置を並べて作る → 直すたびに 2 倍の絵を描き直すことになる。新で作りを決めてから旧を足す

## 影響・トレードオフ

- 路面軌道とスラブ軌道は POC に無い見た目で、見本の画像をユーザーから受け取ってから作る
- 道路を 1 つの断面にそろえるので、生活道路も高速道路と同じ幅になる。幅を変えたくなったら、この ADR を書き直す
- 動作の検証は OTRP だけで行う。makeobj は本家と同じもの（60.12）なので、pak の形は本家と互換になる。本家での確認は、配る前などにユーザーが必要と判断したときだけ行う
