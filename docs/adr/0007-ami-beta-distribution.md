# ADR: AMI の第 1 弾は、種類別の pak 4 つを入れた zip を GitHub のプレリリースで配る

> ステータス: Accepted (2026-11-21)
> 由来: [#91](https://github.com/128na/simutrans-addon-dev/issues/91)（第 1 弾をベータ版として出す）・[#61](https://github.com/128na/simutrans-addon-dev/issues/61)・[ADR 0002](0002-ami-scope.md)

## 背景と問題

ロードマップ（#61）の第 1 弾を、ベータ版として出すことになった。基準は「多少課題があってもゲーム内で動作すれば OK」（2026-11-21、ユーザーの決定）。

[ADR 0002](0002-ami-scope.md) は、配布の pak を全部入りのまとめ（`ami.pak`）と種類ごとの pak の両方で作ると決めた。ただ、zip に何を入れて、どこで配るかは決めていなかった。

- 全部入りと種類別を同じフォルダに置くと、同じ物を二重に読む。ゲームはログに `object way::<名前> is overlaid!` を出して上書きする（`ingame/beta_check.sh` の対照で確かめた。2026-11-21）
- OTRP だけで使う絵（分岐の絵・近い斜め・分岐の追加画像）を含む pak も、本家 125.0.1 は読み込んで標準の絵で表示する（[way-addon.md](../reference/way-addon.md) の 9.5）
- 手本の iss は、GitHub のリリースで zip を配り、版を `beta.{n}` のように付けていた

## 決定

2026-11-21 のユーザーの決定（#91 で 4 件とも作業者のおすすめを採った）。

- 出す場所は、このリポジトリの GitHub のリリースにする。ベータの間はプレリリースにする
- 版の名前は `beta.<n>` にする。モノレポなので、タグは `ami-beta.<n>`、zip は `ami-beta.<n>.zip` にする。第 1 弾は `beta.1`
- 配る zip には、種類別の 4 つ（`ami_rail`・`ami_road`・`ami_tram`・`ami_extra`）を入れる。全部入りの `ami.pak` は入れない。ビルドでは、ADR 0002 のとおり全部入りも作る（検証に使う）
- 本家 125.0.1 も対象に含める。本家用の pak は分けない。OTRP だけの絵は、本家では使われないだけにする。配る前に、本家での読み込みをユーザーが確かめる
- zip の中身は `pak128/` の pak、遊ぶ人向けの説明（`ami_readme.txt`）、ライセンスの表記（`ami_license.txt`、CC BY 4.0）。作り方は `addons/ami/release.py`

## 検討した代替案と却下理由

- 全部入りの `ami.pak` だけを配る → 入れ方は簡単だが、使う種類を選べない
- zip に全部入りと種類別を別のフォルダで入れ、どちらかを選ばせる → 遊ぶ人が両方を入れると二重に読む
- アドオンの投稿サイトだけに出す → 作業者が出したり取り消したりできない。投稿サイトへは、リリースの後に足せる

## 影響・トレードオフ

- 種類別の pak を選んで入れられる。ただし `ami_extra.pak`（壁・橋脚・歩道）は線路・道路と組で使うので、readme で一緒に入れるよう頼む
- 正式版までに名前が変わると、ベータの版で作ったセーブデータの物は読み込めなくなることがある。readme でそのことを知らせる
