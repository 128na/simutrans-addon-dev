# ADR: AMI の描画は、エンティティごとの部品・レイアウト検証用モード・設定値・並列で組む

> ステータス: Accepted (2026-11-15)
> 由来: [ADR 0002](0002-ami-scope.md)・[ADR 0004](0004-shared-blender-tools.md)

## 背景と問題

blender-poc の `render.py` は、部品（`Part`）と基準面（`Datum`）で形を組み立てるところまで整えたが、次の点が残っていた。

- 部品が 1 本の長いスクリプトにまとまっていて、線路・道路・壁など物ごとの境目が読み取りにくい
- 確認用の色（`BPOC_DEBUG_COLORS`）は壁・基盤・道床の 3 色だけで、部品ごとには見分けられない。塗りの後で形の不具合に気づき、描き直すことがあった
- 寸法や位置の数値が、部品の中に直接書かれている所がある
- 並列で描く数の上限を 8 に固定していた

AMI は種類と版が POC より多く（線路 3 種・道路 3 種・壁・架線・橋脚・歩道）、描き直しの回数も増える。

## 決定

- **エンティティごとの部品**: 部品は、それが表す物（レール・締結装置・軌道スラブ・てん充層・コンクリート道床・バラスト・まくらぎ・路面・白線・壁・架線・基盤・躯体・橋脚・歩道など）ごとにまとめる。ファイルの分け方は実装で決めてよい
- **レイアウト検証用モード**: 部品ごとに、画像で見分けやすい単色（例: `rgb=(255,0,0)`）で塗るモードを持つ。塗り（材質・汚れ・雪）を実装する前に、このモードで部品の配置・部品の組み合わせ・タイルどうしの接合を確かめる。モードは、後で手直しするときにも使うので残す
- **設定値**: 寸法・位置・色・速度など調整する数値は、部品の中に直接書かず、名前の付いた定数や設定にまとめる
- **並列**: 時間のかかる処理（シートの描画など）は、別のプロセスで同時に動かす。同時に動かす数は設定値にし、作業する PC（i9-12900F・メモリ 128GB・RTX 4070 Ti）に合わせて決める

## 検討した代替案と却下理由

- POC の確認用の色（3 色）のまま進める → 部品の重なりや欠けを、どの部品の問題か画像で分けられない
- 塗りを先に作り、形の不具合はゲームで見つける → POC で、塗りの後に形を直して全部描き直すことが繰り返し起きた
- 並列の上限を POC と同じ 8 に固定する → PC に余裕があり、種類が増えると描く時間が伸びる

## 影響・トレードオフ

- レイアウト検証用モードの色の割り当て表を、部品を足すたびに保つ必要がある
- 定数にまとめる分、最初の実装（`tools/` への移動）で POC のコードの書き直しが増える。書き直した後も、blender-poc のシートが前と同じ絵になることを全画素の比較で確かめる（[ADR 0004](0004-shared-blender-tools.md)）
