# ADR: AMI の範囲を第 2 弾で広げ、モノレール・運河・車庫・操車場と景観・補助の物を足す

> ステータス: Accepted (2026-11-21)
> 由来: [#102](https://github.com/128na/simutrans-addon-dev/issues/102)（ADR 0002 の書き直し）・[#61](https://github.com/128na/simutrans-addon-dev/issues/61)（バリエーションのロードマップ）・[ADR 0002](0002-ami-scope.md)

## 背景と問題

[ADR 0002](0002-ami-scope.md) は、AMI の範囲を線路・道路・路面軌道の 3 系統の way と、その壁・高架・橋・トンネルに限った。建物は入れなかった。ロードマップ（#61）では次のように決めた（2026-11-21、ユーザーの決定）。

- 第 1 弾は、この範囲の中で作る。ベータ版 ami-beta.1 として出した（[ADR 0007](0007-ami-beta-distribution.md)）
- 範囲を広げる（新しい waytype・建物）のは第 2 弾で、ADR 0002 を書き直してから着手する

#61 の表では、iss（`refs/iss/src`、CC BY 4.0）の物のうち、第 2 弾の候補を次の 2 つに分けた。

- 軌道系: 狭軌・モノレール・リニア・運河・車庫・操車場・水路の踏切
- 景観・補助: 歩道・道路の側壁と中央分離帯・路面表示・電柱・道路標識・盛土など

この ADR を決めるときに、次のことを確かめた（2026-11-21）。

- 1 タイルに置ける way は 2 本まで（本体の `boden/grund.h` の `has_way2`）。違う waytype の way が交わるには crossing が要る。要らないのは、路面軌道を道路に重ねるときだけ
- way-object は、1 タイルに waytype ごとに 1 つ（[way-addon.md](../reference/way-addon.md) の 10 章）
- AMI は、tram_track を橋脚（`ami_pier_*`）と `ami_tram` に、water を歩道（`ami_sidewalk`）に使っている。road の way-object は道路の壁（`ami_wall_road_*`）が使っている
- iss の補助の物は、ほかの waytype の way や way-object を重ねて作り、速度の値を目印にしている。路面表示は tram_track の way、電柱は road の way-object、盛土と「橋に見せる way」は track の高架の way。この作りでは、AMI の路面軌道・橋脚・道路の壁と同じタイルに置けない。車両がその上を走れるものもある
- pak128（`refs/pak128`）には、狭軌・リニアの車両が 1 つも無い（道具のメニューの枠はある）。モノレールの車両（懸垂式を含む）と船はある
- `type=cur` の建物（iss の盛土の building の版）は郊外の名所になり、乗客の行き先として数えられる（`descriptor/writer/building_writer.cc`・`simhalt.cc`）
- 新しく足す物は、どれも本家にもある仕組み（waytype・building・roadsign・crossing）で作れる。OTRP だけの機能は要らない

## 決定

2026-11-21 のユーザーの決定（#102 で、作業者の案のおすすめをすべて採った）。この ADR が ADR 0002 を置き換える。

### 0002 から引き継ぐこと

- アドオンの名前は AMI（`addons/ami/`）。物の名前の頭は `ami_`。iss・blender-poc の名前は引き継がない
- ライセンスは CC BY 4.0
- 対象は pak128 の本家 125.0.1 と OTRP。OTRP だけで使う絵（分岐の絵・近い斜め・分岐の追加画像）も入れ、本家では使われないだけにする
- 第 1 弾までの収録（線路 4 種・道路 3 種・路面軌道と、壁・基盤・高架・橋脚・橋・トンネル・歩道）と、その作り（0002 の決定と [ADR 0003](0003-ami-walls-base-piers-as-separate-objects.md)・[ADR 0006](0006-ami-track-variants-by-track-form.md)）はそのまま
- 線路の描画位置は、新描画位置で作り終えてから、旧描画位置（#26）をまとめて作る
- 速度以外の値（費用・維持費・登場年）は、実装の前に一覧で決める
- blender-poc の料金所は移さない

### 第 2 弾で足す物

軌道系:

- 車庫: 線路・道路・路面軌道と、第 2 弾で足す waytype の分（building の `depot`）
- モノレール: 跨座式と懸垂式（`monorail_track`）
- 運河（`water`）と船の車庫
- 操車場: 線路だけ（building の `stop`）。作る前に、ゲームで何に使えるかを確かめる
- 水路の踏切（crossing）。弾 1 の線路×道路の踏切で crossing の作りを決めてから作る

景観・補助:

- 中央分離帯: 道路の壁と同じ枠なので、壁と分離帯を 1 つの way-object にまとめる（架線つきの壁と同じ考え方）
- 歩道: 舗装の種類・高架の歩道・歩道の壁
- 電柱: 歩道の way-object にして、歩道のタイルに立てる（道路の壁と重ならないように）
- 路面表示: 道路の way の版に描き込む。入れるのは多車線の車線と交差点だけ
- 道路標識: 数を絞る（速度制限・一方通行・止まれ程度）
- 盛土: 橋脚と同じく、地面に敷く way（tram_track）にする。列車が乗らないようにするため
- 道路の分岐の絵（#46）: 範囲に入れるが、本体の変更が入るまで着手しない

### 入れない物

- 狭軌・リニア: pak128 に車両が無く、別のアドオンの車両が要る。必要になったら改めて決める
- 道路の上の歩道（iss は road の way）: 車が走れる
- 盛土の building の版（`cur`）と階段（roadsign）: `cur` は名所になって乗客の行き先になる
- 橋に見せる補助の way: iss は track の高架の way で、列車が走る。要るなら、高架の版をもう 1 組足す形で改めて決める
- 説明用の色つきの way: iss の説明のための物
- 路面表示のうち、ラウンドアバウト・黄線・色つき舗装

### 順番

軌道系と景観・補助は、触る部品が重ならない。2 列で並べて進める。

| 順 | 軌道系 | 景観・補助 |
|---|---|---|
| 1 | 車庫（線路・道路・路面軌道） | 中央分離帯・分離帯つきの壁 |
| 2 | モノレール（跨座）と車庫 | 歩道の種類・高架の歩道・歩道の壁 |
| 3 | 運河と船の車庫 | 電柱 |
| 4 | 操車場（線路） | 路面表示（道路の版） |
| 5 | モノレール（懸垂） | 道路標識 |
| 6 | 水路の踏切（弾 1 の踏切の後） | 盛土 |

車庫から始めるのは、building の生成を作り、操車場で使い回すため。中央分離帯から始めるのは、今の壁の部品を使い回せるため。

### 名前と pak

- 既存の物の名前は変えない
- 新しい way は `ami_monorail_straddle`・`ami_monorail_suspended`・`ami_canal`。版の付け方は今と同じ（`_base_<版>`・`_elev_<版>`・`_bridge`・`_tunnel`）
- 車庫は `ami_<種類>_depot`（`ami_rail_depot`・`ami_road_depot`・`ami_tram_depot`・`ami_monorail_depot`・`ami_canal_depot`）、操車場は `ami_rail_yard`
- 補助は `ami_wall_road_<版>_divider`・`ami_sidewalk_<舗装>`・`ami_sidewalk_elev`・`ami_sidewalk_pole`・`ami_road_<種類>_lane<n>`
- 景観は `ami_sign_<名前>`・`ami_embankment_<版>`
- 種類別の pak に `ami_monorail.pak`・`ami_canal.pak`・`ami_scenery.pak`（標識・盛土）を足す。車庫と操車場は、その waytype の pak に入れる。補助は今の pak（道路の版は `ami_road`、壁と歩道は `ami_extra`）に入れる。全部入りの `ami.pak` は今どおり作る
- 名前は、`addons/ami/build.py` が名前の頭で物を振り分ける pak に、そのまま入る形にした

## 検討した代替案と却下理由

- ADR 0002 を書き直す → [docs/README.md](../README.md) の決まり（ADR は書いたら変えない。覆すときは新しい ADR を書き、古い方を Superseded にする）に反する
- 狭軌・リニアも入れる → 狭軌は線路の部品を使い回せて作りやすい。ただ、pak128 だけでは走らせる車両が無い
- iss と同じ作り（ほかの waytype の way・way-object を重ね、速度を目印にする）で補助の物を作る → AMI の路面軌道・橋脚・道路の壁と同じタイルに置けない。車両がその上を走れるものもある
- 新しい物の名前を `ami_depot_<種類>` のように物の種類から始める → `build.py` の振り分け（`ami_rail_`・`ami_road_`・`ami_tram`）に当たらず、種類ごとの pak に入らない
- 景観の物を `ami_extra.pak` に入れる → `ami_extra` は線路・道路と組で使う物の pak。景観の物は無くても遊べるので、入れない人が外せるように分ける
- 軌道系を全部終えてから景観に移る（#61 の並び） → 2 つの列は触る部品が重ならないので、並べた方が早く終わる

## 影響・トレードオフ

- 建物（車庫・操車場）・roadsign（標識）・crossing（水路の踏切）は、AMI の dat の生成（`blender/ami_dat.py`）にまだ無い。物の種類ごとに生成とシートの並びを足す。building は blender-poc の料金所の描き方（4 方向を `render_cell` で描く）が前例になる
- 運河と歩道は、どちらも waytype が water になる。並べて敷いたときにつながるか、船が歩道に入るかは、まだ確かめていない。運河を作るときに確かめ、困るならこの ADR を見直す
- 路面表示を道路の版に描き込むので、表示の種類の数だけ道路の way が増える。表示を足すときは、道路の種類との掛け算で数を見積もる
- 盛土を tram_track の way にするので、橋脚と同じタイルには置けない。路面軌道を敷いた道路の上にも置けない
- 歩道の電柱は、歩道の壁と同じ water の way-object になる。2 つを同じタイルに置くなら、まとめた way-object が要る
- 狭軌・リニアの車両を入れるアドオンを使う人が増えたら、この ADR を書き直して入れるかを決める
- 第 2 弾の物も、本家 125.0.1 での読み込みは配る前にユーザーが確かめる
