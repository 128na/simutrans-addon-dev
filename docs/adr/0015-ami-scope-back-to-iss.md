# ADR: AMI の範囲を iss にある物に戻し、閉塞信号を外す（ADR 0014 の置き換え）

> ステータス: Accepted (2026-11-26)。[ADR 0014](0014-ami-scope-stations-and-signals.md) を置き換える（0014 は Superseded）。停留所を残す決定は [ADR 0016](0016-ami-remove-road-stops.md) が、狭軌とリニアを入れない決定は [ADR 0017](0017-ami-scope-narrow-gauge-and-linear.md) が置き換えた
> 由来: [#292](https://github.com/128na/simutrans-addon-dev/issues/292)・[#264](https://github.com/128na/simutrans-addon-dev/issues/264)（0014 の元の範囲の見直し）・[#277](https://github.com/128na/simutrans-addon-dev/issues/277)・[#278](https://github.com/128na/simutrans-addon-dev/issues/278)

## 背景と問題

[ADR 0014](0014-ami-scope-stations-and-signals.md)（2026-11-25）は、pak256 がインフラを AMI に任せる前提で、AMI の範囲に駅・停留所・線路の信号を入れ、空港・電線も範囲に入れた（作るのは後）。#277 で道路の停留所、#278 で閉塞信号を作った。

2026-11-26 に、ユーザーが AMI と pak256 の関係について方針を出した。

- AMI は 128 用というよりインフラと景観のアドオンで、パックセットのベースとしてそのまま使うのには向いていない。細かい装飾アドオンは基本的なゲームの範囲を超えている
- 256 のパックセットの開発が熟したら、256 にも対応した景観アドオンへ進化させることは検討する余地がある
- 前提として、iss に含まれていないホームは AMI に含めるのは想定していない。作りこむための比較対象や土台が無い（判断 51）
- 信号は今外し、停留所は後で（判断 52）

pak256 は閉塞信号を自前で作るので、#278 の `ami_rail_signal` は使わない（pak256 の進捗管理が確認済み）。

## 決定

- **AMI の範囲は、iss にある物に戻す。** 道路標識・車庫・操車場・軌道・橋・トンネルと、それに付く壁・高架・橋脚・基盤など。iss に比較対象も土台も無い物（駅・信号・空港・電線）は、AMI の範囲に入れない。ADR 0014 の「範囲に入れる物」の表は取り消す
- **閉塞信号（`ami_rail_signal`）を AMI から外す。** dat・画像・生成コード（`ami_dat.py`・`catalog.py`・`render.py`・`sheetlib/roadsign.py`）・訳（`ja_ami.tab`）・README・見本のスクリプトと確認の画像を消す。信号は作り直さない（前方注意・優先・長閉塞・選択信号の予定も取り消す）
- **道路の停留所（`ami_road_bus_stop`・`ami_road_truck_stop`。#277）は残す。** pak256 の間借り用の物として扱い、AMI ではこれ以上手を入れない。AMI の README にそう書く。pak256 が自前の停留所を用意したら外す。外すのは、pak256 の進捗管理から「自前を用意した」と知らせが来てからで、そのときは別の issue にする
- 線路の駅・路面軌道の停留所・港・空港・電線は、作らない（ADR 0014 が決めた第 5 弾の 2 番目以降も取り消す）
- ADR 0014 が引き継いだこと（名前の頭 `ami_`・種類別の pak・CC BY 4.0・狭軌とリニアを入れない・既存の名前を変えない・値は一覧で決める）は、そのまま有効。名前の頭の振り分けなどの決まりは [ADR 0008](0008-ami-scope-second-phase.md) にある
- 256 への対応は、今は進めない。256 にも対応した景観アドオンへ進めるかは、pak256 の開発が熟してから改めて決める

## 検討した代替案と却下理由

- 信号も停留所も残す（ADR 0014 のまま） → AMI は景観・インフラのアドオンで、iss に無い物を作りこむ土台が無い（判断 51）。pak256 が信号を自前で作るので、残しても使われない
- 停留所も今外す → pak256 が自前の停留所を用意するまでは、仮の物を置き換える先が無くなる。外す時期は pak256 の側の都合で決まるので、残して後で外す（判断 52）
- 信号を消さずに「非推奨」として残す → 使わない物が pak と訳とカタログに残り、保つ手間だけが続く。消す方が単純

## 影響・トレードオフ

- `ami_rail_signal` は pak（`ami_rail.pak`・`ami.pak`）から消える。この名前の信号を置いた保存データは、読み込むと信号が消える。使う者は pak256 の側にいない（pak256 の進捗管理が確認済み）
- 閉塞信号の作りで確かめた知見（本体の `obj/signal.cc` の画像の番号、電化の組、追加画像など）は、AMI の README から消える。本体の決まりとして `docs/reference/way-addon.md`・`script-api.md` には残す。経緯は #278 の PR と ADR 0014 にある
- 停留所は残るので、README・カタログ・描画の対象に残る。手は入れないので、本体や道路の変更で壊れたときだけ直す
- 外す日は決まっていない。pak256 からの知らせを待つ
