# ADR: 知見は docs/reference/ に置き、スキルは作業方法だけにする

> ステータス: Accepted (2026-11-14)

## 背景と問題

way アドオンの試作で分かった決まり（本体の描き方、dat のキー、手本の作り、判定の限界）を、
`.claude/skills/way-addon-reference` と `way-calibration` の 2 つのスキルに、作業の手順と混ぜて書いていた。

- スキルは Claude Code が作業のきっかけで読む仕組みで、Codex や人は読まない。知見がスキルの中にあると、ほかの作業者から見えない
- 手順と知見が同じファイルにあると、同じ決まりが 2 つのスキルに少しずつ違う書き方で載る（持ち分・はみ出しの決まりが両方にあった）
- docs の規約は「現在形の md」を allowlist にした文書だけに限っていて、知見を置く場所が無かった

## 決定

- 知見（確かめた事実と決まり）は `docs/reference/<主題>.md` に書く。生きた文書として `tools/docs-policy.json` の `livingDocs` に登録する
- スキルには作業方法（進め方・どのツールを回すか・どこを直すか・確かめ方・作業の注意）だけを書き、決まりはリファレンスへのリンクで引く
- リファレンスに書けるのは、このリポジトリのコードを読んでも分からないこと（本体・手本・道具の外部仕様を、ソース・画像・ゲームで確かめたもの）に限る。
  各項目に確かめた場所を書き、測った数値には日付を書く

`docs/README.md` の「外部フォーマット/外部 API の reverse-engineering 文書」の例外に当たる。

## 検討した代替案と却下理由

- スキルのまま置く → ほかの作業者に見えず、手順と知見の重複が増える
- `docs/records/` に書く → 書いたら変えられない。決まりは測り直すたびに更新するので合わない
- 各アドオンの README に書く → 複数のアドオンで使う決まりが、1 つのアドオンの経緯の中に埋もれる（blender-poc の README は経緯の記録で 700 行を超えた）

## 影響・トレードオフ

- リファレンスは「常に現在を反映する義務」を負う。決まりを確かめ直したら、スキルではなくリファレンスを直す
- リファレンスを足すたびに `livingDocs` への登録が要る（主題ごとに 1 ファイルにして、数を増やさない）
- 手順の中でしか意味を持たない注意（ゲームの終了のしかたなど）はスキルに残すので、境目の判断は残る。迷ったら「作業をしない人にも役立つか」で決める
